# 主界面原型维护规则

适用范围：本目录。目标是维护能跟随当前工作流插件、可独立试用需求的网页原型。

1. 修改前读取 DESIGN.md 与 HANDOFF.md，核对正式来源基线和已有试验差异。Current 以 src/client.js、src/host.js、templates 和真实运行结果为准，旧原型用于设计参考。
2. client.prototype.js 是正式客户端的隔离副本。默认保持真实组件、布局、字号、控件、图算法和主要交互，不以近似页面重画。每一项主动差异写入 DESIGN.md，注明理由、范围和正式源码位置。
3. 用户的功能修改先在原型中完成并试用；不要因原型任务直接编辑 src/、模板、正式 DSH 或运行数据。正式实施须有覆盖方案和范围的用户授权。
4. mock-host.js 只维护内存接口；seed.data.mjs 负责示例。保持与当前宿主返回格式一致，未知接口失败，不转发到真实服务。静态校验只读调用正式内核；真实模型探针与运行不得模拟成已执行。
5. app.css 只负责宿主外壳，shell.css 只负责原型工具条。避免重新复制一套 .vwf-* 样式；样式实验写入客户端副本并登记差异。
6. 首先解决当前界面的对齐和需求，不为例行同步强加新的布局方向。保留“当前原型 / 正式源码对照 / 旧版原型”三个比较入口；ui-workbench 原文件保持历史参照身份。
7. 通过浏览器操作受影响路径，对照相同数据与视口下的正式源码渲染；覆盖相应浅 / 深主题、独立滚动和 390px 布局。记录实际操作、截图、未覆盖项。摘要一致、静态检查、界面体验和正式环境验收分别报告。
8. 正式来源变化时先合并并复核，不通过重置 sync-baseline.json 掩盖偏差。同步命令应保护原型试验，不能直接覆盖。
9. 全部改动留在当前隔离原型工作树。提交、推送、PR 或正式合并按用户授权处理，技能中的留证流程不能扩大授权。
