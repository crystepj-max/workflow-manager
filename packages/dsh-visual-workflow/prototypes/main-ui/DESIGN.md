# 主界面原型对比与修订记录

## 当前问题与结论

问题：如何让独立网页原型保留旧版完整体验，并和当前工作流插件的真实页面结构、样式及交互一致，从而先验证需求再改正式代码？

用户于 2026-10-21 退回首版：“跟之前做的那版，退步了不少，跟实际页面样式也不是一致的。你再检查对比一下，把细节对齐。”

检查确认首版简化重绘造成退步：仅读取了真实蓝图，组件、CSS、图布局和大部分状态均重新写成了近似实现。之前“源码快照已对齐”的表述只由文件摘要支持，不能支持视觉一致，本轮更正。

本轮默认维护一个当前主界面基线；顶部三个入口分别用于原型、正式源码和旧稿对照。它们不是新的 A/B/C 产品方向。

## 唯一主动差异 D1：显式深色选中态

正式客户端仅在 prefers-color-scheme: dark 下为工作区选中底色提供深色回退。当前宿主不定义 brand-fill-soft alias；系统浅色而应用显式深色时，选中步骤实际为文字 rgb(249,250,251)、背景 rgb(232,236,255)，难以辨认。

原型只在客户端副本中为显式浅 / 深应用主题分别提供 #E8ECFF / #293759 的选中底色回退，避免应用与系统主题不同步时串色。它也覆盖同一语义变量用于运行目录的选中态。正式源码与对照入口保留原样。该差异属于本轮原型修正，尚未进入正式代码。可用 theme=dark&system=light 或 theme=light&system=dark 在原型 iframe 中复现两种不一致，不修改系统设置。

## 本轮浏览器证据

环境：Chrome，独立 frame 对照量测为 1920 × 783；带工具条的桌面页面为 1920 × 783，工具条占 48px，因此其预览 iframe 为 1920 × 735。另使用真实 390 × 844 的 iframe 测试窄屏。

- 同视口、同蓝图对照正式源码：设置面板宽 800px，编辑器宽 1440px / 高 719px，正文 13px，编辑器圆角 18px；画布和配置区的尺寸、字体、颜色、圆角量测一致。D1 仅改变显式深色主题选中底色。原始量测见 evidence/component-metrics.json。
- 打开诊断模板：5 个步骤、全部 18 条连接；内置结构只读，配置三档与缩放入口可用。
- 审核节点切换示例供应商 / 模型后保存，再打开仍显示覆盖值，原节点默认值单独保留。
- 个人流程修改步骤名、撤销、重做；关闭出现三选一；“保存并返回”后重新打开，名称与草稿一致。
- 运行 204：结果区可以切到第 1 次“退回修改”与第 2 次“已通过”，两次成果不混用；完整经过列出各次执行。
- 长角色正文：输入区可视高度 228px，内容 858px；滚动后 scrollTop 从 0 到 460，文档没有横向溢出。
- 进行中的并行组保留 3 个独立子项，其中 2 个完成、1 个执行中；暂停及指导写入演示内存，指导按 seq 编号，不产生业务结果。
- 深色、窄屏流程 / 配置区均进行实际浏览器目视复核；截图保存在 evidence/。
- D1 对照量测：应用浅色 / 系统深色时，选中态对比度由 1.61:1 提高到 16.08:1；应用深色 / 系统浅色时，由 1.12:1 提高到 11.26:1。颜色来自浏览器计算样式，计算记录见 evidence/theme-contrast.json；这只覆盖选中态，不是全页面无障碍认证。
- 空模板搜索显示“没有匹配的模板”；旧稿已通过同一服务入口打开。交付时当前内嵌浏览器也已刷新并打开修订版。
- 演示中的 9 套流程通过当前只读内核的结构 / 模型校验；全部脚本通过语法检查。
- 当前页面错误日志为空；没有运行正式产品测试或真实工作流。

## 能力与证据限制

- 本机 3080 的 DSH 服务要求认证，本轮没有更改服务、重启实例或绕过认证。这里“正式源码对照”指相同模拟数据下直接渲染当前 src/client.js，不能冒充已安装实例的截图验收。

- 所有任务、模型、保存、角色修改与控制都在内存；只读内核检查不等于完整宿主门禁或模型、执行引擎验证。

- 运行场景是演示夹具，不作为真实项目进展或业务运行证据。
