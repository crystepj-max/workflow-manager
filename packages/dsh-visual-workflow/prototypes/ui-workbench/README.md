# 工作流 UI 一次性原型

**当前为第二轮：模板工作区与运行详情统一采用编排台，补齐真实分支、多任务和返工记录。待用户体验反馈。**

## 启动

仓库根目录执行，无需新增依赖：

```bash
npm run prototype:ui
```

[打开小尺寸设置入口](http://127.0.0.1:4178/settings/workflow-visual?variant=A&theme=light&view=library&surface=settings)。端口占用时自动递增，以终端输出为准；仅监听 `127.0.0.1`，production 模式拒绝启动。

## 本轮体验顺序

1. 流程库 → 内置模板「模型设置」：逐节点调整供应商与模型，查看「默认 / 覆盖」，逐个或全部还原各节点预设。内置与个人模板的右侧节点配置均有「设置本节点」入口；个人模板修改后保存模板。顶部左右箭头分别为撤销和重做。
2. 流程库 →「我的 5」：体验五套个人模板列表；「新建模板」可从零搭建或复制已有模板。
3. 查看「诊断与修复」→ 检查成果 → 结果与去向：四种结果指向不同后续步骤。画布可独立滚动、缩放，右侧配置不会带走画布。
4. 查看「多视角探索」：展开并行研究组、多个独立视角与汇总；评估结果可返回安排研究。连接清单保留所有业务连接与调用重试。
5. 运行 → 筛选空间 / 待处理 → 工作流界面改版 → 完整经过：点第一次审查查看退回原因，再切到第二次成果。
6. 角色 → 自定义 → 体验检查员：编辑长职责或去掉简介，观察两行摘要；完整职责在详情中独立滚动。
7. 底部切换深浅主题、查看本轮说明和当前状态；窄屏可切换流程与结果 / 配置。

第二轮逐项回应、当前实现核对与验证范围见 [REVIEW-2.md](REVIEW-2.md)。

## 文件与边界

- `prototype-v2.js` / `prototype-v2.css`：当前交互原型。`prototype.js`：保留的初版三个方向。
- 添加 `version=1` 可回看初版，例如 [初版 A](http://127.0.0.1:4178/settings/workflow-visual?version=1&variant=A&theme=light&view=editor&surface=workspace)。初版已知简化仅作历史对照。
- [DESIGN.md](DESIGN.md) 保留初版视觉系统和研究依据；本轮用户偏好与范围以 REVIEW-2 为准。
- `evidence/v2-*` 为本轮截图，其余文件为初版证据。语法、差异格式与真实浏览器重点交互已检查；无正式产品验收结论。
- 模板定义与连接只读加载当前源码。运行、个人模板、角色和模型选项为示例；编辑仅存内存，刷新恢复。没有连接正式 DSH 或执行真实工作流。
- 正式源码、模板均未修改；无提交、推送或发布。原型不能直接当成生产实现。
