# 工作流 UI：一次性设计探索

> 第二轮更新：用户倾向模板编辑和运行详情都采用 A 编排台。当前原型已按此收敛；本轮逐项回应见 [REVIEW-2.md](REVIEW-2.md)。以下保留初版方向探索与配色依据，原先 A + C 的建议已被本轮反馈取代。

## 要回答的问题

产品经理能否通过「要做什么 → 由谁完成 → 结果如何 → 下一步怎么办」理解和使用工作流，并在配置长表单、查看运行成果时保持位置感？

三种结构在同一原型地址 `/settings/workflow-visual?variant=A|B|C` 切换。现有客户端通过 DSH 的 `settings.section / workflow-visual` 注入，没有独立网页路由。本原型在插件旁建立隔离预览入口，保留宿主导航的空间约束、四套真实模板及建设流程顺序；运行固定采用完整功能开发的演示数据，与编辑草稿独立；成果和操作均为示例。它不是已实现能力的说明。

## 宿主空间：小设置入口 → 大工作区

根据用户提供的两张实际 DSH 截图，初始设置弹窗约 800px 宽，左侧设置目录占约 174px。插件可用的内容宽度只有约 590px；这里应负责找流程、看进度摘要和管理角色，不承载完整画布。

点击「编辑」或「查看并验收」后，打开最大 1440px 宽的独立工作区。下层设置暂不可操作；关闭工作区回到原来的页签和列表位置。修改未保存时提供继续编辑、放弃修改、保存并返回。窄屏时工作区铺满可用区域。

两层表面均采用不透明语义底色。背景壁纸只出现在弹窗外，并压暗、模糊；可读性不再依赖宿主皮肤。原型底部方向切换条属于评审工具，不是正式产品界面。

```
DSH 主界面
  └─ 设置弹窗（约 800px）
       ├─ 流程库：搜索、选择、创建
       ├─ 运行：进展摘要、待办
       └─ 编辑 / 查看详情 → 大工作区（最大 1440px）
                             └─ 返回：保留位置，处理未保存修改
```

## 设计前的取舍

最初的「三个方向都用画布加侧栏」会只剩换肤，因此改成三种不同的使用方式：

| 方向 | 页面首先回答什么 | 结构与主要操作 | 代价 |
| --- | --- | --- | --- |
| A · 编排台 | 整个流程怎样连接？ | 步骤目录 / 路线画布 / 独立滚动的配置栏，点步骤编辑 | 复杂分支时需要较宽屏幕 |
| B · 步骤手册 | 我现在应该设置什么？ | 纵向章节目录 / 宽表单 / 后续走向摘要，按步骤前进 | 总览分支弱于 A |
| C · 任务现场 | 现在最需要关注什么？ | 顶部阶段带 / 待办侧栏 / 单一工作区，围绕结果处理 | 高级流程编辑需要展开关系视图 |

```
A  [目录] [          路线画布          ] [配置 ↕]
B  [章节与进度] [       当前步骤表单 ↕        ] [接下来]
C  [                  阶段带                     ]
   [待办与记录] [           结果 / 工作区 ↕          ]
```

推荐以 A 验证复杂编排、以 C 验证日常运行；是否组合由本轮体验决定，尚未确认。

## 视觉系统

每个方向的 6 个基础色为：画布、表面、正文、次要正文、强调色、强调底色。状态色另成语义体系，不能随方向改变含义。

| 方向 | 浅色基础色 | 深色基础色 | 字体与个性 |
| --- | --- | --- | --- |
| A · 雾蓝编排台 | `#F1F4FA` `#FFFFFF` `#1D2B43` `#58677E` `#3D53B6` `#E8ECFF` | `#101827` `#182338` `#EDF2FF` `#ACB9D1` `#B3C1FF` `#293759` | Avenir Next 标题，PingFang SC 中文；SFMono 数据。线路式流程图是唯一强调的视觉元素。 |
| B · 青瓷步骤手册 | `#EDF4F1` `#FCFEFD` `#193A34` `#526D64` `#216558` `#DEEEE7` | `#112420` `#19332C` `#E8F6EF` `#AAC8BB` `#A0DAC3` `#294A3E` | 中文标题用 Songti SC，正文 PingFang SC；像翻阅任务手册，序号确实代表执行次序。 |
| C · 紫灰任务现场 | `#F2F0F6` `#FFFFFF` `#312D44` `#665E79` `#754698` `#EFE4F7` | `#1D1826` `#292233` `#F3EBFC` `#C1B3D0` `#D6B0F1` `#463252` | Avenir Next 紧凑标题，PingFang SC 正文；宽阶段带提供稳定方位。 |

字体使用系统本地栈，无远端字体依赖。圆角以 8 / 12 / 16 为主；间距以 4 / 8 / 12 / 16 / 24 / 32 为主；正文 14px，说明 12px，标题 22–32px。动画仅用于选择反馈，尊重减少动态效果设置。

## 交互建议与依据

1. **按用户的任务命名**：节点 → 步骤；Profile → 负责角色；Provider → AI 服务；schema → 交付内容；outcome routing → 完成后怎么走。底层表达式留在「更多设置」的技术详情，不改变真实业务含义。
2. **保持工作上下文**：固定工作区高度，画布、目录、表单各自滚动；主要操作留在顶部。小屏保留步骤位置条，并切换流程 / 配置，避免把巨大桌面画布压成小字。
3. **统一详情出口**：运行视图中，目录只负责定位，正文只展示一个选中步骤的结果；成果、检查、活动用同一区域内的页签切换。
4. **复杂度逐步呈现**：先任务与角色，再输入和交付要求；流转规则独立页签；模型与技术信息放更多设置。参考 [NN/G：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)。
5. **状态与控制可见**：草稿未保存、模拟暂停、待用户决定都给明确文字；出错说明影响、原因和下一步；支持撤销、取消与恢复。参考 [NN/G：10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)。
6. **主题采用成对语义色**：普通文字对比度目标至少 4.5:1；图标、选中态与控件边界至少 3:1；状态同时给图标和文字。小窗口的辅助正文至少 12px，避免靠缩小文字塞进更多信息。依据 [WCAG 2.2 文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。
7. **键盘与窄屏同等考虑**：有可见焦点、真实表单标签、Escape 关闭、对话框焦点管理；底部方向切换条预留空间。依据 [WCAG 2.2 焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)。

## 现有实现的调查范围

- `src/client.js` 的 152–190 行：外层 `.vwf-editor-body` 可滚动，画布有最小高度，窄屏转为单列；这会增加整体内容离开视口的风险。是源码推断，未在产品 DSH 中复现。
- `src/client.js` 的节点配置包含 ID、模型、输出约束、判定、表达式等内容；根 `CONTEXT.md` 明确记录前端校验文案翻译为优化任务。
- 运行区域同时包含图、节点表和结果展示；本原型把相关信息收拢到唯一详情区。
- 用户反馈是体验问题的直接输入；本轮不把静态调查称为完整产品可用性审计。

## 体验后再决定

待验证：最喜欢的方向；普通任务是否能独立完成；高级规则是否仍能找到；实际 DSH 嵌入密度是否合适。尚无方向被用户选定，不修改正式源码、不提交或发布，不将模拟验收写为真实验收。确认方向之后，正式实现需要重新设计组件、真实数据连接与相应验证。
