![Runtime](https://img.shields.io/badge/Runtime-DeepSeek%20Harness%20v0.1.5--rc.1-blue)
![Version](https://img.shields.io/badge/Plugin-v0.2.0-2EA9A0)
![Repo](https://img.shields.io/badge/Repo-Public-brightgreen)
![Status](https://img.shields.io/badge/Status-Active-orange)

**在你自己的电脑上，跑一条看得见、管得住、留得下证据的 AI 工作流水线。**

Workflow Manager 是一套运行在 **DeepSeek Harness（DSH）** 上的 AI 协作工作流系统。它把"让 AI 干活"从一句口头指令，变成一条完整的流水线：谁做、按什么标准做、做到哪一步了、要不要你拍板、做完留下了什么，全都摆在明面上。

你不写代码也能用。装上插件，打开界面，选一条流程，点开始。

## 1 · 它解决什么问题

让 AI 干活，最大的麻烦从来不是"它不够聪明"，而是**不可控**：它一口气干完十步，中间跑偏了你才发现；关键取舍它替你拍了板；干完什么也没留下；同时开几个任务互相打架。

Workflow Manager 针对的就是这些：

| 你可能遇到的问题 | 它的做法 |
|---|---|
| AI 一口气干完，中途跑偏才发现 | 流程拆成明确的阶段，随时能看到走到哪一步 |
| 关键决策 AI 替你拍板 | 该你决定时它停下来问你，**AI 不代签** |
| 干完什么都没留下，没法复核 | 每一步都产出结构化成果和验证证据，可回溯 |
| 同时开几个任务，互相覆盖打架 | 每个任务独立工作区，天然隔离，互不干扰 |
| 出了问题不知道错在哪一步 | 运行看板实时呈现状态、步骤和日志 |
| 想让 AI 按你们团队的规矩干活 | 流程和角色都能自定义，改一次全局生效 |

一个典型场景：你写下一句话需求，AI 自动完成**需求分析 → 方案设计 → 开发 → 独立审核 → 独立测试**，每一步都留下报告；走到验收环节停下来，把两份报告（一份通俗、一份严格）摆给你看，你点"通过"它就收口，你说"改"它就带着你的意见回到前面重做。

## 2 · 核心特性

| 特性 | 说明 |
|---|---|
| **可视化流程编辑** | 拖拽连线画布 + 右侧配置面板，流程长什么样一眼看清；图形和 JSON 双向实时同步 |
| **开箱即用的流程模板** | 内置多套标准流程，也可以自己新建、修改、删除 |
| **每一步都可视化** | 运行中的流程用颜色标出哪些步骤已完成、正在进行、出了问题 |
| **运行看板** | 实时看到状态、阶段、每个子任务在做什么、最近日志 |
| **人工把关** | 关键节点自动挂起等你拍板，支持断点续跑 —— 关掉应用第二天回来还能接着走 |
| **多任务并行** | 同时跑多个任务互不干扰；同一个任务重复启动会被拒绝，避免写坏成果 |
| **独立工作区** | 每个任务在自己独立的空间里作业，不会覆盖你手上的改动 |
| **质量互检** | 开发与审核强制由不同模型担当，避免"自己审自己" |
| **自定义角色** | 内置一批标准角色，也能建自己的角色，规定每个环节该怎么干 |
| **明确终止保证** | 任何流程要么正常走完，要么以一个明确的原因停下，不会卡死在那里 |

## 3 · 快速开始

装好之后（见下一节），三步跑起来：

1. **选一条流程** —— 打开 DSH 设置 →「工作流」→ 模板库，选一条内置流程，比如「建设 · 完整功能开发」。
2. **起跑** —— 在会话里直接说这条流程的名字，例如「用『建设 · 完整功能开发』跑 issue #12」；会话按该流程的技能手册调用插件起跑，**不需要你复制脚本**。
3. **跟踪** —— 运行回执里会给你一个运行编号（runId），用它就能在看板里跟踪状态。

跑到需要你拍板的环节，它会停下来把材料摆给你。你决定之后，流程继续或者退回重做。

## 4 · 安装

### 环境要求

| 依赖 | 要求 |
|---|---|
| **DeepSeek Harness** | v0.1.5-rc.1（当前最新发布版） |
| **Node.js** | v22 及以上（实测 v22.22.2） |
| **npm / pnpm** | 任意可用版本 |
| **GitHub CLI（gh）** | 可选。用于自动创建和合并合并请求；没有也不影响使用 |

### 安装可视化工作流插件

```bash
# ① 获取源码
git clone https://cnb.cool/chris.ai/workflow-manager.git
cd workflow-manager

# ② 构建插件
cd packages/dsh-visual-workflow
npm install
npm run build

# ③ 安装到 DSH（路径请换成你机器上的绝对路径）
dsh plugin --profile web add link:/你的绝对路径/workflow-manager/packages/dsh-visual-workflow

# ④ 完全退出并重启 DSH，然后打开 设置 →「工作流」
```

> 第 ② 步不能跳过。源码里不含构建产物，不构建直接安装会加载不到界面。

### 安装配套技能（可选）

技能是"用一句话触发整套流程"的入口。装进公共技能目录后，**任何项目的 DSH 会话都能直接调用，不用往项目里拷任何文件**。

```bash
cd workflow-manager
./dsh/install-requirements-analysis.sh      # 需求分析
./dsh/install-construction-bootstrap.sh     # 建设 · 完整功能开发
./dsh/install-execution-plan.sh             # 执行计划（批量调度）
```

装好后，在任意项目的会话里直接说「用开发工作流跑这个需求」即可触发。

四条内置流程的技能包（可在会话里按名字直接调用流程）用仓库命令安装：

```bash
npm run install:builtin-skills        # 装进 DSH 技能目录
npm run install:builtin-skills:pool   # 同时装进跨 AI 助手共享的公共技能池
```

> 新装的技能需要**重启会话**才能被识别 —— DSH 在会话启动时读取技能列表。

### 更新与卸载

```bash
# 更新：拉取最新代码 → 重新构建 → 重新安装
git pull
cd packages/dsh-visual-workflow && npm install && npm run build
dsh plugin --profile web add link:/你的绝对路径/packages/dsh-visual-workflow

# 确认已安装
dsh --profile web --dump-config | grep visual-workflow

# 卸载
dsh plugin --profile web remove dsh-visual-workflow
```

## 5 · 使用指南

所有功能都在 **DSH 设置 →「工作流」** 这个页面里，分两个页签。

### 模板库

流程清单，一行一条。可以：

- **新建** —— 从零画一条自己的流程；
- **编辑** —— 打开可视化编辑器修改；
- **删除** —— 删除自己建的流程（内置流程只读，删不掉）。

内置流程带 `builtin` 标记，只读；你自己建的可随意改。

### 可视化编辑器

点「编辑」滑出的大面板就是编辑器，左边是画布，右边是配置面板。

**画布**能做什么：

- 从节点右边的把手**拖拽连线**，连到目标节点即成为一条路径；
- **右键画布**可以添加结束节点；
- **滚轮缩放**，缩放以鼠标位置为锚点；
- 空白处可拖动，节点自动分层排布，回退路径走上方外围车道、自动避让；
- 选中的节点或连线会高亮。

**配置面板**里可以设置：

- 每个**节点**：名称、由哪个角色来做、用哪个模型、目标是什么、结果怎么判定、输出格式要求；
- 每条**连线**：是成功路径还是失败路径、什么条件下走这条线。

**保存时**会先做一次完整检查。有问题会在弹窗里逐条列出，关掉后自动定位到第一个问题字段并标红。检查通过才会写盘，同时自动生成可调用的技能 —— **保存即完成**。

### 运行与看板

**运行工作流**的正式方式：在会话里发起这条流程（走插件的起跑通道），运行记录完整——同一个任务跨多次执行仍显示为一个运行，看板里能续跑、暂停、给指导。只有会话拿不到工作流引擎时，才回退到「把脚本交给 DSH 内置执行器」；回退时看板记录会退化（只显示一段、没有完成类型），会话会明确告诉你。

**运行看板**每 3 秒自动刷新，能看到：

- 运行列表（可点选切换）；
- 当前任务所处的状态和阶段；
- 一张只读画布，节点按状态染色；
- 子任务表格：哪个子任务、走到哪一步、结果如何；
- 最近 20 条日志。

### 需要你拍板的时候

流程跑到需要人工确认的环节，会**挂起**并返回一个等待状态，同时把需要你判断的材料准备好。比如验收环节会给出两份报告：一份通俗版给你看结论，一份严格版列证据。

你给出决定后，流程从挂起点继续。**通过**就往下走；**不通过**就带上你的意见退回重做。

这个过程支持断点续跑 —— 中间关掉应用、第二天回来，仍然可以接着往下走。

### 同时跑多个任务

可以。每个任务有独立工作区，数据天然分开，看板里互不串扰。

两条保护规则：

- **同一个任务重复启动会被拒绝**，避免两个流程同时改同一份成果；
- 同时有多个任务在跑时，看板会提示你**先收口再开新任务**（是提示，不强制）。

需要你拍板的卡片会**排队**：一次只处理一张，第一张显示"裁决中"，其余的显示"排队 #n"。

## 6 · 内置工作流

开箱即用的四类标准流程：

| 流程 | 路径 | 适用场景 |
|---|---|---|
| **建设 · 完整功能开发** | 需求分析 → 方案设计 → 开发 → 独立审核 → 独立测试 → 人工验收 → 收口 | 从零做一个完整功能 |
| **优化 · 快速迭代** | 目标确认 → 执行 → 评估 → 收口 | 在已有基础上快速改进 |
| **诊断 · 缺陷修复** | 缺陷诊断 → 修复 → 审核 → 回归验证 → 收口 | 定位并修复一个问题 |
| **探索 · 多视角探索** | 探索统筹 → 专家研究（并行）→ 综合分析 → 结论评估 | 一个开放问题需要多角度研究 |

其中「探索」流程最多进行 **3 轮研究**（含首次广泛扫描），必要时自动补充最多 2 轮定向研究。

这四条流程都以可视化模板的形式提供，你可以直接改，也可以照着它们的样子建自己的。

### 这些流程的技能，在不同环境里能用到什么程度

每条内置流程都会生成一份**自包含技能包**（流程剧本 + 各环节角色提示词 + 运行脚本）。装进 DSH 技能目录用 `npm run install:builtin-skills`；要同时分发给其他 AI 助手共用，装进公共技能池用 `npm run install:builtin-skills:pool`（幂等，可重复执行）。

同一个技能包，在不同环境里的能力不一样：

| 能力 | DSH + 工作流插件 | 其他 AI 助手 |
|---|---|---|
| 发现并加载流程手册 | ✅ | ✅ |
| 无人值守自动推进（自动流转、回退额度记账） | ✅ | ❌ |
| 运行看板 / 暂停续跑 / 逻辑运行记录 | ✅ | ❌ |
| 人工门禁挂起与按决策恢复 | ✅ | ❌ |
| 证据链与版本锚定 | ✅ | ❌ |
| 按流程手册 + 角色提示词，自己当总指挥执导各环节 | ✅ | ✅（用自己的子代理扮演各环节） |

按流程看，其他助手的可用程度从高到低：**探索 ≈ 8–9 成**（纯研究，不碰代码仓库，最值得用）→ **优化 ≈ 6 成** → **诊断 ≈ 5 成** → **完整功能开发 ≈ 3–4 成**（依赖本仓库的施工脚本，离开本仓库退化更多）。

一句话：**在其他助手里，它是"能读懂、能照着执导"的流程手册；要无人值守跑全流程、留证据，请在 DSH 里用。**

## 7 · 内置角色

角色规定"这一步该由谁、按什么标准来做"。系统内置 12 个：

**通用角色**

`requirements` 需求分析 · `designer` 方案设计 · `dev` 开发 · `review` 审核 · `test` 测试 · `evaluator` 评估 · `accept` 验收助手 · `closeout` 收口

**专业角色**

`diagnose` 缺陷诊断 · `orchestrator` 探索统筹 · `researcher` 专家研究 · `synthesizer` 综合分析

内置角色始终可选、只读；你也可以**创建自己的角色**，把它用在流程的任意节点上。

## 8 · 即将推出

以下能力正在开发中，会让这套系统更好用：

- **更聪明的人工决策** —— 需要你拍板时不再只给"是 / 否"，而是列出可选方案、各自的成本与风险，并给出推荐意见；你的每次决定都会留下不可覆盖的正式记录。
- **可控的成本边界** —— 为自动重做设置额度，用完时停下来请你决定是否追加，而不是无限循环下去。
- **随时暂停与继续** —— 运行中可暂停、补充指导意见、再恢复，不必从头再来。
- **完整的运行档案** —— 每次运行都有完整的版本与来源记录，成果、证据、决策全部可追溯。
- **更规范的结果定义** —— 每个环节的产出按统一的业务结果来定义和流转，让"为什么走到这一步"始终有据可查。
- **统一的触发入口** —— 从界面、从对话、从技能，三种方式触发的是同一套运行机制，行为完全一致。

## 9 · 常见问题

**装完在设置里找不到「工作流」？**
先跑 `dsh --profile web --dump-config | grep visual-workflow` 确认插件已注册，再确认是**完全退出并重启**应用（不是刷新页面）。

**改了流程，界面上没变化？**
如果改的是插件源码，需要重新构建（`npm run build`）再重启；只改流程内容的话，保存后即时生效。

**执行过程中报错怎么办？**
以会话发起（插件起跑通道）为正式路径；只有会话拿不到工作流引擎时才回退到脚本方式，回退时会明确提示看板记录将退化。

**技能装好了但在会话里调不到？**
技能列表是会话启动时读取的，**重启会话**后再试。

**多个任务同时跑会互相干扰吗？**
不会。每个任务独立工作区、独立数据。但有两条保护：同一任务不能重复启动；多任务并行时看板会提示你先收口。

**AI 会自己替我签字吗？**
不会。验收这类关键决策必须由你做出，系统只负责把材料准备清楚。
