# Definition Check（定义完成检查）

> 进入「待确认」前必须逐项勾选；全部通过后才可请求人工确认基线。  
> 人工确认后才可落档为「已定义」。  
> 任一未勾选或未决产品事项 > 0 → **禁止**标为「已定义」。

复制到分析会话或落盘 `.scratch/<feature-slug>/definition-check.md` 使用。

---

## 检查元数据

| 项 | 值 |
|---|---|
| 任务名称 | |
| 拟确认基线版本 | V1 |
| 检查人（Agent） | |
| 检查时间 | |
| 未决产品事项数 | 必须为 0 |

---

## 9.1 目标与范围

- [ ] 用户问题明确
- [ ] 需求目标明确
- [ ] 非目标明确
- [ ] 修改范围明确
- [ ] 不修改范围明确
- [ ] 修改前状态明确
- [ ] 修改后状态明确

## 9.2 规则与边界

- [ ] 主要业务规则明确
- [ ] 主要用户路径明确
- [ ] 关键边界场景明确
- [ ] 关键异常场景明确
- [ ] 对已有功能的影响明确
- [ ] 已知风险明确

## 9.3 决策完整性

- [ ] 所有会影响产品结果的人工决策均已完成
- [ ] 不存在「施工时再决定」的产品问题
- [ ] 未决产品事项数量为 0

## 9.4 任务组织

- [ ] 如需求复杂，已完成必要的功能切片拆分
- [ ] 每个子任务均可独立 UAT
- [ ] 前置依赖已明确填写「无」或具体任务
- [ ] 优先级已确定

## 9.5 验收

- [ ] 每个主要功能有明确验收条件
- [ ] 已能形成主要 UAT 场景
- [ ] 验收标准可以通过真实操作判断

## 9.6 无人值守

- [ ] 已明确「无人值守许可」
- [ ] 若允许无人值守，不存在必须在施工过程中由人选择的产品问题

---

## 结论

- [ ] **全部通过** → 状态可改为「待确认」，呈递人工确认基线
- [ ] **未通过** → 保持「定义中」，列出缺口并继续决策/补全
