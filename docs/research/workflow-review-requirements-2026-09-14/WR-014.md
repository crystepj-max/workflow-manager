## 2. 需求目标与验收标准

**目标：**收口准确报告已交付事实，只有任务明确需要且已有授权的交付动作才执行，清理失败不伪装成功。

**业务规则与边界：**

- 收口输入明确列出 required_actions、授权引用、目标适配器和成果版本。非 Git 本地文档交付默认动作集为空，只整理产物和结论；不得默认创建 PR 或删除环境。
- 需要源码/正式文档修改时回到最终证明之前，不在 closeout 偷改成果。生成收口报告等管理元数据应写到证据区并与候选内容区分。
- Git 动作按仓库已配置的目标和项目政策选择适配器，禁止硬编码 origin 或通用角色直接拼 gh。对未支持的平台返回明确能力缺失，不伪装完成；本条 V1 交付本地与现有 GitHub 路径，不新增 CNB 平台功能。
- 必需动作未确认成功则不报 DELIVERED；非必需环境回收失败记录 cleanup_pending、保留路径及原因，不影响已经成立的成果事实。禁止强删含未保全改动的工作区/分支。

**可检查的验收条件：**

- [ ] AC-01：非 Git 优化正常收口，无 Git/PR 调用；已授权 GitHub 交付通过动作接口执行且回读确认。
- [ ] AC-02：缺必要授权时先完成可交付材料并准确等待该动作授权；既有有效授权不重复询问。
- [ ] AC-03：必须合并却合并失败时不得 DELIVERED；可选清理失败保留成果状态并列出待清理资源。
- [ ] AC-04：收口前后候选内容一致；含未保全改动的工作区不被强删；同组环境遵守全部成员完成后回收。

**代表验收路径：**用本地文档和假 GitHub 适配器各收口一次，再分别注入合并失败、可选清理失败和工作区有未保全改动，检查三者的完成与清理状态。
