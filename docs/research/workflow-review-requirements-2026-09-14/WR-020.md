## 2. 需求目标与验收标准

**目标：**每个 Run 可解释时间与调用花在哪里，并把这些成本与验收质量放在同一份本地报告。

**业务规则与边界：**

- 以 Run 为 trace、节点逻辑步骤与 attempt 为关联单元，记录开始/结束、模型、输入版本、重试类别、业务轮次、结果状态及人工作用。等待人工与自动运行耗时分别统计。
- 用量按供应方回传记录；没有 token 或价格数据时标 unavailable，不能估为零。已知价格须记录来源时间/版本与币种；不记录凭据、完整提示或敏感成果正文。
- 质量字段来自明确证据：自动验收通过率、已确认返工原因、人工退回/接受、未解决项；不得由模型自评分单独代表交付质量。提供 JSON 与人读摘要，先不要求在线监控服务。
- 汇总必须能追溯 attempt；日志缺失显示覆盖不足，不把不完整统计用于精确排名。

**可检查的验收条件：**

- [ ] AC-01：8 次调用的优化样例展示 8 次 attempts 的时间/状态，并分别显示业务返工、技术重试与人工等待。
- [ ] AC-02：用量缺失、价格缺失、取消及崩溃恢复均有明确状态；汇总与底层明细一致，不重复累计重放事件。
- [ ] AC-03：人工验收来源、成果版本和质量指标可追溯；凭据与提示全文不进入默认指标文件。
- [ ] AC-04：本地报告可比较四模板的调用、自动耗时、等待与结果质量，并提示样本量/证据不足。

**代表验收路径：**运行一次含技术重试、两轮优化和人工等待的样例，导出报告；对照底层事件手算调用与耗时，再隐藏用量数据确认报表显示不可用。

## 4. 影响范围与建议优先级

**影响对象：**Run 明细查询、本地用量/耗时导出、人工介入和质量证据关联。

**功能边界 / 非目标：**不建设远程监控、计费平台或全项目绩效系统，不承诺缺失供应方数据时可准确计算费用。

**优先级理由：**补齐可靠交接、可维护性或运行保障，在关键错误放行问题之后推进。

**风险与兼容：**耗时与费用不是质量替代品；机器通过、真实业务结果和人工验收必须分列，避免优化错误指标。
