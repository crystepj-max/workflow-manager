## 2. 需求目标与验收标准

**目标：**评审者不能改动被审成果，测试者可产出测试证据而不能修改业务候选，发布能力只对明确授权动作开放。

**业务规则与边界：**

- 节点声明最小能力：读候选、写候选、写测试/证据、调用外部发布；宿主在暴露工具和工作区时落实。建设 dev 可写候选和自测；review 只读候选且可写审查证据；test 只读业务候选，可写独立测试区/证据；研究只读冻结源且写私有研究区。
- 测试所需构建缓存和临时产物位于明确可写副本/目录，不靠开放整个源码目录解决。测试器注入新测试时记录测试覆盖层，证明仍绑定原业务候选。
- 不支持隔离能力的 Profile 在独立证明前明确受阻或降级为“非独立、不能签发正式 Proof”；不能用更强提示词冒充宿主隔离。既有有效授权决定外部动作能力，不给所有 closeout 自动发布权。

**可检查的验收条件：**

- [ ] AC-01：review 写候选、test 写业务源码、researcher 写源树均被实际文件/工具层拒绝，而不只是模型遵守。
- [ ] AC-02：review/test 能在证据区写报告，test 能运行所需测试与缓存；合法行为不因只读候选全部失效。
- [ ] AC-03：无发布授权节点无法调用发布动作，已授权适配动作仍按原流程执行。
- [ ] AC-04：路径穿越、符号链接和直接 shell 绕过尝试均按支持的宿主边界验证；不支持强制隔离的环境明确标注能力缺失。

**代表验收路径：**在真实受支持宿主上分别以 review/test/researcher 运行受控越权写入探针，再执行合法报告与测试操作，检查拒绝、可用性和成果未变。

## 4. 影响范围与建议优先级

**影响对象：**节点工具可见性、源码/测试/证据目录权限与正式独立证明资格。

**功能边界 / 非目标：**不设计完整 RBAC 平台，不声称能在不支持的外部 CLI 沙箱上隔离一切；不替代模型认知独立性评估。

**优先级理由：**补齐可靠交接、可维护性或运行保障，在关键错误放行问题之后推进。
