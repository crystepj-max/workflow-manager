## 2. 需求目标与验收标准

**目标：**每次成功结果能列出真实产物及其不可变版本，下游从索引读取，必要产物缺失时不签发完成证明。

**业务规则与边界：**

- 支持静态必需/可选产物以及 fanout 动态产物清单。条目包含 logical_name、producer attempt、round/item、相对路径、媒体类型、字节数、摘要及正式记录引用。
- 产物必须位于授权成果根内；校验存在、可读、声明类型与摘要。动态路径基于受校验的专家标识与轮次，拒绝路径穿越、重复逻辑标识和指向其他轮的冒名条目。
- 必需产物提交失败时保留节点专业结论，但阻止以“交付完整”为前提的后续证明。可选缺失显式记录；消费方只读取声明清单，探索综合不扫描目录猜最新。

**可检查的验收条件：**

- [ ] AC-01：缺失建设 UAT 必需卡片时不能宣称验收材料就绪；补齐后可继续同一 Run。
- [ ] AC-02：同一专家两轮报告形成两个可读版本；综合明确收到本轮及声明保留的历史结果，不混入无关文件。
- [ ] AC-03：错误摘要、越界路径、符号链接越出授权根、重复产物 ID 均被拦截。
- [ ] AC-04：可选报告缺失不误阻断；必需/可选状态与产物校验结果在记录中可见。

**代表验收路径：**生成两名专家两轮报告，额外放置一个同名前缀的过期文件；综合只收到索引内条目。删除一个必需报告后应显示材料缺失而非已完成。

## 4. 影响范围与建议优先级

**影响对象：**四模板声明文件的核验、探索动态报告交接和完成材料完整性。

**功能边界 / 非目标：**覆盖本地文件型产物；不建设云存储、全文索引或通用附件管理产品。

**优先级理由：**补齐可靠交接、可维护性或运行保障，在关键错误放行问题之后推进。

**风险与兼容：**大文件计算摘要有成本，流式处理并按已声明根访问；不把“文件存在”当作内容正确的业务验收。
