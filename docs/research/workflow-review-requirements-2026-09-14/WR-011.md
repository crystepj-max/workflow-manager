## 1. 需求背景与参考资料

技术失败先内部修复再走自环，不消耗业务返工额度。technical-retry 复现连续调用 1000 次才停止，远超用户容易理解的“最多 3 轮”；不计额度的重新确认回路也可能反复消耗。

## 2. 需求目标与验收标准

**目标：**失败后的最大自动消耗可解释、可配置且有限，技术问题不吞掉业务返工额度。

**业务规则与边界：**

- 建立技术失败分类：输出结构错误可有限修复；暂时服务错误可退避重试；权限拒绝、必需输入缺失、业务契约冲突不自动重跑有副作用节点。所有实际模型调用计入统计。
- V1 建议默认：同一节点、同一输入版本的一次激活最多 3 次模型尝试，包含首次和格式修复；重试等待 1 秒、2 秒。单次调用截止 30 分钟，Run 累计自动运行时间上限 4 小时；人工等待不计时。配置可收紧或显式调整时间上限，启动时展示并冻结，恢复不得自动清零技术消耗。业务额度沿用模板/M2，不改变建设的常量 3。
- 不计业务额度的回边，以节点、实际输入内容摘要、评价基线内容及目标摘要识别进展；仅改变 Revision 序号或 attempt_id 不视为进展；连续 2 次返回相同签名且无新有效成果则受阻。停止原因指出预算种类、已用量与下一步，不再主要依赖 AGENT_CAP。
- 费用仅在模型价格和实际用量可知时计算/限制；未知显示 unavailable，不能当 0。本条必须实现调用次数和时间硬界限，精细成本看板归 WR-020。

**可检查的验收条件：**

- [ ] AC-01：持续无效输出最多调用 3 次即停止；内部格式修复和技术自环不能各自偷偷获得额外 3 次。
- [ ] AC-02：暂时错误按可控时钟验证退避；不可重试错误最多调用 1 次即停止；超时后停止发起新调用并尽力取消当前调用。
- [ ] AC-03：业务返工计数不因技术重试增加；同一受阻 Run 恢复不重置已耗预算，人工明确新技术额度后才能继续。
- [ ] AC-04：相同目标的无进展重新确认连续 2 次后受阻；真正的新目标/新基线不被误判。
- [ ] AC-05：用户可查看冻结的次数/时间限制及实际消耗；无法强制终止的外部调用标明取消能力限制。

**代表验收路径：**用无效输出和临时服务异常分别驱动优化确认节点，核对调用计数、退避、时间预算、停止原因；再重复无新内容的重新确认，确认不会持续运行。

## 4. 影响范围与建议优先级

**影响对象：**四模板自动调用次数、技术失败等待、运行时间、恢复预算及用户受阻提示。

**功能边界 / 非目标：**不扩大业务自动返工额度，不引入 Temporal 或队列服务，不在未知价格下承诺实际货币硬上限。

**优先级理由：**影响错误放行、虚假完成或失控消耗，建议先于扩展使用范围处理。

**风险与兼容：**新增数字是本需求建议基线，非历史产品决定。长耗时任务可在开跑前显式调整时间限制；超时不能保证第三方已经停止执行，因此必须与副作用幂等配合。
