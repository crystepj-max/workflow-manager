## 2. 需求目标与验收标准

**目标：**所有建设入口按同一机械规则判定可开工性，模型只解释失败项和无法机械核实的补充信息。

**业务规则与边界：**

- 调用现有 runPreflight，复用任务状态、无人值守许可、Issue/本地/Run 基线一致、环境组与依赖完成等检查，不复制第二份条件判断。
- 支持 DEFINED 与满足当前契约的 LOCAL_DEFINED；有前置依赖但已完成、同组成员环境有效时不能因“有依赖”一概拒绝。
- 必要输入缺失、版本不一致或依赖未完成时，在启动开发之前受阻，逐项输出原因与可恢复动作。环境只读核查，不由 evaluator 自动创建/清理另一套现场。
- 机械 PASS 不能被模型无证据推翻，机械 BLOCKED 不能被模型说服放行；新增可客观验证的规则须进入同一检查器。

**可检查的验收条件：**

- [ ] AC-01：同一输入从 Bootstrap、正式 wf_run 和测试适配入口获得相同可开工结论及原因码。
- [ ] AC-02：已完成依赖的合法同组成员、合法本地已定义任务通过；未完成依赖、版本冲突、缺许可均受阻且 dev 未调用。
- [ ] AC-03：模型输出 PASS 不能覆盖机械失败，机械通过的常规场景不再额外消耗一次模型资格判断调用。
- [ ] AC-04：不覆盖既有模型连接探测；任务资格检查与服务就绪检查可分别定位失败。

**代表验收路径：**准备无依赖、合法串行成员、依赖未完成及本地已定义四份任务输入，从两种正式建设入口核对结果和开发启动次数。

## 4. 影响范围与建议优先级

**影响对象：**建设开工入口、任务资格校验及阻塞原因，不改变后续专业质量门。

**功能边界 / 非目标：**只收敛建设开工资格检查，不重新实现任务定义、环境分配或批量调度。

**优先级理由：**补齐可靠交接、可维护性或运行保障，在关键错误放行问题之后推进。

**风险与兼容：**减少模型调用不等于删除必要门禁；未知外部状态应明确未核实，不能机械默认通过。
