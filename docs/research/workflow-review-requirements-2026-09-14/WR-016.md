## 2. 需求目标与验收标准

**目标：**模板加载前即可知道关键约束是否受支持，同一契约在编辑、生成和执行中含义一致。

**业务规则与边界：**

- 以现有 Blueprint 版本字段为基础梳理版本命名；新增协议能力声明时单一映射，避免再造相互独立的版本号。V1 所需能力至少覆盖现有八类关键字以及本需求包必需的数量约束、组合约束和显式语义校验能力。
- 维护机器可读支持矩阵：声明、静态校验、运行时执行三者逐项一致。未知验证关键字或未支持的必需能力明确拒绝；title/description 等注释可忽略但不能伪称执行。
- 公共 envelope 只承担版本、Run/Node/Attempt、快照、模型、输入/输出引用和关联决定；领域 payload 仍由各节点定义。新增引用接口逐项注册，不创建涵盖所有业务字段的超级 Schema。
- 旧无能力声明蓝图进入明确 legacy 模式，记录警示；未知不兼容主版本禁止新开 Run。已启动 Run 继续使用冻结协议与脚本，不静默迁移。

**可检查的验收条件：**

- [ ] AC-01：对全部声明支持关键字提供至少一个合法和一个非法值，静态/运行时结论一致。
- [ ] AC-02：未知关键字、未来主版本、缺少必需能力均在代理调用前拒绝并给出路径；注释字段不误阻断。
- [ ] AC-03：四模板生成、投影往返及 Portable 样例分别按其真实契约验证，不把不同 Schema 体系误当同一协议。
- [ ] AC-04：旧 Run 恢复仍用原快照；新增协议字段可追溯生产者和消费方，领域 payload 没有被统一成大而全结构。

**代表验收路径：**给探索计划添加受支持 minItems，再故意换为未支持的约束关键字；前者真实阻止空数组，后者在启动前明确报不支持。

## 4. 影响范围与建议优先级

**影响对象：**蓝图导入/编辑、编译校验、运行兼容与模板作者收到的诊断。

**功能边界 / 非目标：**不要求完整实现 JSON Schema 2020-12，不迁移所有 Portable 历史包，不引入独立协议服务。

**优先级理由：**补齐可靠交接、可维护性或运行保障，在关键错误放行问题之后推进。

**风险与兼容：**严格拒绝可能暴露旧模板中一直未执行的规则；须提供定位和 legacy 行为说明，不能静默删掉约束让模板通过。
