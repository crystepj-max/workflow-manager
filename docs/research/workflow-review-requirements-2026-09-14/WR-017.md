## 2. 需求目标与验收标准

**目标：**用户和 agent 能快速识别当前真实行为、未来目标与历史兼容；生成指南只要求对应模板实际需要的动作。

**业务规则与边界：**

- 建立一份有基线提交与核验日期的能力索引，列 Current 代码/模板证据、Target 规格及差异、Legacy 入口与适用版本。保留历史设计，不把计划写成已上线。
- 生成 runbook 按模板人工关口、收口节点、工作区和完成类型输出：探索研究完成无需 merge commit；非 Git 优化不要求 PR；建设 M2 严格三态与定义外置保持明确。
- 兼容转换集中在入口适配并列出维护位置、仍有使用者的证据和退役条件；V1 只标注与集中已重复的解释，不无依据删除兼容能力。
- 每项后续实现负责更新直接相关索引；本条当前事实以开发时核验 HEAD 为准，并记录相对评审基线差异。

**可检查的验收条件：**

- [ ] AC-01：能力索引逐项提供源码或测试链接，无已实现能力仍被无版本标注地列作“尚未实现”。
- [ ] AC-02：四模板生成指南各经检查：人工关口、产物、完成类型与模板一致；探索/非 Git 优化没有强制合并要求。
- [ ] AC-03：M2 与 Portable 旧七阶段关系一处明确解释并被其他文档引用，无两套互相矛盾的当前主链。
- [ ] AC-04：旧运行恢复说明与新建流程说明可区分；生成一致性检查能发现指南与模板漂移。

**代表验收路径：**让只拿到生成 Skill 的接手者分别阅读探索和建设入口，按文档指出开始条件、完成产物及人工关口；答案应与当前模板/宿主行为一致。

## 4. 影响范围与建议优先级

**影响对象：**接手者阅读的能力索引、建设兼容说明和四模板生成 Skill。

**功能边界 / 非目标：**只清理工作流机制及四模板直接相关文档，不做全仓知识治理，不改全局 Agent Policy 或用户已安装 Skill。

**优先级理由：**补齐可靠交接、可维护性或运行保障，在关键错误放行问题之后推进。

**风险与兼容：**并行实现会改变 Current，合并前重核源码；索引必须记录基线，不能把本需求包的建议提前列为已实现。
