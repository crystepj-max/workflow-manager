## 2. 需求目标与验收标准

**目标：**完成类型由经过核验的执行路径和决定记录派生，准确区分评估通过、人工接受及建设三态。

**业务规则与边界：**

- 优化：evaluate PASS 路径仅可形成 EVALUATION_PASSED；经当前人工等待点 ACCEPT 才可形成 USER_ACCEPTED。后者必须引用本 Run、本决定点及当前 candidate_ref 的有效人工记录，且记录产生在成果冻结之后。
- 建设保持 ACCEPT/REJECT/CONDITIONAL_PASS：REJECT 回开发；CONDITIONAL_PASS 只记录下一轮优化输入，不表示接受本轮未达标成果。禁止通用 USER_ACCEPTED 快捷路径覆盖建设三态或跳过应有收口。
- 人工记录只能由宿主人工交互入口形成，模型结果、评论文本或伪造 actor 字段不能创建同等授权。重复提交同一个决定 ID 应幂等，互相冲突的第二次决定拒绝并保留审计。

**可检查的验收条件：**

- [ ] AC-01：无决定、其他 Run 决定、旧候选决定、模型自报人工接受四种情况均不能生成有效 USER_ACCEPTED。
- [ ] AC-02：优化 PASS 正常自动收口；真实 ACCEPT 对应同一成果时正确生成 USER_ACCEPTED。
- [ ] AC-03：建设三态各走原定路径，无操作继续等待；CONDITIONAL_PASS 的后续意见不修改本轮基线。
- [ ] AC-04：同一决定重复恢复不重复收口；成果在决定后变化时必须重新获得针对新版本的验收。

**代表验收路径：**运行优化进入人工 CONFIRM，先提交伪造模型结果应失败；在宿主界面接受当前候选应成功。建设分别选择三态并核对状态、成果版本和后续意见去向。
