## 2. 需求目标与验收标准

**目标：**成果和证明精确引用本次真正消费的输入 Revision；只使受影响的下游证明失效。

**业务规则与边界：**

- 使用 resolved_inputs 中的正式引用生成依赖集合，并绑定本次 attempt；依赖具体 Revision，禁止“最新”浮动引用。非正式临时引用不可用于签发正式 Proof，必须先提交或明确阻断。
- 输入发生新 Revision 时，对直接和传递消费者标记 stale；不修改历史专业结论内容。更新无关成果不能使既有证明 stale。旧记录缺依赖时显示依赖不完整，不推断其已证明最新成果。
- 依赖缺失、跨 Run 不受支持的引用、环依赖和不存在的 Revision 给出定位错误。V1 不开放跨 Run 成果消费。

**可检查的验收条件：**

- [ ] AC-01：A→B→Proof 更新 A 后，B 与 Proof 失效；独立 C 仍有效。更新 C 不影响该 Proof。
- [ ] AC-02：同一成果有两版时消费者仍能读取其绑定旧版；新执行明确使用新版，不悄悄改写历史引用。
- [ ] AC-03：并行专家一人补充只使实际读取其旧结果的综合/终评失效，不使无关专家报告失效。
- [ ] AC-04：缺失引用、临时引用用于正式 Proof、循环依赖均被拒绝；恢复后依赖集合不扩大为所有当前记录。

**代表验收路径：**构造两条互不依赖的成果链，各签发证明；只更新其中一条，检查界面/记录输出只提示该链需要重新验证。
