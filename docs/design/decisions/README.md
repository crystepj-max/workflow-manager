# 架构级决策记录（ADR）

> 本目录存放**架构级决策**：影响跨任务、跨版本、难以低成本推翻的选择。
> 权威约定见 `docs/design/workspace-directory-convention.md` §1.9（变更记录分层）。

## 与相邻记录的分工（不互相替代）

| 记录类型 | 存放位置 | 记录什么 |
|---|---|---|
| **架构级决策** | 本目录 `NNNN-<slug>.md` | 跨任务、长期、推翻成本高的选择 |
| 任务级记录 | `docs/tasks/`（登记册 + 任务卡 + `archive/<TASK_ID>/`） | 单任务的范围、验收与归档三件套 |
| 阶段性决策票 | `wayfinder/tickets/*.md` + `wayfinder/MAP.md` | 某一批次内待决问题的逐票决断，阶段完成后冻结 |
| 交付事件 | 根 `CHANGELOG.md` | 每次合并发生了什么的流水 |
| 研究过程 | `docs/research/<slug>.md` | 调研与实验结论 |

## 硬规则

1. **已接受的记录永不修改。** 决策被推翻时，写一条新记录，并在旧记录的状态行标注 `Superseded by NNNN`。
   这样仓库里留下的是一条可追溯的决策时间线，而不只是当前状态。
2. **一文件一决策**，编号单调递增，标题用祈使式短语。
3. **一段一决策**：一条 ADR 只解决一个问题；多个决定 → 多条 ADR 或一条 ADR 内的明确列表。
4. **必须写「被否决的备选及原因」**。只写结论的决策记录，日后无法判断是否还有效。
5. **入库**：本目录全部文件进版本控制。放在 wiki 或忽略目录里的决策记录，结局是被遗忘。

```markdown
---

## 后果
- 正面：
- 代价 / 新增的负担：
- 风险与缓解：

## 被否决的备选
- 备选 A —— 否决原因
- 备选 B —— 否决原因
```
