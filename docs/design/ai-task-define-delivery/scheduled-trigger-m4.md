# M4｜定时触发（到点唤起同一执行计划）

> **里程碑**：M4  
> **定位**：在约定时刻**自动唤起**已有「执行计划 / 批量开工」，不另写筛选、排序、并发、补位或汇总规则。  
> **依赖**：M1 已定义；M2 单任务交付；M3 Execution Plan（`execution-plan-m3.md`）。  
> **权威取舍**：以实施任务书 V0.1 §10 为准；本里程碑**不含**完整「待验收工作台」界面，**不含**每晚常驻循环 / 漏跑补跑。

---

## 1. 用户价值

白天谈清并确认的一批任务，能在约定时间自动开跑施工；第二天你直接看「谁等你验收、谁卡住、谁做完」，再验收/收口——不必夜里盯着，也不必早上再挨个手动开工。

---

## 2. 输入（预约单）

| 字段 | 说明 |
|---|---|
| 到点时刻 `runAt` | 一个指定时刻（ISO 8601）；到点后启动一次 |
| 批次说明 | 与 M3 相同的候选任务清单 + 最大并发（`batch.json`） |
| 启动方式 | 本里程碑固定为「到点再调同一执行计划」；亦可用「立即」对照，行为必须一致 |
| （可选）模拟事件 | 仅机械验收：释放名额/补位事件，不连真实施工环境 |

预约语义（V0.1）：

- **约一次**：到点跑一轮；不是每晚自动重复。
- **未到点**：不启动；可查询「仍在等待到点」。
- **已到点 / 强制立即对照**：调用与「立即批量开工」相同的执行计划入口。

---

## 3. 行为（硬约束）

1. 定时逻辑**只负责**：判断是否到点 → 唤起 M3 执行计划 → 落盘夜间批次报告。  
2. **不得**在定时逻辑里复制：资格筛选、快照、排序、并发、补位、结束判断、汇总字段定义。  
3. 同一批候选：`立即开跑` 与 `到点开跑` 选出的任务、启动顺序、并发与补位结果必须一致（时间戳字段可不同）。  
4. 不做需求分析、改基线、代签验收；有依赖任务仍按 M3 记入「未纳入」。

```text
预约（runAt + 批次）
  ↓
未到点 → 等待 / 回报「尚未到点」
  ↓
到点 → 调用同一套 Execution Plan
  ↓
自动施工阶段结束（或机械模拟结束）
  ↓
写出夜间批次报告（次日可读）
```

---

## 4. 夜间批次报告（次日可读）

字段对齐 M3「批次汇总」，并加抬头说明「本报告由到点触发产生」：

```text
【夜间批次报告】
批次名称
预约到点时刻
实际启动时间
自动施工结束时间
快照任务总数 / 最大并发

等待验收：
- …（含验收定位信息）

执行受阻：
- …（节点 / 原因 / 返工 / 下一步）

已完成：
- …

未纳入：
- …（原因）
```

本里程碑**不**建设独立「待验收工作台」；次日验收仍走单任务交付既有验收三态入口，报告只负责指路。

---

## 5. 端到端试跑（验收）

至少一次用 **3～5** 个真实或等价夹具任务走完：

```text
白天定义并确认 → 预约到点（或机械强制到点）→ 夜间/模拟施工 → 次日按报告验收 → 收口或返工
```

清单见 `m4-e2e-trial.md`。

---

## 6. 明确非本里程碑

- 完整待验收工作台 / 验收快速操作界面（产品规格 §42 后置）
- 每晚常驻循环、漏跑自动补跑、关机错过策略
- 第二套调度规则；有依赖自动接续；运行中抢占 / 动态塞入新任务
- 批量里改需求或代签 UAT
