# M4 端到端试跑清单

> 对应 `scheduled-trigger-m4.md`。目标：用 3～5 个任务证明「白天定义 → 到点开跑 → 次日按报告验收」闭环。

## 机械对照（仓库内必过）

```bash
node scripts/ai-task-scheduled-m4-check.mjs
```

证明：同一批候选下，**立即开跑**与**到点开跑（强制到点）**的快照任务与启动顺序一致；并写出夜间批次报告文件。

夹具：`scripts/test/fixtures/ai-task-scheduled-m4/`（复用 M3 场景任务 A/B/C，共 3 个）。

## 真实试跑（合入后 / dogfood，3～5 个）

| 步 | 你做什么 | 成功长什么样 |
|---|---|---|
| 1 | 白天用需求分析把 3～5 个任务谈到「已定义」，无人值守=允许，前置依赖=无 | 每条有基本信息 + 规格 + 基线版本一致 |
| 2 | 写好批次清单与最大并发；预约一个到点时刻（或先用「立即」对照） | 预约单可被到点启动读取 |
| 3 | 到点后无需再点「开工」；自动进入批量施工与补位 | 与立即跑行为一致 |
| 4 | 自动施工结束后打开夜间批次报告 | 能看到等待验收 / 受阻 / 已完成 / 未纳入 |
| 5 | 次日按报告对「等待验收」做通过 / 退回 / 有条件通过 | 原任务可续跑或收口，不丢上下文 |

## 记录证据时至少留下

- 批次名称、预约时刻、实际启动时间
- 夜间报告全文或路径
- 等待验收任务列表与验收结论
- 说明：未另写一套筛选/排序/补位规则（定时只唤起执行计划）
