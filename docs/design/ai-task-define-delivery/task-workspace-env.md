# 单任务施工环境（分支 + 独立工作区）

> **产品拍板（2026-09-06）**  
> 1. **只改单任务交付**：启动时判断沿用关联任务的分支/工作区（worktree，即：同一套独立施工现场），还是新建。批量调度**只管排谁开工**，不管分支与工作区。  
> 2. **定义阶段**拆任务时，人与 Agent 共同判定关联；确认后写入任务关联（如父 Issue ↔ 子 Issue）。基于父任务建立分支与工作区后，同组子任务在该环境内**串行**开发。  
> 3. **同环境内全部任务验收通过后**再清理工作区。

权威契约字段见 `public-task-contract.md` §1.1。机械入口：`scripts/ai-task-workspace-env.mjs`。

---

## 1. 用户价值

| 场景 | 行为 |
|---|---|
| 互不相关的任务 | 各自新建分支 + 独立工作区，可并行 |
| 有关联 / 父子依赖 | 共用同一环境组；按依赖顺序串行施工 |
| 同组全部验收通过 | 才清理该组的独立工作区 |

🟢 并行不互相踩；有依赖的不会开错现场；验收未齐不提前拆台。

---

## 2. 环境组（Workspace Env）

一个环境组绑定：

- `env_id`（建议 = 父 Issue 编号或功能 slug）
- `work_branch`
- 独立工作区路径（Git worktree）
- 成员任务列表（root + members）及各自状态

| 施工环境角色 | 含义 |
|---|---|
| `独立` / `root` | 本任务负责创建分支与工作区（通常是父任务或无关联任务） |
| `成员` / `member` | 沿用已有环境组；不得另拉一套 |

---

## 3. 单任务启动判定

```text
实施前检查通过
  ↓
读 Issue：施工环境组 / 角色 / 前置依赖
  ↓
角色 = 独立或 root？
  ├─ 是 → 创建分支 + worktree，登记环境组
  └─ 否（成员）→
        环境组是否存在？
        ├─ 否 → 受阻：父环境尚未建立
        └─ 是 → 前置依赖任务是否均已完成？
              ├─ 否 → 受阻：等待同组前置完成（串行）
              └─ 是 → 沿用同一分支与工作区开工
```

批量调度**不得**调用本模块创建/清理工作区；它只决定「轮到谁跑单任务交付」。

---

## 4. 清理

仅当环境组内**全部成员**状态为「已完成」（验收通过或有条件通过后的收口）时，才移除 worktree 并归档环境组元数据。

任一成员仍为交付中 / 等待验收 / 受阻 → **禁止**清理。

---

## 5. 与 #93 隔离内核关系

本模块消费 `scripts/workspace-isolation.mjs` 的 Git worktree 能力（创建 / 清理），在「任务关联」层增加：

- 环境组登记与成员串行门禁  
- 「全员验收通过后再清理」  

不平行实现第二套 Git 操作。
