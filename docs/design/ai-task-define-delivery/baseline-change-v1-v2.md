# 需求基线 V1→V2（实质变更闭环）

> 适用：已进入「已定义」或之后的任务，发生实质需求变更。  
> 权威：`docs/design/ai-task-define-delivery/public-task-contract.md` §4。

---

## 1. 判定

下列任一变化 → **必须**升版（不得只改措辞假装仍是旧版本）：

- 目标 / 功能范围 / 非目标
- 用户行为 / 业务规则 / 验收标准
- 风险边界 / 功能切片边界明显变化

下列可不升版（直接修正文档即可）：

- 错别字、表述优化、不改变含义的补充、增加已有结论的证据或示例

---

## 2. 流程

```text
发现实质需求变化
  ↓
任务状态 → 定义中（若已在交付中：先标记执行受阻·定义型，再回定义）
  ↓
完成必要人工决策（渐进式决策卡）
  ↓
更新本地任务规格：复制为 task-spec-V2.md（或同文件升版并写版本历史）
  ↓
跑 Definition Check（未决事项 = 0）
  ↓
人工确认：「确认需求基线 V2，可按该版本进入交付。」
  ↓
Issue 添加版本变更评论（下方模板）
  ↓
Issue 基本信息：需求基线版本 = V2；任务规格位置指向 V2；必要时更新定义时间策略见下
  ↓
状态 → 已定义
```

**定义时间**：首次进入「已定义」的时间保留用于排序；升版不回拨定义时间。可另增「基线确认时间」于规格版本历史。

**已启动的交付 Run**：禁止静默切到 V2；应受阻并等待按新版本重新进入执行。

---

## 3. Issue 版本变更评论模板

```text
需求基线：V1 → V2

变更原因：
<原因>

主要变化：
- <变化 1>
- <变化 2>

详细规格：
.scratch/<feature-slug>/task-spec-V2.md
```

发布时仍加：

```text
> *This was generated by AI during triage.*
```
