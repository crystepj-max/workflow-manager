# M1 → 建设流程桥接说明（定义外置）

> **里程碑**：M1（只接线契约与入口语义，不做完整 M2 交付改造）  
> **产品拍板**：单任务交付以任务书为准改造建设流程——**定义外置**，交付从「已定义」开工。

---

## 1. 当前与目标

| 维度 | 当前（建设 Portable Contract） | 目标（AI 任务定义与批量交付 V0.1） |
|---|---|---|
| 定义位置 | 建设主链 Stage「requirements」内完成 | 由「需求分析」Skill 外置完成，产出「已定义」 |
| 交付起点 | 从 requirements 开始整条七阶段 | 从「已定义」进入实施前检查 → 开发 → … |
| 自动返工上限 | 已为 **3** | **产品拍板：3**（与建设一致；覆盖上游规格文中的 2） |
| 人工验收 | `accept` / `reject` / `user_accepted` | 严格三态：`ACCEPT` / `REJECT` / `CONDITIONAL_PASS`（见公共契约 §6） |

## 2. M1 已完成的预留

- 公共任务字段 / 状态 / 版本 / 「已定义」落档清单：`public-task-contract.md`
- 定义入口升级：`dsh/skills/requirements-analysis`（不新建第二入口）
- 验收三态与返工上限 3 写入公共契约，供 M2 消费

## 3. M2 必须完成的最小接线（本文件不实施）

1. 建设 / 单任务交付入口：若 Issue 状态已是「已定义」且版本一致 → **跳过**重新定义决策闭环，进入实施前检查。
2. 实施前检查读取公共契约 §1/§5 字段。
3. 人工验收枚举迁移到严格三态；废弃用 `user_accepted` 表达「有条件通过」。
4. 自动返工常量显式对齐 `auto_rework_limit = 3`。

## 4. 纪律

- M1 **不**修改 `handoff.schema.json` 验收枚举（避免本里程碑扩大范围）。
- M1 **不**重写建设七阶段 runbook 主链。
- 发现建设契约与公共契约冲突时：产品行为以 `public-task-contract.md` 为准；实现迁移在 M2 提交。
