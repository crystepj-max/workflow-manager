# M3｜Execution Plan（批量调度）

> **里程碑**：M3  
> **定位**：只决定「哪些已定义任务现在开始 / 何时补位」，**不**做需求分析、开发、审查、测试或 UAT。  
> **依赖**：公共契约 `public-task-contract.md`；单任务交付主链 `single-task-delivery-m2.md`。  
> **产品拍板沿用**：自动返工上限 3；验收严格三态（由单任务交付执行，本计划只观察 Run 宏观状态）。

---

## 1. 输入

| 字段 | 说明 |
|---|---|
| 所属项目 | 仓库 / 工作区标识 |
| 候选任务范围 | Issue 基本信息文件列表（或等价清单） |
| 最大并发 | 正整数；同时处于 `RUNNING` 的上限 |
| 启动方式 | `immediate`（立即）/ `scheduled`（定时触发同一 Skill，M4） |

V0.1 排序固定：

```text
P0 > P1 > P2
同优先级：定义时间从早到晚
```

---

## 2. 可执行资格（进入快照）

全部满足才可进入本批快照：

```text
状态 = 已定义
AND 无人值守许可 = 允许
AND 前置依赖 = 无
AND 存在有效需求基线版本
AND 本地规格可读取
AND Issue 基线版本 = 本地规格版本
```

不满足时：

- **有前置依赖** → 记入「未纳入」，原因：`V0.1 暂不支持关联任务自动执行`（不报错中断整批）
- **其它资格失败** → 记入「未纳入」并写明原因

---

## 3. 任务快照

启动时冻结每条：

- 任务 ID / 名称  
- 需求基线版本  
- 优先级  
- 定义时间  
- Issue 基本信息路径、本地规格路径  

计划启动后：

- 新出现的已定义任务 **不**加入本批  
- 需求版本变化 **不**自动更新快照；已启动的旧 Run 在安全点应 `BLOCKED`（由单任务交付执行）

---

## 4. 启动、名额与补位

- 在最大并发内按排序启动单任务交付（Workflow Run）  
- **占用名额**：Run 宏观状态 = `RUNNING`  
- **释放名额**：`WAITING_HUMAN` / `BLOCKED` / `COMPLETED`  
- 释放后立即从快照中尚未启动的任务按序补位  

V0.1 不支持：动态加入新任务、抢占、P0 打断低优先级。

---

## 5. 批次自动施工结束

当同时成立：

```text
没有 RUNNING
+
没有「快照内未启动但仍可执行」的任务
```

即结束本批**自动施工阶段**（不必等全部 `COMPLETED`）。

任务可分布在：等待验收 / 执行受阻 / 已完成。

---

## 6. 批次汇总（最低字段）

```text
批次名称
开始时间
自动施工结束时间
快照任务总数

等待验收：
- …

执行受阻：
- …（阻塞节点 / 原因 / 已返工次数 / 推荐下一步）

已完成：
- …

未纳入：
- …（原因）
```

每个等待验收任务至少给出 UAT 入口或定位信息（Issue / 验收卡路径）。

---

## 7. 责任边界（摘要）

| 事项 | Execution Plan |
|---|---|
| 选批次任务 / 排序 / 并发 / 补位 / 汇总 | ✅ |
| 启动单任务交付 Run | ✅（触发，不实施内容） |
| 需求分析 / 改基线 / 开发 / 审查 / 测试 / UAT | ❌ |

---

## 8. 机械验收场景（本里程碑）

场景 1（必过）：A/P0、B/P1、C/P1，均已定义、允许无人值守、无依赖；最大并发=2。  
期望：先启 A+B；A → WAITING_HUMAN 后 C 补入；无 RUNNING 且无可启动剩余时结束并出汇总。
