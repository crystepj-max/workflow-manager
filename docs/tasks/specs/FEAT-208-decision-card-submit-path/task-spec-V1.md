# 决策卡提交路径闭环（UI 续跑接原运行）

## 1. 背景与裁决

LOC-016 的 DT-01-ui-resume-attribution 已由松哥裁决（2026-09-19）：**UI 发起的续跑接在原运行上继续**——同 Logical Run 追加段/attempt。依据：需求目标未变更，变更的只是开发工具与实现方式；运行详情的快照版本记录已承载这些变更。FEAT-85 已交付决策卡/恢复卡的界面与字段映射，提交路径当时按受阻交出；本任务按裁决实现提交闭环。

## 2. 实现要求

1. 决策卡（WAITING_HUMAN）点选选项 + 理由提交 → 走既有字段映射，向原 Logical Run 追加段/attempt 续跑；不新开运行、不伪造成功状态。
2. 恢复卡（BLOCKED 改模型恢复）同口径：提交后原运行按新 Provider/Model 恢复执行。
3. Formal Record provenance 如实记录「UI 触发」来源（触发人/触发面），不冒充会话内触发。
4. 提交后的详情页状态流转（运行中/等待人工/受阻）与既有三页签、attempt 切换、链路弹窗联动保持。

## 3. 零回退约束

- FEAT-85/103/105/107/108 已验收行为全部保持；决策卡/恢复卡的呈现层不动，只接通提交路径。
- 载荷预算不上调（现值 289230B / 290816B，余量约 1.6KB——实现优先复用既有 RPC 调用路径与样式；超限先瘦身，禁止自行上调）。
