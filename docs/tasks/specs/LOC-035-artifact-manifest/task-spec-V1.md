## 9. 业务规则

1. 每项包含 logical_name、producer_attempt_id、round_id、item_id（非 fanout 可为 null）、授权根内 relative_path、media_type、byte_length、sha256、required、verification_status 和正式 ref。身份按 attempt + round + item + logical_name 唯一，静态和动态声明走同一入口。
2. 生产者提交后由宿主读取实际字节并计算摘要，保存不可变版本再提交 manifest；消费者只读取该版本，不按 glob 或固定最新文件名扫描。声明摘要若提供必须相符，缺失由宿主计算；文件后续改写不能改旧版本。
3. 只允许普通可读文件，解析真实路径后检查授权根，拒绝绝对路径、.. 越界、符号链接越界、重复身份、跨轮冒领、摘要不符。MIME 只做声明/可识别格式校验，不推断业务真实性；必需文件默认不允许空字节，确需空文件须声明 allow_empty。
4. 必需产物失败时保留专业节点结果并将材料置为 incomplete，阻断 Proof/READY_FOR_HUMAN/DELIVERED；补齐由新提交尝试产生新 manifest Revision，在同 Run 继续。可选缺失记 missing_optional；路径和摘要错误即使可选也不能形成有效附件。
5. 复制快照与校验必须针对同一组字节，失败不得留下可消费的正式 ref；按 LOC-029 的提交/恢复机制清理或重用未正式化快照，不重复登记。

输入输出和归属：输入为 output.files 的兼容字符串声明（默认必需）或带 required 的结构声明，以及 fanout item 实际产物列表；LOC-029 提供 attempt 和提交事务。输出 artifact manifest Revision 与有效文件读取引用。与 LOC-034 可组合，但不依赖它的传递失效实现。

## 11. 异常和边界场景

- **缺 UAT 卡片与恢复**：建设节点返回正常结果但删去声明必需的 UAT 卡片。 处理结果必须为：首次不可宣称 READY_FOR_HUMAN，专业结果仍在；补齐后产生新有效清单且可继续。
- **两轮同名报告**：同一专家两轮分别写内容 R1、R2 的同名报告。 处理结果必须为：两个版本分别保持 R1/R2，综合只接收声明版本，不混入目录其他报告。
- **拒绝越界与损坏**：准备 ../outside、越界 symlink、同身份重复项、错误 sha256 和跨轮 item。 处理结果必须为：明确定位失败产物和原因，无可用伪 ref；合法根内文件能通过。
- **可选与空文件**：必需报告有效，可选报告缺失；另准备空的必需文件。 处理结果必须为：可选缺失可交付且可见；默认必需空文件阻断，显式允许空文件可通过结构校验。

共同恢复规则：证据不足写 BLOCKED/UNVERIFIED 并保留失败输入、恢复位置；同一原因重试不改变基线，不因无人值守降低验收。旧 Run 使用冻结快照；范围外变化另行记录，不静默迁移历史。
