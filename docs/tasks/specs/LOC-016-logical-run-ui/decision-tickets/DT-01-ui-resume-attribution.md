## 1. 必须决定什么

看板（浏览器 RPC）要发起一次续跑，必须回答：**谁作为这次执行段的 initiator / 归属？跨会话、跨重启如何保持绑定？**

## 2. 为什么必须现在决定（对片2 的产品结果影响）

- 续跑唯一入口是 agent 侧工具 `wf_run`（`packages/dsh-visual-workflow/src/host.js:2520+`），其执行需要 `agents.requireInitiator()` 与 `resolveEngine()`（`:2603-2605`）。
- `resolveEngine()` 在宿主 ctx 拿不到 `workflowEngine` 时，退化为「当前发起 agent」桥接（`:2506-2512`）；同文件 `:81-82` 明确浏览器 RPC 没有发起 agent。
- 结论：**不解决执行归属，看板就无法发起续跑**；这将直接决定片2 是「界面内完成」（V1 目标）还是退化为「复制命令」（目标降级）。
- 归属口径同时影响：Run 记录的任务归属与 Formal Record provenance、暂停/中断控制通道、并发互斥（同 `taskId` 串行）、工作区生命周期挂靠。

## 3. 候选方案（探路后择一）

**方案 A · 宿主保留发起绑定**
创建逻辑运行时记录发起 agent / session 绑定；续跑 RPC 复用该绑定取得 engine。
- 成本：宿主需持久化绑定并在会话失效时给出明确失败；跨重启需重建或降级。
- 收益：语义与今天 `wf_run` 一致（同 taskId 串行、同工作区、同 provenance）。
- 风险：发起会话已结束/被清理时的行为必须定义，否则会出现「看板点了没反应」。

**方案 B · 宿主级执行通道（不依赖会话）**
在宿主平面直接取得 `workflowEngine`（例如由组合在 host 平面挂载 engine 服务或提供无 agent 的运行入口）。
- 成本：涉及组合 / 平台层改动，超出插件自洽范围。
- 收益：看板与 Chat 真正对等，执行归属不与某个会话绑定。
- 风险：可能触碰「Invocation 与 Runtime 分离」与既有 agent 归属语义；需与 DSH 组合层确认。

**方案 C · 界面触发会话（回灌消息）**
看板把续跑意图回灌为一条会话消息，由 agent 执行 `wf_run`。
- 成本：需要一条客户端 → 会话的正式通道（当前无）。
- 收益：不改执行归属语义，续跑仍由 agent 发起。
- 风险：需要有人在会话里；「界面内完成」变成「界面发起、会话执行」，需人工确认是否满足目标。

**方案 D · 不做**（片2 取消，决策卡永久停留在「复制参数」）
- 成本：V1 目标降级。
- 收益：零技术风险。

## 4. 探路清单（关闭本票前必须完成的证据）

1. 在**开发 DSH** 中实测：从浏览器 RPC 调用时 `ctx.get('workflowEngine')` 是否可用、`agents.currentInitiator()` 返回什么（记录真实返回，不靠推断）。
2. 若选 A：验证「发起 agent 绑定」在**同一会话续跑**与**跨会话续跑**两种情形下能否取得 engine 并真正起跑（最小可运行实验）。
3. 若选 B：与组合层确认 host 平面能否提供 engine；不行则记录结论并排除。
4. 确认续跑对既有语义的影响面：同 `taskId` 互斥、`logicalTrigger='human_decision'|'pause_resume'`、Formal Record provenance、workspace 挂靠、暂停/中断控制通道（`segmentCtrls`）。
5. 给出**可复现**的结论与推荐方案（含失败降级行为：绑定失效时看板必须给出明确提示，不得静默无效）。
