## 9. 业务规则

- 为宿主管理的动作分配 operation_id，键由 Run、逻辑动作、目标和授权范围组成；同一动作跨模型尝试保持不变，不以 attempt_id 重新生成。
- 动作账本至少记录计划、授权引用、执行中、已确认成功、已确认失败、结果未知。执行前登记，外部成功后保存远端对象 ID/版本/回读凭证；重复调用同键返回原结果。
- 外部服务支持幂等键时传递；不支持时以目标身份和回读规则查证。崩溃后未知状态无法判明时停止自动重试并显示需核查，不能承诺所有服务 exactly-once。
- V1 先覆盖现有交付所需的创建 PR、合并和关闭任务接口，并提供本地假适配器；无授权不调用真实外部服务。任意 shell 脚本不自动获得同等保证。

**接手者可直接采用的实现边界：**新增小型本地操作账本和 execute-or-reconcile 入口，复用宿主 Run 身份/路径；定义 create-review、merge、close-task 三种受管理操作形状，接到现有可用适配器，并配本地计数型适配器验证恢复。独立接口可在 WR-014 收口接线前验收。

**接口与数据约定：**operation_id 的身份依据为 run+logical_action+target+authorization_scope，不因 attempt 变化；规范参数另存摘要以发现同键不同参数。provider.execute()/reconcile() 的查询结果只能为 confirmed_success、confirmed_not_executed、unknown；unknown 禁止重复执行。不支持的平台返回 capability_unavailable；本仓库 GitHub 不可用时不绕过 CNB 工具政策直接实现平台调用。

本条拥有 operation_id/操作账本及 execute-or-reconcile 接口；WR-014 的交付适配器消费该接口。接口内部不得推断用户授权。

**兼容方式：**新运行使用本条新规则；已启动运行保持其冻结快照。无法补证的旧历史明确 legacy/unverified，不改写成已验证完成。若其他 P0 已合入，复用其公共接口并运行集成检查；没有硬依赖的条目允许通过既有接口完成自身切片，不能自行等待整个需求包。

## 15. 验收条件

- [ ] AC-01：在外部成功但本地确认前注入崩溃，恢复先查询原目标，不重复创建第二个 PR/动作。
- [ ] AC-02：重复请求同键、同参数返回同一结果；同键不同目标/参数拒绝。
- [ ] AC-03：未知结果且查询不可用时进入待核查受阻，不再次执行；确认未执行后可安全重试。
- [ ] AC-04：输出格式修复只修复结果，不重新执行已确认动作；账本包含授权、操作、回读与恢复记录。

## 16. UAT 场景

### UAT-01 主路径与关键反例

- 验收目的：验证 §3 用户目标与 §15 全部 AC。
- 前置条件：对应候选源码在隔离 worktree；Node.js 24 与所需依赖可用；真实产品模式验证按既有发布规则使用安装产物。
- 操作步骤：用本地计数适配器模拟 create-review 已成功、确认前断线；两次恢复执行次数仍为 1。再模拟未知状态不能查询，要求受阻而非重发，三个动作种类共用该验收。
- 预期结果：正常输入达成目标；非法/缺失/过期输入按 §9 和 AC 拒绝；结果状态、产物和原因一致。
- 人工关注：界面/报告能看懂通过或受阻原因，不把测试替身结果当成用户已经接受。

### UAT-02 恢复与兼容

- 前置条件：保存一个旧快照与一个新规则 Run 的中间状态；仅在隔离环境制造中断。
- 操作步骤：分别恢复旧快照、新运行，再执行一次同请求重放或同内容重读；核对输出与证据。
- 预期结果：旧快照不静默迁移；新运行不丢有效成果、不伪造历史证明；本条涉及的非法条件仍被拦截。
- 证据要求：输出日志/实际产物/状态快照与候选 HEAD；不能只附最终 PASS 字样。
