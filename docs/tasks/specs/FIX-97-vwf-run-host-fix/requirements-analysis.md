# FIX-97 需求分析

## 问题
运行底座三处缺陷导致评价基线运行时不可靠（见任务规格背景）：目录错位、恢复被旧信号取消、任务编号被抹掉。

## 方案对比

- **方案 A（选定）：直接修复 host.js 三处 + 补 EB6/EB7/EB8 回归测试**
  - 成本：约 3 处精准补丁 + 1 个测试文件，已实现
  - 收益：缺陷消除、测试覆盖、风险最低
  - 风险：低，改动局部

- **方案 B（否决）：重构运行底座的 cwd 解析架构**
  - 成本：大范围重构
  - 收益：架构更统一
  - 风险：超出本次缺陷范围，引入回归，违反「只动必须动的地方」

- **方案 C（否决）：靠提示词规避**
  - 收益：无
  - 风险：运行底座缺陷不能靠提示词绕过，治标不治本

## 结论
采纳方案 A。缺陷定位清晰、修复代价最小、测试充分、不扩大范围。
