# FIX-97 任务规格 V1 —— VWF 运行宿主三项修复

## 当前状态
定义中（实现已随本分支完成，待合并）

## 背景与用户影响
可视化工作流插件有一个核心能力：每次工作流运行时，系统会冻结一份「验收契约」副本当作基线，后续运行都跟它对账，防止有人偷偷改验收标准（该功能由 LOC-027 引入并已上线）。

但这个「运行底座」有 3 个缺陷，会让工作流跑起来时不可靠：

- **缺陷一（目录错位）**：运行产出的文件（基线冻结副本、产物清单）存错了位置 —— 按「源码目录」而不是「实际运行目录」去找，导致基线冻结/产物清单找不到正确位置。
- **缺陷二（恢复失效）**：一个运行被中途中止后想「恢复」接着跑，结果一恢复就被旧的「中止信号」立刻取消掉，恢复永远失败。
- **缺陷三（编号丢失）**：把工作区参数合并进运行脚本时，一个空值会把已经填好的「任务编号」清掉，导致运行目录错位到默认的 `.agent-runs/task`，多个任务混在一起。

🟢 修好后：工作流运行（尤其带基线的评价类运行）能稳定冻结、稳定恢复、目录各归各位，不会相互串台。
🟡 不修的后果：评价基线运行时能力名存实亡（冻结找不到、恢复起不来、目录错位），下游依赖它的功能会误判或失败。

## 目标
修复运行底座的 3 个缺陷，让「评价基线运行时」及所有使用运行底座的工作流可靠运行。

## 范围
- 只改运行底座 `packages/dsh-visual-workflow/src/host.js` 的三处：
  1. 新增统一函数，规定「运行产物目录」一律按「实际运行目录」解析（技术术语：runArtifactCwd，即：业务含义——运行文件落盘的真正位置）。
  2. 恢复运行时新建一个干净的信号控制器（技术术语：new AbortController，即：业务含义——重新发一个「开始」指令，不复用已被取消的旧指令）。
  3. 合并工作区参数时，只在明确给了任务编号才带上它（避免空值抹掉编号）。
- 改测试 `evaluation-baseline-runtime.test.mjs`：新增 3 个回归用例（EB6/EB7/EB8）覆盖上述修复，并把老测试夹具从「源码目录」改成「实际运行目录」。
- 不碰：登记册对账脚本、执行计划、其他模块。

## 验收标准
1. **EB6**：运行产物按「实际运行目录」解析，契约在那个目录时冻结成功并自动恢复。
2. **EB7**：合并工作区参数后脚本的任务编号仍是原逻辑任务编号（不被抹掉）。
3. **EB8**：恢复运行拿到的是未中止的新信号，恢复段能正常启动。
4. `evaluation-baseline-runtime.test.mjs` 全部用例通过（含 EB1–EB8）。
5. 夜间批次调度器的候选采集测试不回归（本次未触碰该文件）。
