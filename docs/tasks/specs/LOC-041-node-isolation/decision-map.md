# LOC-041 节点隔离决策地图

目标：审核/测试无法改被审成果，但合法测试和报告仍可用。范围：单一参考宿主的强制隔离，不做全平台权限产品。验收：同一真实配置同时通过越权拒绝和合法操作四组 UAT，详见 [V1](task-spec-V1.md)。

原始 WR-018 对宿主能力和支持范围没有固定路径，属 L 型；未确认前禁止整块开工。以下调查提出明确路线，人工接受后才按一个可独立 UAT 的 M 型切片处理。

| 决策工单 | 问题 | 推荐及理由 | 备选与代价 | 状态 |
|---|---|---|---|---|
| ISO-D1 | 首批保证哪个运行环境 | 本机 macOS 的独立 DSH SDK 子进程 Profile；已有公开 cwd/profile/sandbox 接入点可调查 | 所有外部 CLI/Profile：支持矩阵及平台测试显著扩大 | 待确认 |
| ISO-D2 | 不支持时是否仍出独立证明 | 明确 unavailable 并阻断正式独立 Proof；可查看非独立历史结果 | 仅提示“不修改”：无法达到原 AC，故不采纳为等价实现 | 待确认 |
| ISO-D3 | API 不足时是否改 DSH 上游 | 本仓库配置/适配；实际缺口报 BLOCKED，单独定义上游工作 | 本批改上游：新增仓库、版本维护和验收范围 | 待确认 |

依赖顺序：ISO-D1 → ISO-D2/ISO-D3 → [OpenSpec](../../../../specs/node_isolation/proposal.md) → V1 确认。三项可随确认单方案 A 一次接受；没有用户答复不能填写“已关闭”。

调查证据见 [本轮记录](../../p1-definition-evidence-2026-09-15.md)。当前引擎 agent opts 不含节点 cwd；公开 SDK provider 有独立 profile/cwd，但配置加载时解析 cwd，需要由宿主创建/绑定本节点的受控 provider。实际安装版本不同不能假设选项生效。

施工的首个技术验证是：在隔离开发配置中注册一个受控节点 provider，以可写 scratch 为 cwd、候选位于该写根外，验证文件工具和直接 shell 都拒绝候选写入，同时可写报告。还须验证无授权 shell 发布被有效进程/网络策略阻断。不得采用只隐藏工具名或关键词过滤的替代品。

探针失败时输出具体 Profile/API/策略缺口、已观察行为和恢复步骤；用户可决定新增上游需求，但本任务不能为了结束而弱化 AC。真实探针属于施工阶段，本轮仅调查与定义，没有宣称运行成功。
