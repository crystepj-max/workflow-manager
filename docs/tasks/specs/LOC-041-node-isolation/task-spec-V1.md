## 9. 业务规则

1. V1 参考对象为本机 macOS 的独立 DSH SDK 子进程 Profile，使用公开 provider/会话配置和有效文件/进程沙箱；实现仅在本仓库适配和开发 Profile 配置。先探测当前安装 API，禁止把未识别选项塞进 agent() 假装生效；不支持则明确受阻，不升级上游或暗降安全要求。
2. 能力矩阵：dev 读写候选且可自测；review 读候选、写私有证据；test 只读业务候选、写测试覆盖层/缓存/证据；researcher 只读冻结源、写每 item 私有区。closeout 只读候选、写报告，仅持有效授权的受控动作可发布。
3. 候选/冻结源位于节点可写根之外；测试需要构建时在独立派生副本与测试覆盖层运行，记录原候选摘要、覆盖层和构建来源并在结束后验证候选未变。不得因测试需缓存而开放整个原业务目录；新测试不合并为未审业务修改。
4. 宿主必须同时约束文件工具与直接 shell；只过滤工具名无法阻止 shell 写入/联网。无发布授权时不暴露凭据，进程沙箱/网络策略也必须阻止直接发布旁路；不能靠命令字符串黑名单证明隔离。合法授权发布走单独受控动作通道。
5. 保证等级记录 enforced 或 unavailable（附探测与拒绝证据）。不能提供强制边界的 Profile 在正式独立 Proof 前阻断；可查看已有非独立结果，但不得以降级结果满足本条正向验收。
6. 至少一个真实参考配置必须同时通过拒绝越权和合法操作两类探针才算本条实现完成；全部 Profile 报 unavailable 不满足交付。实现中遇上游缺口记录 BLOCKED 和最小 API 缺口，不能把本条改成仅写文档通过。

输入输出和归属：本条拥有 node_capabilities、isolation_guarantee 和探测/执行 adapter；配置通过已有 DSH provider 公开入口注册，在本仓库新增有限适配模块。能力声明传入引擎前必须被宿主落实，后续 LOC-039 只登记真实已支持能力。

## 11. 异常和边界场景

- **实际阻止三类写入**：在声明支持的真实 Profile 准备候选 canary 文件并记录摘要。 处理结果必须为：工具/系统明确拒绝，前后字节相同；仅模型选择不写不算通过。
- **合法测试与证据**：同一参考 Profile 准备可运行的 Node fixture 及独立测试覆盖层。 处理结果必须为：合法操作成功，证据包含原候选和覆盖层摘要，候选未被改写。
- **发布授权边界**：使用受控本地发布探针服务和无授权节点；另设有效授权受控动作。 处理结果必须为：无授权路径均拒绝且无请求副作用；授权通道仅允许指定目标，探针不使用真实凭据。
- **绕过与不支持**：准备 ../路径、外部 symlink、脚本间接写入及未配置沙箱的 Profile。 处理结果必须为：支持 Profile 全部拒绝绕过；不支持 Profile 标 unavailable、不能出正式独立 Proof；至少一配置正向 UAT-01/02/03通过。

共同恢复规则：证据不足写 BLOCKED/UNVERIFIED 并保留失败输入、恢复位置；同一原因重试不改变基线，不因无人值守降低验收。旧 Run 使用冻结快照；范围外变化另行记录，不静默迁移历史。
