## 9. 业务规则

1. 能力索引以具体检查的 main 提交为 Current 基线，每项列状态、适用版本/入口、源码或测试证据。Target 仅引目标规格，Legacy 明确仍支持的读取/恢复路径；本批需求不能因已写规格列为已实现。
2. M2 定义外置、单任务交付与 Portable 旧七阶段差异在一处权威文档解释，其他指南引用该处；保留旧包恢复说明，不用旧包否定当前流程。
3. 生成指南从模板当前节点/边/终态及明确模板说明生成；建设保留人工关口，探索不要求合并，非 Git 优化不要求 PR。指南不得凭阶段名字推测 USER_ACCEPTED 或 DELIVERED。
4. 只修改蓝图/生成器或权威源，重新生成验证；禁止手改 .generated 或已安装全局副本。新增漂移检查应能发现故意改坏生成指南或模板后未重生成，不做只搜固定词的自证测试。

输入输出和归属：输入当前 main 的 templates 与实际生成器/测试；输出文档能力索引及四套生成 Skill/runbook。所有链接仓库相对、可随 clone 迁移。

## 10. 用户操作路径

1. 执行者读取任务卡与本规格，确认 V1 已获批准；记录当前分支/HEAD 并核对相对本轮检查基线的变化。
2. 使用本任务独立环境，按已有单任务工作流开工；没有业务硬前置。
3. 按 §7–9 实现本条完整能力，以 §16 的固定场景验证成功和失败路径。
4. 呈递逐项 AC、实际证据、候选版本与限制，到人工验收关口等待；不代签或自行进入发布。

## 11. 异常和边界场景

- **找到真实入口**：准备新接手者，给出能力索引，不提供本次对话。 处理结果必须为：能区分已实现/目标/历史，每项有可打开证据与基线，不误把需求当上线。
- **四模板逐项核对**：生成全部四模板指南。 处理结果必须为：探索不要求 merge，非 Git 优化不要求 PR，建设没有跳过人工门。
- **兼容说明单源**：准备 M2 新任务和旧 Portable Run 两个阅读场景。 处理结果必须为：新旧路径清晰，七阶段没有被称为当前 M2 主链。
- **验证可迁移及漂移**：在临时 checkout 生成产物并复制可移植文档。 处理结果必须为：链接不依赖作者绝对目录，检查能报漂移，重新生成恢复一致。

共同恢复规则：证据不足写 BLOCKED/UNVERIFIED 并保留失败输入、恢复位置；同一原因重试不改变基线，不因无人值守降低验收。旧 Run 使用冻结快照；范围外变化另行记录，不静默迁移历史。

启动前读取当前仓库 AGENTS.md、单任务 runbook 和环境登记；Node.js 24，首次缺依赖时 npm install。建设 Run 的 DSH 资源按当前环境分配器实际记录使用；本批按 D-BATCH 确认采用当前 runbook 的共享宿主/独立 Run 命名空间，与现行 AGENTS 的唯一开发实例 9527 约定一致。此前不操作 DSH；不复制旧任务 Home、不重启其他 Run 的 DSH。每任务 namespace/cache 与资源记录独立；开发 DSH 固定端口共享且同时只有一个活跃插件。执行前检查槽位；其他任务活跃时等待或受阻，不调用会抢占重启的 start。候选默认并发 1，凭据只引用已配置 Profile，不自动复制。

当前批量工具只接纳无依赖任务；本任务确认后可作为独立候选，仍需执行时重新做资格/环境检查。 本轮不创建 Run 或开发环境。
