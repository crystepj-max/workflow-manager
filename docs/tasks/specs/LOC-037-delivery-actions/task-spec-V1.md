## 9. 业务规则

1. 事实整理是只读候选阶段，报告列候选版本、证明、人工决定和未完成项。发现必须改候选时退回修改及重新证明，不在 closeout 偷改。非 Git 默认 required_actions=[]，可完成纯本地交付。
2. 动作计划字段 required_actions、optional_actions、authorization_ref、target_adapter、target_ref、candidate_ref；由已批准交付范围及仓库配置确定。每个动作执行前验证授权对象、范围、版本与目标匹配，有效授权复用。缺必要授权保留报告并等待，不重复整理或索要已有授权。
3. V1 支持 local/no-op 和 CNB 动作路径（推送沿用仓库既有封装脚本与凭据配置，不自行拼装参数）；选择默认推送目标必须先读 remote.pushDefault/分支上游及显式目标，不固定 origin。目标 GitHub 或未知适配器时 capability_unavailable，不回退发布到 CNB。GitHub 适配在账号暂停问题解决后单独定义。
4. 执行调用 LOC-032 的 operation ledger execute-or-reconcile。必要动作失败/结果不确定时不能 DELIVERED；不确定先回读对账，不盲目重试。成功必须有远端对象和候选版本回读证据。
5. 可选清理失败只记录 cleanup_pending，交付事实不倒退。待保全脏改动、其他活跃 Run、同组未完成成员禁止回收；共享开发 DSH 仅回收本 Run namespace/resource，不停止整个共享宿主。
6. 各目标平台既有政策不被新动作接口绕过：CNB 合并请求遵守仓库合并规则与既有授权要求；GitHub 适配恢复后同样遵守 Controller Review Gate、人工验收和发布授权政策。

输入输出和归属：消费 LOC-032 的 operation_key、授权范围、pending/succeeded/failed/unknown 与外部结果引用；输出 delivery_report、逐动作状态、cleanup_pending。新动作规划归本条，重复执行保障归 LOC-032。

## 11. 异常和边界场景

- **非 Git 本地交付**：准备非 Git 文档目录，required_actions 为空且事实报告齐全。 处理结果必须为：可交付，Git/PR 调用为零，报告包含正确候选和限制。
- **授权及远端回读**：在隔离的 CNB 测试仓库或受控 API 替身，准备有效/缺失授权两组动作。 处理结果必须为：有效授权不重问且有回读；缺失组已有报告但未执行必要动作。真实远端未授权时该层证据标 UNVERIFIED。
- **失败分类与目标**：准备必要 merge 失败、可选清理失败、目标 GitHub 三种场景。 处理结果必须为：必要失败不是 DELIVERED；仅可选失败可交付并列残留；GitHub 报能力缺失且不调用 CNB。
- **成果和资源保全**：记录候选摘要；准备含未提交改动的工作区及同组活跃成员。 处理结果必须为：候选未改，脏改动/活跃成员未删除，其他 Run 和共享 DSH 保持可用。

共同恢复规则：证据不足写 BLOCKED/UNVERIFIED 并保留失败输入、恢复位置；同一原因重试不改变基线，不因无人值守降低验收。旧 Run 使用冻结快照；范围外变化另行记录，不静默迁移历史。
