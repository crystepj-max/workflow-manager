共同根因：**登记册是投影，git 历史才是事实**——两者靠人肉同步。

## 2. 任务目标

合并后账自动对上、并发写互不覆盖、调度判定不被账本滞后误导。

## 3. 涉及范围

- **做**：
  1. 新增对账脚本 `scripts/registry-reconcile.mjs`（plan / apply）：扫描主干合并痕迹（提交信息尾部任务号 + 收口标签 `task/<id>/v*`），对「git 有合并事实、登记册未记合并」的条目自动回写为已合并（含合并提交与时间）；反向差异（账本记了合并、git 无痕迹）只报告不自动改；
  2. 登记册加乐观锁：顶层 `revision` 字段，写回前校验「读入后磁盘没被别人改过」，不一致拒绝并指引先同步再对账；
  3. 执行计划依赖判定改看事实：依赖任务在登记册已合并，**或**主干有合并痕迹，即视为满足；仍不满足才排除并说明。旧的「有依赖一律排除」废止。
- **不做**：远端实时推送（CNB 无现成事件能力）；登记册迁远端（违背本地轨道离线可用）；改验收三态、返工上限等纪律。

## 4. 实现说明

| 层 | 载体 | 挂载点 |
|---|---|---|
| ① 对账 | `scripts/registry-reconcile.mjs`（plan / apply） | 夜间批次开头；日常校验；发现账实不符时手工执行 |
| ② 版本锁 | `scripts/local-task-registry.mjs` 的 load/save | 所有登记册写路径自动生效（revision 递增） |
| ③ 依赖判定 | `scripts/ai-task-execution-plan.mjs` 的 assessCandidate | 每次批次构建自动生效 |
| ④ 批次前对账 | `scripts/ai-task-scheduled-trigger.mjs` 唤起执行计划前 | 每次夜间批次自动生效；对账结果写入批次报告抬头，失败不阻塞 |

## 5. 验收标准

| # | 验收项 | 判定方式 |
|---|---|---|
| 1 | 对账推导正确：提交信息尾部任务号与收口标签均被识别为合并事实 | 单测 5 用例（含标签、无任务号提交不误判） |
| 2 | 并发写保护：两会话同时读写，后写者被拒且指引明确 | 单测（旧视图写回抛错，重读后可写） |
| 3 | 依赖判定：依赖已完成不再被一律排除；依赖未完成仍排除且说明 | M3 机械验收更新后通过 |
