## 9. 业务规则

1. 以 Run 为 trace、节点与 attempt 为关联单元；事件包含稳定 attempt_id、节点/轮次、开始结束时间、状态、实际模型、成果/证明引用及 retry_kind。业务返工、技术重试和普通调用分开计数；缺原因写 unknown。
2. 原始时间保留 UTC，单 attempt 耗时以可靠开始/结束差计算；Run 自动墙钟时间对并行区间求并集，累计调用时间可求和但单独命名。人工等待区间独立列出，不双算进自动墙钟；未结束/崩溃无结束事件时为 partial，不能虚构耗时。
3. usage 只采用 provider 实值并记来源，缺失为 unavailable 不是0；成本需要用量与对应模型价格共同存在，价格包含来源、版本/生效时间、币种。缺一则该成本不可用，已知部分合计必须标 partial，禁止换算未配置汇率。
4. 重放按稳定事件/attempt 身份去重；同 attempt 状态更新不新增调用次数。聚合可从原始记录重建，崩溃恢复不得重复累计。采用 LOC-029 实际提交时序，不从最后节点结果推测历史调用。
5. 质量仅关联显式 review/test/human decision、候选和 Proof 版本；通过率明确分母和样本，未知/未执行单列。模型评价不能代替人工接受；缺 P0 新字段明确 unavailable，不新增业务硬前置。
6. 导出默认仅允许列出的元数据与引用，不存提示全文、正文、凭据、请求头或含密钥 URL。报告具备四模板对比，但无样本模板写无数据，不推断哪种模板更好。

输入输出和归属：消费 LOC-029 的 attempt 事件及版本引用，provider 可得 usage 和显式价格配置；输出可重建的 metrics JSON、摘要与界面链接。LOC-031 的预算事件若可用直接关联，不可用不猜测、不改其预算政策。

## 11. 异常和边界场景

- **八次调用完整展示**：固定优化样例共8次实际调用，含一次技术重试、一次业务返工及人工等待区间。 处理结果必须为：8条调用，分类可追溯，自动和等待分列，并行时间未重复算为墙钟。
- **缺数据与恢复**：准备缺 usage、缺 price、cancel、崩溃未结束及重复重放事件。 处理结果必须为：缺值 unavailable，未结束 partial，已知部分标部分合计；重放不增加调用或成本。
- **质量与隐私**：准备明确人工决定/测试证明及敏感提示标记。 处理结果必须为：决定关联真实候选版本，非人工状态不误报接受，敏感标记/凭据/提示全文未导出。
- **四模板对比**：四模板各一份可复核记录，另设无样本/部分用量记录。 处理结果必须为：调用、时间、等待、质量和已知成本一致；无数据和样本不足显式呈现，不得排名冒充统计结论。

共同恢复规则：证据不足写 BLOCKED/UNVERIFIED 并保留失败输入、恢复位置；同一原因重试不改变基线，不因无人值守降低验收。旧 Run 使用冻结快照；范围外变化另行记录，不静默迁移历史。
