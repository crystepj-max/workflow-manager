## 9. 业务规则

1. runPreflight 保持资格判定唯一入口，Bootstrap、正式 wf_run 和测试包装使用同一组经过路径解析的任务卡、V1 规格、登记册/环境事实。字段语义不由模型重新解释。
2. 状态必须已定义/本地已定义、无人值守允许、卡片/规格/Run 基线一致、Definition Check 确实通过且未决为 0；必须按勾选结果读取，不允许未勾选的“全部通过”文字或只写标题就放行。
3. 依赖不是一律必须无：同组从真实环境记录验证完成；跨组从登记册合入提交及当前候选祖先关系验证。依赖已定义、交付中、等待验收或只有本地未合入提交均不可当作满足；缺状态载具也不可省略检查。
4. 公共接口可增加兼容原因码/事实来源；同样输入各入口原因码与拒绝对象一致。envStore 等上下文由入口可靠解析，正式入口缺上下文失败，不通过省略参数绕过。检查只读，资源创建在资格通过后的原交付流程进行。
5. 机械通过可生成 preflight PASS 记录接续开发；失败任何模型 PASS 均无效。模型路由与服务可用性保留独立探测及失败码，不把断网误报需求不合格。

输入输出和归属：保留 runPreflight(issuePath,specPath,opts) 的兼容形态，增加必要只读上下文解析及 reasons[{code,field,source,message}]；已有 failures 文本保留。输入 GitHub 同步卡/本地任务卡等价，输出机械资格事实供三入口消费。

## 11. 异常和边界场景

- **三入口一致**：准备合法本地已定义任务、等价 GitHub 卡和已完成同组成员三种夹具。 处理结果必须为：三入口均通过且原因结构一致；无需额外模型资格调用。
- **逐种拒绝**：准备未完成依赖、跨组提交未合入、V1/V2冲突、缺许可、未勾选检查五组。 处理结果必须为：都明确拒绝同一原因，dev 调用为零，缺上下文亦不放行。
- **模型不能覆盖**：对机械失败输入注入 evaluator PASS；对合法输入禁止资格模型调用。 处理结果必须为：失败不被覆盖；合法任务直接接续专业开发阶段。
- **服务与资格分离**：任务资格合法但模型连接失败，另设模型可用但资格失败。 处理结果必须为：分别报告服务就绪和资格原因；未创建多余工作区，不移除现有连通性探测。

共同恢复规则：证据不足写 BLOCKED/UNVERIFIED 并保留失败输入、恢复位置；同一原因重试不改变基线，不因无人值守降低验收。旧 Run 使用冻结快照；范围外变化另行记录，不静默迁移历史。
