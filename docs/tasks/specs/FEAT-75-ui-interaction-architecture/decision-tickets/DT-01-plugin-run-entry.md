# DT-01 · 插件是否新增运行入口（产品决断票）

| 项 | 值 |
|---|---|
| 类型 | 决策票（产品决断，含一项技术探路） |
| 状态 | **open**（🔴 先决：`DT-00` —— 若 #75 被裁定关票，本票的归属随之转移） |

| 不阻塞 | S-0（权威落库）、S-2、S-3、S-4——四片与入口选择无关，可先行推进基线 |

## 1. 必须决定什么

用户在插件界面里选中一个工作流之后，**能不能在界面内把它跑起来**；如果只能回 Chat 起跑，界面就永远是"看与改"的地方，不是"用"的地方。

三选一是 #75 §3 原文的 A/B/C：A＝Chat/Skill 仍是唯一正式入口；B＝插件"使用此工作流"只负责打开/创建会话并携带 Skill；C＝插件直接创建 Logical Run，但仍调统一 Invocation。

## 2. 为什么必须现在决定

- **事实基础已被本轮复核改写**：#75 正文写"插件侧无运行入口"，实际运行能力**早已存在**，只是形态是 Chat 侧工具 `wf_run`（`src/host.js:3075`，起跑 `:3456`），而浏览器 UI 无入口（`src/client.js:5194-5198`）。所以本题不是"要不要有 Runtime"，而是"要不要给这个 Runtime 加一个界面按钮"。
- **LOC-015（GitHub #83）已经裁过一次相邻问题**：发起权归插件、"结果回灌"方案不采纳、内置 `workflow` 工具降为应急回退。裁的是**发起权归属**，不是**界面入口**。选 B 会让当年被否的回灌思路以界面形态重新上桌，需要产品经理明确是否接受这个反转。
- #75 若不定这一条，就永远无法宣布"产品信息架构与交互定稿完成"，而它又决定 S-1 是否存在。
- 红线：任一选择都不得产生第二套运行状态机或两份运行历史（P8 + #75 §3 禁令 + 架构文档 §3）。

## 3. 候选方案

**方案 A · Chat/Skill 保持唯一正式入口，插件不加运行按钮（推荐）**
- 成本：零。不改 UI、不占载荷（现值 289230B/290816B，余量约 1.6KB），不新增宿主 RPC。
- 收益：与当前已验收形态完全一致（LOC-015 真机 UAT 已通）；零回退风险；把 S-1 从 #75 派工面移除，#75 可专注已确定的净新增缺口（S-3/S-4/S-2）。
- 风险：用户必须知道触发词或去 Chat 发起；"编辑器里改完却跑不了"的体验落差继续存在；#75 §3 的定稿结论会写成"暂不做"，需要在文档里明确这是决定而非遗漏。

**方案 B · 插件按钮只唤起会话并携带 Skill**
- 成本：中，且**含一项未取证的技术前提**——插件浏览器侧与宿主之间只有 RPC（`vwf.*`）、宿主事件订阅、进程内 MCP 工具三类通道，本轮未找到"从插件打开 Chat 会话并注入 Skill"的公开能力。需先探路（探路清单见 §4）。
- 收益：入口可见性大幅提升，执行归属语义不变（仍由 agent 发起），天然满足"不得有第二套 Runtime"。
- 风险：若通道不存在则退化为 LOC-016 C1 同型阻塞（"界面发起、会话执行"需要有人在场）；且与 LOC-015 已否决的回灌思路部分重合，存在口径反复。

**方案 C · 插件直接创建 Logical Run（走统一 Invocation）**
- 成本：高。需要新的宿主执行通道（浏览器 RPC 无发起 agent，见 LOC-016 DT-01 §2 取证）、新的运行参数装配界面、载荷预算突破（几乎必然要配套瘦身专项）。#83 设想的独立 `Invocation Adapter` 分层在 `src/` 零命中，等于还要先补一层架构。
- 收益：一屏闭环，看板/编辑器/运行统一在一个产品面。
- 风险：**最高**——最容易长成第二套运行状态与历史，直接顶到 P8 与 §3 禁令；且与 LOC-015 已裁定的"发起权在 agent 侧"冲突，需要同时推翻两张票的结论。FEAT-208 正在裁定的"UI 续跑归属"若先落地，可能把这条路自然铺平——顺序上值得等它一程。

## 4. 探路清单（若倾向 B 或 C，先做再裁）

1. 宿主是否暴露"打开会话 / 携带 Skill 发起"的公开能力？取证点：`src/host.js` 的 `ctx` 面与 `registerRpc` 全集、DSH 插件 API 文档。
2. 若走 C：浏览器 RPC 取得 engine 的可行路径（`resolveEngine()` 现有降级链能否绕开 initiator）。
3. 任一方案对载荷预算的实际增量（估 KB，超线则先瘦身）。

## 5. 关闭判据

产品经理在 A/B/C 中择一，并写明：是否接受"插件内无运行入口"作为 v0.1 定稿结论。选 B/C 时须同时批准探路清单与随之而来的瘦身/架构工作量。

## 6. 产物

- 结论回写 `docs/design/workflow-ui-interaction-architecture.md` §3（当前写的是"待 DT-01"占位）；
- 选 A：本票关闭即取消切片 S-1，并在 #75 §3 对应完成标准标注"裁定为不做"；
- 选 B/C：另立 S-1 施工卡基线（含探路结论），并追加一张架构分层票补 `Invocation Adapter` 的归属定义。
