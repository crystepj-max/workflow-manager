# DT-01 · 命令命名空间是否从 `/codex-review` 改名

**性质**：产品选择，本任务书明令 Agent 不得自行决定。已按**选项 (a) 不改名**实现，可回退。

## 背景

受控入口命令为 `/codex-review next|retry|extend`，命名先于 Codex→Bugbot 切换而定。引擎已换 Cursor，命令名里的 "codex" 成为历史包袱。是否改名影响：在途 PR 已发的旧命令、各执行器（DSH/Cursor/Codex）脚本与文档里的命令字面量、`AGENTS.md` 与 workflow `if: startsWith(...)` 匹配。

## 选项

| 选项 | 内容 | 收益 | 代价 / 风险 |
|---|---|---|---|
| **(a) 不改名**（当前实现） | 命令仍 `/codex-review`，仅在 `AGENTS.md` 加注「历史命名，先于切引擎」 | 改动最小、零断链、Agent 习惯与在途 PR 不破 | 名字与 Cursor 引擎语义不符，对新 Agent 有轻微误导 |
| (b) 直接改名 `/pr-review` | 一次改净，同步 `AGENTS.md` / workflow `if:` / 测试 | 语义干净 | **在途 PR 里 `/codex-review` 立即失效**（须公告 + 空窗）；跨执行器文档需全量替换 |
| (c) 改名 + 旧命令废弃兼容 | 新旧同时接受，旧命令走废弃期 | 迁移平滑、不断链 | 两套入口并存，与「唯一受控入口」初衷相左，需维护别名解析与下线时点 |

## 推荐

**默认维持 (a)**，待本卡验收/发布后另起一个「择机改名」的独立小卡处理 (b) 或 (c)，避免把引擎切换与命令迁移两件事混进一次变更。若产品偏好一次到位 (b)，需接受在途 PR 命令失效的公告成本；若担心断链选 (c)，但要为"兼容期结束"设明确下线条件。

## 裁定（已落）

- **选择：B · 改名为 `/pr-review`，旧命令 `/codex-review` 即刻失效、无兼容期。**
- 执行：本任务后续 PR（DT-01=B 落地）已改 `parseCommand`、workflow `if:` 前缀、AGENTS.md、`.cursor/BUGBOT.md`、测试；内部审计标记与文件名保留旧名（非用户可见）。
- 裁定人：产品（会话明确指示 "B"）／ 时间：2026-09-20
