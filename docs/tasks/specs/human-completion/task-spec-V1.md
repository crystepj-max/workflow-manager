## 9. 业务规则

- 优化：evaluate PASS 路径仅可形成 EVALUATION_PASSED；经当前人工等待点 ACCEPT 才可形成 USER_ACCEPTED。后者必须引用本 Run、本决定点及当前 candidate_ref 的有效人工记录，且记录产生在成果冻结之后。
- 建设保持 ACCEPT/REJECT/CONDITIONAL_PASS：REJECT 回开发；CONDITIONAL_PASS 只记录下一轮优化输入，不表示接受本轮未达标成果。禁止通用 USER_ACCEPTED 快捷路径覆盖建设三态或跳过应有收口。
- 人工记录只能由宿主人工交互入口形成，模型结果、评论文本或伪造 actor 字段不能创建同等授权。重复提交同一个决定 ID 应幂等，互相冲突的第二次决定拒绝并保留审计。

**接手者可直接采用的实现边界：**复用宿主已有人工决定入口与 Logical Run 恢复机制，在接受决定时附加 WR-003 candidate_ref；在完成转换前核对 Run、决定点、身份来源及候选。关闭建设通用 USER_ACCEPTED 快捷结束旁路。

**接口与数据约定：**decision_ref 包含 decision_id、logical_run_id、checkpoint_id、candidate_ref、choice、actor_source、decided_at。只能从宿主真实人工交互生成 actor_source；模型字段不构成来源证明。已有有效决定与候选不变时恢复复用；候选变化后不得自动沿用。

消费 WR-003 的 candidate_ref；本条拥有 Decision 与 candidate_ref 的关联验证及 completion 派生规则。WR-009 只将已核验完成语义映射到生命周期。

**兼容方式：**新运行使用本条新规则；已启动运行保持其冻结快照。无法补证的旧历史明确 legacy/unverified，不改写成已验证完成。若其他 P0 已合入，复用其公共接口并运行集成检查；没有硬依赖的条目允许通过既有接口完成自身切片，不能自行等待整个需求包。

- 前置条件：保存一个旧快照与一个新规则 Run 的中间状态；仅在隔离环境制造中断。

- 预期结果：旧快照不静默迁移；新运行不丢有效成果、不伪造历史证明；本条涉及的非法条件仍被拦截。
