# VWF 动态载荷瘦身专项（回到 272KiB 以内）

## 1. 背景与目标

六批快速迭代 + CNB 同步累计后，集成态动态载荷达 **291348B**（host 116787 + client 174561），超 272KiB 上限（278528B）**12820B**。本任务通过**真实代码级整合**把载荷压回 272KiB 以内，使上限常量恢复 272KiB 且闸门正大光明通过。这是 FEAT-105/107 部署的前置任务。

**硬目标：host + client ≤ 278528B（272KiB），达标后把 build-bundle.mjs 与 tests/static-bundle.test.mjs 的常量从 284KiB 改回 272KiB 并使闸门通过。**

## 2. 瘦身手段（按优先级）

1. **重复逻辑合并**：84/85/86/100~103 六批各自实现的相近 helper（状态映射、日期格式化、弹窗骨架、列表渲染等）合并为单一实现。
2. **死代码清理**：被整合取代的旧渲染路径、不再被引用的样式选择器与分支（FEAT-103 整合后底部节点/结果区域、独立 Formal Artifacts 区块等旧路径应已无引用）。
3. **重复文案/样式归并**：locales 中同义重复键、CSS 中可合并的选择器组。
4. **压缩表述**：过长的注释压缩排版（不影响语义与证据记录的关键内容）。

禁止手段：删除/弱化任何仍有引用的能力代码；改变用户可见行为；上调预算常量来「达标」。

## 3. 零回退约束（硬门禁）

- 全部既有测试修订后必须通过：仓库根 npm test（681 基线）；插件 npm test（371 基线，W1/W3/W8/W10/W11 五个引擎层失败 + EB4 偶发为基线已知）。
- FEAT-84 V-1~V-13、FEAT-85 列表/详情行为、FEAT-86 角色语义、FEAT-100/101/102/103 各验收项的**行为**逐一保持（呈现像素级微差可接受，交互与信息完整性不可变）。
- token 集成口径（DT-02）：角色/主题域零 alias；编排台/运行详情域 alias 不增长。
- 不改 RPC、数据契约、执行语义。
