# 决策票 DT-01 · FEAT-77 每任务执行模型

- **状态**：已裁定（closed）
- **提出时间**：2026-09-17（回顾性固化）
- **提出方**：需求分析

## 背景

夜间批次要把一批待办在夜窗内施工。执行模型决定"调度"与"施工"如何分配，直接关联故障隔离与跨工具一致性。

## 待决选项

| 选项 | 描述 | 结论 |
|---|---|---|
| A. 每任务独立 CLI 会话（**选定**） | 调度器为每个任务 spawn 独立 AI CLI 会话，渲染专属提示词 | **采纳** |
| B. 单会话 + subagent | 维持旧形态，会话内每任务经 subagent | 否决：不解决规则漂移与单会话雪崩 |
| C. 单会话串行 | 同会话逐任务施工 | 否决：无并发、无隔离，夜窗时长不足 |

## 裁定

**采纳 A**。理由：
1. 故障隔离彻底——单任务会话崩溃只影响自身，名额释放后补位，整批不雪崩；
2. 上下文小——每会话只装一个任务的简报，不随批次膨胀；
3. 跨工具一致——行为边界固化在渲染后的 `session-prompt.md`，ZCode/Codex/DSH 同一份；
4. 调度与施工分离——调度器只编排（确定性脚本），AI 只做单任务施工。

## 后续动作

- 调度器并发上限由 `schedule.maxConcurrency` 控制，默认 3，需结合夜窗机器资源设定；
- 会话结束契约 `release-event.json` 三态为硬契约，调度器据此聚合报告，不得在会话内自行判定"完成"绕过人工验收。
