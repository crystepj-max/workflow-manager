## 1. 需求背景

开发 DSH 的「每任务一个独占运行空间」机制（#185）已由 LOC-020 判定退役。该机制留下的运行态数据没有回收干净：分配的独占 Home 目录从未被使用却仍留在盘上；一批已终止的 UAT / 探针工作区记录仍在；工作区登记册里的条目全部指向已经不存在的目录。

## 2. 用户问题

一句话：**运行目录里留着已经作废的东西，而且登记册说的和盘上实际有的对不上**——以后回头看会误判哪些工作区还活着、哪些机制还在生效。

## 3. 目标

开发侧运行目录（`~/.dsh-workflow-dev`）内不再存在已作废的机制遗留物与指向空实体的登记条目；并留下一份可核对的清理报告，说明清了什么、为什么没清某些项。

## 4. 非目标

- 不释放空间（对象合计约 100 KB，不构成动机）。
- 不动产品侧 `~/.dsh/workspaces/`。
- 不动 `.agent-runs/` 证据明细（另有机制与门控）。
- 不动 `visual-workflow/` 下的运行数据。
- 不做 LOC-020 的机制改造。

## 5. 修改前

- `~/.dsh-workflow-dev/tasks/loc-014-r1/`：一个只有归属标记文件的空目录（#185 遗留）。
- `~/.dsh-workflow-dev/workspaces/records/`：12 条已终止 UAT / 探针记录。
- `~/.dsh-workflow-dev/workspaces/.vwf-registry/state.json`：11 条登记，`workspace_path` **全部不存在**，`records_path` 仍存在 → 登记册与实体不一致。
- 产品侧 `~/.dsh/workspaces/`：8 条记录 + 7 条登记（含运行中 / 暂停），本次不处置。

## 6. 修改后

- 开发侧独占 Home 遗留目录已清（或经确认保留并写明）。
- 开发侧工作区记录已清（或经确认保留并写明）。
- `state.json` 内不再有指向已消失目录的条目；保留项有明确理由。
- 产品侧、证据目录、运行数据目录均零改动（前后校验一致）。
- 一份清理报告落盘，含盘点清单、前后条目数对比、不可删除项及原因。

## 7. 功能范围

1. 只读盘点（定义阶段已完成，见 §12）——执行阶段需重跑一次以获取最新状态。
2. 输出待清清单并向人工呈递确认。
3. 人工逐项确认后执行删除（优先走系统回收站/可恢复方式）。
4. 收敛 `state.json` 登记条目。
5. 输出清理报告。

## 8. 不修改范围

- `~/.dsh/**`（产品侧全部）
- `<仓库>/.agent-runs/**`
- `~/.dsh-workflow-dev/visual-workflow/**`
- 任何代码、蓝图、生成产物、脚本行为

## 9. 业务规则

- **先盘点、后确认、再删除**：未获人工逐项确认的对象一律不动。
- 删除优先走系统回收站；无可用回收站时须二次确认。
- 实例正在运行时不得清理其正在使用的记录。
- 以**实体**为准收敛登记册，不反向重建目录。
- 删除失败（锁文件 / 权限 / 被引用）必须如实写入报告，不得静默跳过或谎报。
- 清理前后必须能核对：条目数、目录数、体量。

## 10. 用户操作路径

1. 执行只读盘点命令 → 得到当前待清清单。
2. 逐项确认清单（可整体确认或逐条取舍）。
3. 确认后执行删除与登记册收敛。
4. 阅读清理报告，核对「清了什么 / 没清什么 / 为什么」。

## 11. 异常和边界场景

| 场景 | 处置 |
|---|---|
| 登记册条目指向的实体已消失（当前即是） | 以实体为准移除条目 |
| `WAITING_HUMAN` 条目 | 先确认有无未完成人工门；有则保留并写明 |
| 开发 DSH 实例在运行 | 跳过其实例正在使用的记录，或先停实例 |
| 删除 / 改名失败（本机已知锁文件与权限异常） | 如实上报，不重试绕过、不静默跳过 |
| 待清对象被其他 Run 引用 | 停止该项并上报 |

## 16. UAT 场景

### UAT-01 盘点清单可核对

- 验收目的：确认清单与实际盘上情况一致，人工能据此决策。
- 前置条件：
  1. 开发侧运行目录保持现状。
- 操作步骤：
  1. 执行只读盘点。
  2. 随机抽 3 项到磁盘上人工核对（路径是否存在、内容是否如描述）。
- 预期结果：
  1. 清单列出全部待清项，含路径 / 体量 / 归属 / 建议处置。
  2. 抽查项与清单描述一致，无遗漏、无虚构。
- 建议人工关注：清单里是否出现"看不懂为什么要清"的项。

### UAT-02 确认后才删除，且边界零改动

- 验收目的：确认不可逆操作有门控、且不误伤边界外对象。
- 前置条件：
  1. 已记录清理前：开发侧条目数 / 目录数 / 体量、产品侧同项快照。
- 操作步骤：
  1. 在未确认状态下尝试执行删除 → 应被拒绝。
  2. 确认后执行清理。
  3. 对比前后快照。
- 预期结果：
  1. 未确认时不动任何对象。
  2. 清理后开发侧待清项已消失。
  3. 产品侧 `~/.dsh/workspaces/`、`.agent-runs/`、`visual-workflow/` 三项快照与清理前逐字节一致。
- 建议人工关注：产品侧是否被动过（这是本任务最需要防的误伤）。

## 17. 风险

- 🔴 **不可逆删除**。缓解：只读盘点 → 清单 → 人工确认 → 回收站优先 → 报告留痕。
- 🟡 **实例在跑时清理影响运行态**。缓解：先停实例或跳过相关条目。
- 🟡 **本机已知锁文件 / 权限异常导致删除失败**。缓解：如实上报、不绕过。
- 🟡 **范围误伤产品侧**。缓解：明确列为 UAT 校验项，做前后快照比对。

## 18. 已知限制

- 登记册收敛只处理开发侧；产品侧 7 条（含 RUNNING / PAUSED）继续保留，未来是否收敛另议。
- `visual-workflow/` 下的运行数据是否含残留未核实，本任务不覆盖。
- 清理结果不影响任何功能，纯数据整理。
