## 9. 业务规则

1. 首轮 BROAD 默认 3–5 名 expert_id 唯一的专家，每项 focus、brief 非空并关联至少一个 question_id；必需问题清单非空且 ID 唯一。对去首尾空白、折叠连续空白后的 focus+brief 完全相同项拒绝，不以模型判定语义相似。3 为下限、保证探索研究下限，5 为上限、控制预算；两者是默认边界而非硬拒绝。
2. 计划或首轮分析判断所需专家数低于 3 或高于 5 时，不自动拒绝也不自动放行：宿主暂停该轮并生成人工决策卡，写明判断的实际人数、理由、成本影响与可选动作；人工决定按批准人数放行（记录例外与批准人）或退回修改计划。未获人工决定前不启动任何专家。重复 ID、空任务、完全相同任务等质量违规仍直接拒绝，不提供人工放行通道。
3. 补充 TARGETED 为 1–5 名，每项有非空 research_targets，目标必须映射当前 open_gaps 的已知 question_id。NEEDS_RESEARCH 必须给出可执行缺口及目标；次数仍最多两次，不新增第三次调用。
4. 综合必须接收每项成功/失败、证据 ref、未覆盖问题和来源重合信息。必需问题只有带可读证据的回答或有证据支撑的未知/不可得结论才算已处理；纯缺报告不能算未知已覆盖。全失败不能生成成功研究结论。
5. PASS 仅对应 EVALUATION_PASSED；INSUFFICIENT 对应 INSUFFICIENT。补充额度耗尽仍 NEEDS_RESEARCH 时，保留评估原裁决并由宿主生成 effective_verdict=INSUFFICIENT、system_completion=INSUFFICIENT、budget_exhausted 原因及缺口清单；有效终态二者必须一致，原始 evaluator_decision 独立留存，不伪造评估者主动通过/放弃，也不自动追加研究。
6. 历史结论与来源可保留，综合声明它实际使用的轮次；只有相关缺口允许触发补充。专业判断仍由评估者给出，机械层只校验人数、映射、必需覆盖字段和裁决一致性。

输入输出和归属：plan 输出 questions[{id,required}]、expert_briefs[{expert_id,focus,brief,question_ids,research_targets}]；research 保留现有 fanout success/failure 项；synthesis 输出 coverage[{question_id,status,evidence_refs,reason}]、source_overlaps、open_gaps；终评携带与覆盖一致的裁决。结构字段为本任务 V1 提议，兼容读取旧 Run 冻结脚本。

## 11. 异常和边界场景

- **首轮有效任务**：准备专家数 0/2/6、重复 ID、空 brief、完全相同任务和合法 3/5 人七类计划。 处理结果必须为：人数低于 3 或高于 5（含 0/2/6）在专家启动前暂停并生成人工决策卡（含实际人数、理由与可选动作），不自动拒绝或放行；重复 ID、空 brief、完全相同任务直接拒绝；合法 3/5 人按各自任务运行。
- **一个缺口一个专家**：首轮保留一个 question_id 对应缺口。 处理结果必须为：前者仅启动 1 人，后者不进入补充调用且说明缺口。
- **部分与全部失败**：三专家中一人失败且其问题必需；另准备三人全失败。 处理结果必须为：失败和未覆盖可见，未覆盖必需问题禁止 PASS，全失败无伪成功证据。
- **耗尽与裁决追溯**：设置两次补充均无足够证据的固定结果序列。 处理结果必须为：最多两次补充，系统 INSUFFICIENT，原 NEEDS_RESEARCH 未被篡改，无额外模型调用。

共同恢复规则：证据不足写 BLOCKED/UNVERIFIED 并保留失败输入、恢复位置；同一原因重试不改变基线，不因无人值守降低验收。旧 Run 使用冻结快照；范围外变化另行记录，不静默迁移历史。
