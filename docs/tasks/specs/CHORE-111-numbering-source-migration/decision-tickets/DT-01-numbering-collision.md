## 背景（为什么必须决定）

发号源迁到 GitHub 后，`<TYPE>-<号>` 的号来自 GitHub issue 编号。但 GitHub 侧**号段已被占用**：

| GitHub 号 | 标题 | 状态 | 与本地任务的关系 |
|---|---|---|---|
| #106 | `docs: v0.1 DSH / Cursor / Codex 并行开发计划与 Issue 调度基线` | CLOSED | 真实历史 issue，**不可动** |
| #108 | `[Accidental / Closed] temporary branch marker` | CLOSED | 占位，无实际内容 |
| #109 | `[Accidental / Closed] do not use` | CLOSED | 占位，**与本地 `FIX-109`（cnb#109）撞号** |
| #110 | `[Accidental / Closed] branch tool typo` | CLOSED | 占位，**与本地 `CHORE-110`（cnb#110）撞号** |

关键约束：**GitHub issue 编号不可回收**——删除 issue 后该编号也不会被复用，全局单调递增。因此「删掉占位号腾出来」这条路不存在。

要决定的核心问题是：**这些历史占位号与本地已发布号之间怎么对齐？**

## 方案

| 方案 | 做法 | 成本 | 收益 | 风险 |
|---|---|---|---|---|
| **A · 复用占位号对齐（推荐）** | 把 GitHub #109/#110 **重命名并重开**，标题改为 `FIX-109`/`CHORE-110` 的真实任务名，作为这两个任务的正式 GitHub issue；此后新任务号从 GitHub 当前最大号 +1 起（约 #205+） | 极低——两条 `gh issue edit` + `gh issue reopen` | 消除**唯一两处实际撞号**；活跃任务立刻有 GitHub 锚点；无号段浪费 | 占位号留有 `[Accidental]` 的创建历史与 reopen 事件；#109/#110 的创建时间早于任务本身（不影响使用，需在 issue 内注明） |
| B · 不复用，历史号保留 CNB 号 | 不动 GitHub；`FIX-109`/`CHORE-110` 的 `remote` 继续记 `cnb#109`/`cnb#110`；新任务号从 GitHub 当前最大号 +1 起 | 低——仅改发号逻辑 | 改动最小；历史事实完整；不触碰 GitHub 既有 issue | 永久保留两处号义冲突——检索 `#109` 时会同时命中「GitHub 占位 issue」与「本地 FIX-109」，需靠 `remote` 字段区分平台 |
| C · 一次性重编全部任务号 | 把 registry 中 71 个任务的号全部改成 GitHub 号，同步改卡片文件名、规格目录名、分支名、标签名、所有交叉引用 | 高——牵动文件名/分支/标签/引用链 | 编号体系彻底统一，无历史包袱 | 破坏所有已发布引用（卡片路径、分支名、git tag、PR 描述）；历史提交里的 `cnb#N` 文本改不掉；收益远低于成本 |

## 推荐

**倾向 A。** 三条理由：

1. **对症且彻底**——实际撞号只有 #109/#110 两处，复用是唯一能做到「零断裂 + 零浪费」的路径（编号不可回收是硬约束）。
2. **成本极低**——两条 `gh issue edit` + 两条 `gh issue reopen`，无代码改动，风险接近零。
3. **C 属于过度治理**——历史上 `cnb#N` 已经写进提交信息、分支名与标签，改不回来；强行重编只会制造「文档说 -205、提交说 cnb#109」的更大不一致。

**A 与 B 的差别仅在于那两处撞号是否清理**：A 清掉，B 留着靠 `remote` 字段区分平台。若松哥认为占位号历史难看、宁可留冲突，则选 B。

## 共同底线（不随方案变化）

无论选哪一种，以下三条都必须在 CHORE-111 中落实：

1. **历史任务的 `task_id` 一律不改**——`FIX-109`/`CHORE-110` 等已发布号保持原样。
2. **历史任务的 `remote` 字段一律不改**——`cnb#N` 是当时的事实记录；若选 A，则新增 GitHub issue 后在 `remote` 追加 `github#N` 而非覆盖。
3. **切换后禁止再用 CNB 发号**——`allocate` 必须断言不产出 `cnb#` 形式的号；GitHub 不可达时降级为 `TMP-*`，不得静默回落 CNB。
