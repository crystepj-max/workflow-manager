## 9. 业务规则

1. 输入和质量判据以同目录 benchmark-plan-V1.md 的12项为准，开始比较前冻结夹具内容、验收清单、template/script digest 与模型路由/设置。主路径基准12×3=36次；C1只比较三项建设机械preflight共9次，C2只比较探索X02定向补充共3次；总上限48次逻辑运行，不自行增加候选或样本。
2. C1仅将已确定资格判断替换为机械检查，保持同一任务事实、失败阻断和后续独立review/test/人工三态；C2仅在一个已知失败视角的补充轮减少无关专家，首轮仍3–5人，保留综合/终评和补充上限。若当前基准已具有同样能力，该候选记不适用、减少相应实验次数，不制造旧版对照或另找未批准候选。
3. 同一任务/重复编号的A与B使用完全相同的角色模型路由、参数、限额、夹具、权限和验收者规则，创建独立干净工作区/会话；按AB、BA、AB交替顺序执行。Provider/version变化后该配对不可直接比较，记录失配而非静默换模型。
4. 记录全部顶层和内部分派的实际模型调用及失败重试，不能把嵌套调用隐藏在一个节点内。Run自动墙钟采用活动区间并集，人工等待单列；中位数基于三个完整可比重复，不将取消/超时删除后只算成功者。缺完整配对则结论为证据不足。
5. 质量表包含每项固定AC、证据完整性、错误完成/越权、人工决定来源；比较至少要求候选每次全部固定质量项通过、证据完整且无新增越权/错误完成。基准没达到质量线时，可报告差异但不能仅凭更快失败声称等质收益；探索的有依据INSUFFICIENT可按预先冻结判据合格，不视作伪PASS。
6. 适用子集节省率=1-候选总实际模型调用/基准总实际模型调用；分母为0则不适用。只在配对任务上计算，禁止把未跑候选的其余任务混入分母。采用门槛为节省率≥20%、各适用任务的中位自动耗时不增加，且质量/证据条件全部满足；样本小，仅作本场景建议，不给总体显著性结论。
7. 费用只采用可核实usage与当时价格或账单，缺值为unavailable。真实调用前必须有已批准模型配置与费用上限/币种、可落实的预算约束；没有则停在实验准备，不能根据“分析需求”推定无限消费授权。固定48次不是48次模型调用。
8. 开始一个逻辑运行前需保证剩余额度可覆盖该Run的已配置调用/token上限或供应商硬额度；无法约束则不启动。超时/取消/失败均占一次计划执行，保留原始记录；重跑需重新批准额度，不能自动补足直到结果好看。费用上限触及、服务不支持有效限额、关键版本漂移时暂停实验并列未执行项。
9. 建设样例的人工验收仍必须由真实用户作出；实验可在等待关口停泊，汇总请求人工处理，不代签和不把测试注入事件记成人工验收。实验记录/发布为本地交付，不自动向他人发送或执行Git远端动作。

接口与数据归属：输入为固定fixtures、冻结配置及授权预算记录；输出 trial_id/task_id/arm/repeat/model_settings/input_digest/baseline_digest、原始调用/时间/usage/费用来源、质量核对表、人工事件和decision。可手工汇总现有日志；LOC-042/043 若届时可用可复用，但不依赖其尚未实现接口。

## 10. 用户操作路径

1. 读取任务卡、本规格和 §7 配套协议，核对批准版本、当前分支/HEAD 与启动基线。
2. 冻结12项输入、模型设置、候选与预算，在隔离环境逐个完成配对；未获真实费用授权仅制作实验准备。
3. 按验收计划保存原始结果、差异与错误，不隐藏失败，不以替身代替真实宿主/模型证据。
4. 汇总逐项 AC、候选版本及限制，交到人工验收关口；本需求分析不授权运行或发布。

## 11. 异常和边界场景

- **12任务与36基准记录**：完整时有36个真实逻辑运行记录；没有实测只能标实验准备，mock不能填充真实数据。
- **候选配对与度量**：至多12次候选；设置一致、分母正确，内部调用和失败未遗漏，缺费用不声称省钱。
- **采纳与负结果**：每项结论有适用范围和可复核计算；未满足全部条件为不采用或证据不足，不以删失败样本换绿。
- **隔离、额度与人工边界**：生产模板/角色未覆盖；无额度不调用模型，达上限不续跑；人工未决定就保持等待，报告不假称产品验收。

预算缺失/触顶、价格不可约束、模型路由变化或人工未验收时，保存原始样本及未执行列表并停止依赖该条件的操作；不得补跑直到得到好结果。
