## 9. 业务规则

- 提供节点级输入绑定，支持任务原始输入、指定上游节点的结构化字段、指定成果引用；required/optional、首次运行默认值必须显式声明。普通首次执行允许尚无评价反馈；由返工边进入时，触发返工的裁决和差距必须存在。
- 解析发生在调用代理之前，输出不可变输入清单；记录生产节点、执行标识及可用的成果版本。仅注入声明内容，正文可通过明确的文件引用交付；不把整个 Run 的历史无限拼进提示。
- 缺必需输入、引用错误类型或当前轮没有成功产出时，在调用消费节点前给出可定位错误；不得静默退用另一轮旧结果。旧蓝图维持原行为并显式标注旧输入模式。

**接手者可直接采用的实现边界：**沿用 compileBlueprint/runtimeCtx/callNode 接入 inputs 声明；resolveInputs 在调用之前解析任务字段与当前流转的上游结果。投影内核保留声明。V1 只支持明确字段路径与结构化引用，不提供任意表达式执行器。

**接口与数据约定：**输入选择器只支持 $.task、$.results.<node> 的明确字段链和触发本次返工的结果引用；禁止 eval、路径穿越及目录扫描。临时 version_ref 使用本次流转稳定标识和内容摘要，正式 Record 接入后用实际 Revision 替代，不要求 WR-006 先完成。

本条拥有“节点输入声明 → resolved_inputs”的接口。每项至少包含 binding、producer、version_ref、value 或 artifact_ref；已有 Record 时引用其 Revision，否则明确标记临时执行引用，不伪装为正式证据。WR-007 消费此清单。

**兼容方式：**新运行使用本条新规则；已启动运行保持其冻结快照。无法补证的旧历史明确 legacy/unverified，不改写成已验证完成。若其他 P0 已合入，复用其公共接口并运行集成检查；没有硬依赖的条目允许通过既有接口完成自身切片，不能自行等待整个需求包。

## 16. UAT 场景

### UAT-01 主路径与关键反例

- 验收目的：验证 §3 用户目标与 §15 全部 AC。
- 前置条件：对应候选源码在隔离 worktree；Node.js 24 与所需依赖可用；真实产品模式验证按既有发布规则使用安装产物。
- 操作步骤：使用优化模板与现有 runtime-harness，按首次执行→评估 gaps=A→返工→评估 gaps=B→返工的顺序保存每次 agentCalls 的真实 prompt；报告应逐项展示收到的输入与来源。
- 预期结果：正常输入达成目标；非法/缺失/过期输入按 §9 和 AC 拒绝；结果状态、产物和原因一致。
- 人工关注：界面/报告能看懂通过或受阻原因，不把测试替身结果当成用户已经接受。

### UAT-02 恢复与兼容

- 前置条件：保存一个旧快照与一个新规则 Run 的中间状态；仅在隔离环境制造中断。
- 操作步骤：分别恢复旧快照、新运行，再执行一次同请求重放或同内容重读；核对输出与证据。
- 预期结果：旧快照不静默迁移；新运行不丢有效成果、不伪造历史证明；本条涉及的非法条件仍被拦截。
- 证据要求：输出日志/实际产物/状态快照与候选 HEAD；不能只附最终 PASS 字样。
