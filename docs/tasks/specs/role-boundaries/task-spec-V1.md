## 9. 业务规则

- dev 允许必要自测与实现相关测试，不自签独立测试证明；review 保持独立判断且不修改候选；test 可写测试和证据，不解决业务源码冲突，发现冲突回开发/集成。
- accept 只整理本模板所需材料；建设按 uat-card.md/acceptance-summary.md 与严格三态，不代签。requirements/designer 不进入实施职责；diagnose 负责故障复现、根因假说及支持/反驳证据，不能把未验证推测写成已确认根因；保留 designer 作为定义/自定义工作流资产。evaluator 服从节点给定裁决与评价标准。
- orchestrator/researcher/synthesizer 保留视角、反证和不确定性职责，枚举与模板一致：探索统筹使用 PLAN_READY，研究 confidence 使用 high/medium/low；研究报告名来自节点声明；closeout 只整理已冻结事实，其外部执行机制归 WR-014。
- 将固定文件名、Git 要求、输出枚举、路径和任务完成条件放到 Node/上下文；优先级明确为宿主安全与授权 → 节点场景契约 → 角色通用能力，不用通用角色覆盖节点基线。

**接手者可直接采用的实现边界：**更新 dsh/roles 与节点场景目标，保留编译冻结机制；建立 role×node 对照并对实际编译 prompt 验证，不只扫描关键词。不得修改用户安装目录，分发按后续正式发布流程。

**接口与数据约定：**dev 可以自测但不签独立 Proof；review 不改候选；test 可写测试/证据但不解业务冲突；accept 整理三态材料而不代签；diagnose 区分假说/证据；requirements/designer 不实施；evaluator 使用节点评价标准；探索三角色维持独立视角/反证/不确定性，closeout 整理事实。角色不自授工具/发布权限。

本条拥有角色职责矩阵及 Role/Node 场景信息分工；与 WR-002 的裁决表保持一致。权限字段由 WR-018 拥有，不能用文案声称已实现权限隔离。

**兼容方式：**新运行使用本条新规则；已启动运行保持其冻结快照。无法补证的旧历史明确 legacy/unverified，不改写成已验证完成。若其他 P0 已合入，复用其公共接口并运行集成检查；没有硬依赖的条目允许通过既有接口完成自身切片，不能自行等待整个需求包。
