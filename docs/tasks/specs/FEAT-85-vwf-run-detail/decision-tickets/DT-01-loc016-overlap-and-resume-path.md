## 决策 1 · 与 `LOC-016` 的范围重叠如何处置

**必须决定什么**：`LOC-016`「运行看板 Logical Run 决策卡与工作区 UI」已定义同一表面，且其呈现层实现已存在于未合并分支 `dev-loc-016-r1`（停在人工验收）。新立的任务应当并入它、接它的分支做增量，还是按 handoff 原文独立立单？

| 方案 | 成本 | 收益 | 风险 |
|---|---|---|---|
| **A** 按 handoff 原文在主干上独立立单 | 立单成本最低；交付路径最短 | 立刻可开工；需求以本轮 UI 交互为唯一依据，不受 `LOC-016` 验收状态牵制 | **高**：与 `dev-loc-016-r1` 的 1319 行 `client.js` 改动重复实现；收口阶段必然要做一次分歧裁决；两套详情逻辑存在同时上主干的可能 |
| B 并入 `LOC-016`，把 handoff 作为其新一版规格续作 | 定义阶段需重写 `LOC-016` 规格并处理其验收状态（`attempt=11`、返工额度 3/3 已耗尽、`spec_path` 指向旧 `.scratch/` 约定） | 零重复劳动；生命周期语义唯一 | **高**：`LOC-016` 卡在人工验收且额度耗尽，先要一次人工裁决才能继续；本批次今夜无法产出 |
| C 接 `dev-loc-016-r1` 做增量 | 基线偏离主干，收口时两笔未验收工作捆在一起合并 | 今夜可推进；不重复实现 | **中高**：验收面变大；`LOC-016` 若被退回返工，本任务须跟着重做 |

**裁定：A**。依据 —— 人工在本轮决策中选择「立刻可开工」优先。**代价已被显式登记而非隐藏**：

1. 规格 §17 风险第 1 项记录重复实现风险；
2. 规格 §18 已知限制第 1 项声明收口阶段必然需要分歧裁决；
3. 规格 §11 要求开工第一步确认基线；
4. 验收项 **V-12 / UAT-07** 把「分歧裁决结论（复用 / 取代 / 并存）」立为必须交回的产物。

**本票不预设裁决结论**；若最终选择「并存」，UAT-07 要求写明两者职责边界与后续收敛计划。

## 决策 2 · `DT-01-ui-resume-attribution` 阻塞的提交路径如何处置

**必须决定什么**：`LOC-016` 的决策票 `DT-01-ui-resume-attribution`（UI 发起续跑的执行归属）状态为 **open**，它阻塞「决策卡点选续跑 / BLOCKED 改模型恢复」的提交路径。本任务的这一部分是：① 不做、② 只做界面并交出缺口、③ 夜间自行选一个方案实现。

| 方案 | 成本 | 收益 | 风险 |
|---|---|---|---|
| **A** 完整做出界面与字段映射；提交路径按受阻交出，交回缺口与映射表 | 交付不完整，需后续补 | 界面成果不浪费；无人值守不越权 | 低 |
| B 本任务完全不做决策卡与恢复卡 | 零 | 无越权风险 | 中：与 handoff 范围不符，验收项 V-6 / V-7 无法达成 |
| C 夜间自行选定执行归属方案并实现 | 零 | 功能闭环 | **高**：执行归属影响 Run 归属、Formal Record provenance、并发互斥与工作区生命周期挂靠，属产品级架构裁决，无人值守会话不得代签 |

**裁定：A**。依据 —— handoff 自身已给出同一处置原则（「若发现 host 尚未暴露结构化决策提交入口，先把缺口登记为运行协议依赖；不要在 client 中伪造成功状态」）。本裁定把该原则从「缺入口」推广到「决策未裁」。

**边界行为（已写入规格 §11，不属未决产品事项）**：做到该项时若 `DT-01` 仍为 open → 完成界面与字段映射 → 交出结构化交接 → 在 `release-event.json` 中按 `BLOCKED` 或如实标记 → **不得**在客户端伪造成功状态。
