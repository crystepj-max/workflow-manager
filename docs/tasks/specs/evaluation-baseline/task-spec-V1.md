## 9. 业务规则

- 确认 READY 后由运行时读取评价契约原始字节，计算 SHA-256 并保存不可变副本；模型摘要不得作为权威值。执行和评估均获得该副本引用及摘要。
- 同一基线内原路径被修改时拒绝继续评估，不静默更新摘要。RECONFIRM_REQUIRED 进入确认节点后可以生成新版本，但必须记录取代关系；旧基线的 PASS 不适用于新基线。
- 摘要按字节定义，换行或编码变化也视为内容变化；标准化操作只能发生在冻结之前。

**接手者可直接采用的实现边界：**confirm READY 后由宿主完成只读副本与摘要；使用既有 Run 证据目录隔离版本，随后节点读取该冻结路径。沿用 RECONFIRM_REQUIRED 业务边，新版确认后显式替换活动评价基线引用。

**接口与数据约定：**evaluation_baseline_ref={run_id,version,artifact_path,algorithm:"sha256",digest,supersedes?}；version 在同 Run 单调递增。原评价文件缺失/不可读是阻塞；摘要与模型声称值不同时拒绝，不自动纠正其专业结果。旧快照缺少副本标记 unverified，不迁移成已验证。

本条拥有 evaluation_baseline_ref（版本、不可变路径、算法、摘要、前版引用）及其相等校验；可通过现有节点上下文接入，不硬依赖 WR-001。

**兼容方式：**新运行使用本条新规则；已启动运行保持其冻结快照。无法补证的旧历史明确 legacy/unverified，不改写成已验证完成。若其他 P0 已合入，复用其公共接口并运行集成检查；没有硬依赖的条目允许通过既有接口完成自身切片，不能自行等待整个需求包。
