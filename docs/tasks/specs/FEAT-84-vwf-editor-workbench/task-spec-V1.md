## 1. 需求背景

正式界面已经有模板编辑能力（画布、节点配置、JSON 编辑、实时校验、撤销历史），但它的**承担表面不对**：完整画布塞在小尺寸设置弹窗里，弹窗可用内容宽度只有约 590px（见 `packages/dsh-visual-workflow/prototypes/ui-workbench/DESIGN.md` 「宿主空间」节），节点配置是长表单。用户在查看分支、回环、扇出与结果去向时，需要反复滚动，且右侧表单滚动会把画布一起带出视口。

同一轮用户反馈已经确认：模板编辑与运行详情**都采用 A 编排台方向**（`DESIGN.md` 顶部说明与 `REVIEW-2.md`）。本轮把该方向从一次性原型落成正式组件。

## 2. 用户问题（业务语言）

三件事同时疼：

1. **位置感丢失**——在右侧配置栏里翻找字段时，中央画布被滚走，用户不知道自己在改流程的哪一段。
2. **看不懂在配什么**——界面用的是节点、schema、表达式这类技术词，用户想的是「这一步谁做、交什么、做完往哪走」。
3. **流程关系被压缩**——检查不通过、修复仍有问题、原判断不成立、暂时无法继续这类**多种业务结果**，在当前界面里容易被理解成「成功 / 失败」两个按钮；并行研究（扇出）与返工回环也看不出结构。

一句话：**用户改得动流程，但看不懂流程，也守不住自己的位置。**

## 3. 目标

用户在单一工作区内，不离开上下文就能完成「看懂流程 → 改一处 → 看结果往哪走」：

1. 模板编辑有**两层表面**：小设置入口负责找模板与看摘要；「编辑 / 查看并验收」打开独立大工作区。
2. 大工作区的画布、右侧配置栏、连接清单**各自滚动**，头部与保存 / 返回操作常驻可见。
3. 节点配置按**渐进披露**呈现：先业务语言（任务 / 负责角色 / 交付内容），再结果与去向，最后才是高级设置与 JSON。
4. 流程关系**完整可见**：多结果路由、业务回环、扇出后汇总、调用重试与业务返工分开标识。

## 4. 非目标

- 不改工作流执行引擎、编译器、模板业务语义与回环计数规则。
- 不新增自定义模板的模型默认 / 覆盖 / 全部还原产品规则。
- 不做运行详情、人工决策卡、BLOCKED 恢复（属 FEAT-85）。
- 不重做角色存储、角色引用、供应商注册、模型列表后端（角色表面属 FEAT-86）。
- 不把原型中的示例运行 / 个人模板 / 角色内容当作生产数据。
- 不引入第二套滚动容器或第二套视觉方向（不复活初版 B/C 方向）。

## 5. 修改前

- 正式入口是小尺寸设置弹窗；完整画布没有承载表面。
- 生产组件已有 `Editor` / `Canvas` / `NodeInspector`、JSON 编辑、实时校验与历史栈，但页面结构未按 A 编排台收口。
- 外侧 `.vwf-editor-body` 可滚动、画布有最小高度（`src/client.js` 约 152–190 行的既有样式）——**画布与配置栏共享父级滚动**，是位置感丢失的直接原因（源码推断，`DESIGN.md` 已记为待验证项）。
- 撤销 `↶` / 反撤销 `↷` 已存在且有独立文档与测试证据（`packages/dsh-visual-workflow/docs/editor-toolbar-actions/README.md`）。
- 「选中节点 → 供应商与模型」入口已存在并可改模型（内置逐节点默认 / 覆盖见 LOC-014）。

## 6. 修改后

- 小设置入口保持轻量（找模板、看摘要、管理角色），「编辑 / 查看并验收」打开最大 1440px 宽的独立大工作区；关闭后回到原列表位置、筛选与滚动位置。
- 大工作区为 A 编排台：左侧步骤定位、中间路线画布、右侧单一节点配置栏；三者独立滚动。
- 节点配置分三段披露，业务词在前，技术词与 JSON 收进「高级设置」。
- 结果与去向可编辑且可读：多结果、回环、扇出汇总都以业务语言呈现。
- 未保存改动在关闭工作区时给出「继续编辑 / 放弃修改 / 保存并返回」三选一。
- 浅色、深色、390×844 窄屏、键盘焦点均达到同一可读性。

## 7. 功能范围

1. 两层表面与返回位置保持（列表、筛选、滚动位置）。
2. A 编排台三段结构与三个独立滚动区。
3. 节点配置渐进披露（基础 / 结果与去向 / 高级设置）。
4. 多结果业务路由的呈现与编辑。
5. 业务回环的呈现；与调用重试分开标识。
6. 扇出（并行研究组）与汇总的呈现，含子节点各自报告。
7. 连接清单（普通业务路由 / 业务回环 / 调用重试分类）。
8. 撤销 / 反撤销既有语义保持。
9. 内置模板结构只读；内置节点模型默认 / 覆盖 / 还原兼容保持。
10. 浅色 / 深色语义色、键盘焦点、Escape 关闭、窄屏布局。
11. 关闭未保存提示三选一。

## 8. 不修改范围

- 执行引擎、编译器、模板 JSON 语义、回环计数规则。
- 运行详情 / 人工决策 / BLOCKED 恢复（FEAT-85）。
- 角色存储、角色引用、角色权限（FEAT-86）。
- 供应商注册与模型列表后端。
- 既有 RPC 契约：本任务默认**不修改** `src/host.js`；若确需数据契约变化，先登记兼容性理由并单独交接。

## 9. 业务规则

- **业务结果不得二元化**：检查类节点必须能表达「检查通过 / 修复仍有问题 / 原判断不成立 / 暂时无法继续」等多种结果及各自去向。
- **业务回环 ≠ 调用重试 ≠ 返工轮次**：三者在界面上必须使用不同标签与说明，不得合并成同一个「重试」。
- **扇出未完成不得冒充汇总完成**：部分子任务未完成时，汇总节点必须显示为等待而非完成。
- **内置模板结构只读**：内置模板的节点与连接不可编辑；可编辑的是内置节点的供应商 / 模型设置。
- **模型范围边界**：默认 / 覆盖 / 还原只对内置模板生效；自定义模板不出现该层交互。
- **连接清单不漏边**：渲染结果必须覆盖模板定义中的全部连接；若模板存在连接而节点配置缺少对应结果选项，先按模板定义与校验器补齐渲染，**不得自行删除连接**。
- **技术词降层**：字段名、JSON、表达式只出现在「高级设置」层，且必须给出可理解的说明。
- **未保存不静默丢弃**：关闭大工作区时不得静默丢失改动。

## 10. 用户操作路径

1. 打开小设置入口 → 流程库 → 看到「内置 / 我的」分组与模板摘要。
2. 打开内置模板 → 确认名称、来源与只读提示 → 点「编辑 / 查看并验收」→ 进入大工作区。
3. 大工作区：点左侧步骤定位 → 中间画布定位到该节点 → 右侧只显示该节点详情。
4. 在右侧配置栏滚到底 → 中央画布仍可见、可拖动、可缩放、可查看连接。
5. 节点详情内先看「任务 / 负责角色 / 交付内容」→ 展开「结果与去向」→ 需要时展开「高级设置 / JSON」。
6. 打开连接清单 → 逐条看到普通业务路由、业务回环、调用重试。
7. 修改节点名称或结果去向 → 点 `↶` 撤销 → 点 `↷` 反撤销；撤销后输入新修改 → 旧重做记录被清除。
8. 点返回 / 关闭 → 若有未保存改动，选择继续编辑 / 放弃修改 / 保存并返回。
9. 保存后返回流程库 → 重新打开 → 名称、连接与已保存配置保持一致。

## 11. 异常和边界场景

| 场景 | 期望行为 |
|---|---|
| 模板定义有连接，但节点配置没有对应结果选项 | 以模板定义与校验器为准补齐渲染，**不删除连接**；界面给出可理解的缺项提示 |
| 画布与配置栏仍共享父级滚动 | 先解决容器高度与 `min-height: 0`，**不得**通过缩小字号掩盖 |
| 内置模型还原接口与当前客户端状态不一致 | 沿用既有 `vwf.workflows.modelOverride.get / save / clear`；记为模型依赖问题，**不扩展**为自定义模板功能 |
| 窄屏 390×844 | 流程 / 配置两个区域可切换；不把桌面画布缩成不可读小图；顶部主操作与底部保存不被遮挡 |
| 深色主题下对比度不足 | 按共享契约 token 修正，不得出现深色背景配深色字 |
| 保存失败 | 明确显示失败原因，保留用户输入，不静默丢弃 |
| 内置模板被尝试编辑结构 | 控件不可用并给出只读说明，不静默忽略点击 |
| 键盘操作 | Tab / Shift+Tab 可达全部可操作控件，焦点可见，Escape 关闭当前工作区或对话框 |

## 16. UAT 场景

### UAT-01 编排台位置感

- 执行时机：裁决前可观测
- 验收目的：确认画布不再被配置栏滚动带走。
- 前置条件：
  1. 已启动正式 DSH，插件包为本次候选版本。
  2. 打开任一内置模板进入大工作区。
- 操作步骤：
  1. 在右侧配置栏连续向下滚动到底部。
  2. 观察中央画布是否仍可见。
  3. 在画布上选中另一个节点。
  4. 用滚轮缩放画布。
- 预期结果：
  1. 中央画布始终可见，未被滚出视口。
  2. 仍可选中节点并进入其详情。
  3. 画布可缩放，连接仍可查看。
- 建议人工关注：画布与配置栏是否真的各自滚动，而不是靠缩小字号掩盖。

### UAT-02 业务语言可完成配置

- 执行时机：裁决前可观测
- 验收目的：确认不阅读 JSON 也能完成一次节点配置。
- 前置条件：
  1. 打开一个自定义模板（可编辑）。
- 操作步骤：
  1. 新增一个节点，仅使用业务词填写任务与负责角色。
  2. 配置交付内容。
  3. 设置「结果与去向」中的一个业务结果及其去向。
  4. 全程不展开「高级设置 / JSON」。
- 预期结果：
  1. 四步均可完成，界面不要求用户理解字段名或表达式。
  2. 保存后重新打开，配置保持一致。
- 建议人工关注：技术词是否被正确收进高级层。

### UAT-03 多结果 / 回环 / 扇出可读性

- 执行时机：裁决前可观测
- 验收目的：确认流程关系不被压缩成成功 / 失败二元模型。
- 前置条件：
  1. 分别准备一个多结果模板（诊断类）、一个含业务回环的模板、一个扇出后汇总的模板（探索类）。
- 操作步骤：
  1. 在诊断类模板中选中检查节点，查看其多种业务结果与各自去向。
  2. 打开连接清单，查看普通业务路由、业务回环、调用重试三类标识。
  3. 在探索类模板中展开并行研究组，查看多个子节点及其各自报告。
  4. 将其中一部分子节点置为未完成，观察汇总节点状态。
- 预期结果：
  1. 检查节点显示多种业务结果，不是两个按钮。
  2. 三类连接标签可区分，连接清单不漏边。
  3. 并行组、子节点报告、汇总输入来源可见。
  4. 部分未完成时汇总节点显示为等待，不冒充完成。
- 建议人工关注：回环与调用重试是否被误标为同一类。

### UAT-04 撤销历史与未保存返回

- 执行时机：裁决前可观测
- 验收目的：确认历史语义与未保存保护未被改造破坏。
- 前置条件：
  1. 打开一个自定义模板进入大工作区。
- 操作步骤：
  1. 修改节点名称，点 `↶` 撤销，再点 `↷` 反撤销。
  2. 撤销后直接输入一个新的修改。
  3. 尝试再次点 `↷`。
  4. 关闭大工作区。
- 预期结果：
  1. 撤销与反撤销按预期生效，无可用历史时按钮为禁用态。
  2. 撤销后产生新修改时，旧的重做记录被清除，`↷` 不可用。
  3. 关闭时给出「继续编辑 / 放弃修改 / 保存并返回」三选一。
- 建议人工关注：JSON 编辑与画布是否共用同一条历史。

### UAT-05 主题与窄屏

- 执行时机：裁决前可观测
- 验收目的：确认浅色 / 深色 / 窄屏可读可操作。
- 前置条件：
  1. 浏览器视口可切换；对比度测量工具可用。
- 操作步骤：
  1. 分别以浅色与深色打开大工作区，检查正文与控件边界。
  2. 将视口切到 390×844，检查横向溢出、顶部主操作与底部保存是否被遮挡。
  3. 用 Tab / Shift+Tab 遍历可操作控件，检查焦点可见性，按 Escape 关闭。
- 预期结果：
  1. 无深色背景配深色字；正文 ≥ 4.5:1，控件边界 / 图标 ≥ 3:1。
  2. 无横向滚动；主操作与保存可见可点。
  3. 键盘可达全部操作，焦点可见，Escape 关闭当前工作区或对话框。
- 建议人工关注：测量方法与工具须随证据记录。

### UAT-06 收口后回归
