## 1. 需求背景

Codex 以「先做可点原型、再定施工边界」的方式交付了一轮 UI 交互更新：一次性原型（`prototype:ui`，默认 `http://127.0.0.1:4178/settings/workflow-visual`）在第二轮收敛到 A 编排台方向，并拆出三份互不重叠的施工 handoff（H1/H2/H3）。本任务承接其中的 H1。

原型是**交互参考**，其编辑、运行、角色与模型示例全在浏览器内存中，不能当作生产数据；三份 handoff 也明确声明「不是正式任务规格，不替代 Issue 与人工验收」。本任务的工作即把 H1 转成正式规格并落到生产组件。

## 2. 用户问题（业务语言）

用户能改流程，但**看不懂流程，也守不住自己的位置**：

1. 完整画布被塞在约 590px 宽的小设置弹窗里；右侧配置栏一滚动，画布就被带出视口，用户不知道自己在改哪一段。
2. 界面用节点、schema、表达式等词，用户想的是「这一步谁做、交什么、做完往哪走」，两者对不上。
3. 业务结果被压缩：检查不通过、修复仍有问题、原判断不成立、暂时无法继续，这些在界面里容易被理解成「成功 / 失败」；并行研究（扇出）与返工回环看不出结构，调用重试与业务回环也容易被当成同一件事。

## 3. 目标

1. 两层表面：小设置入口管「找模板 + 看摘要」，编辑与查看进独立大工作区，返回时保留原列表位置。
2. 大工作区三区独立滚动（步骤定位 / 路线画布 / 节点配置栏），头部与保存、返回常驻。
3. 渐进披露：业务词在前，结果与去向居中，字段名、JSON、表达式收进高级层。
4. 关系完整可见：多结果业务路由、业务回环、扇出后汇总、调用重试与业务返工分开标识。

## 4. 非目标

- 不改执行引擎、编译器、模板业务语义、回环计数规则。
- 不给自定义模板增加模型默认 / 覆盖 / 全部还原层级。
- 不做运行详情、人工决策卡、BLOCKED 恢复（FEAT-85）。
- 不重做角色存储、角色引用、供应商注册、模型列表后端（FEAT-86）。
- 不引入第二套视觉方向（不复活初版 B/C）。
