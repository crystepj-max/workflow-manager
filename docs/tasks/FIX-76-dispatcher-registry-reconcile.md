## 摘要（三要素速览）

### 任务目标

让夜间批次调度器在采集候选前自动完成登记册账实对账，不再依赖总控提示词手动补步骤，消除「账本滞后导致本可开工的任务被误排除」。

### 涉及范围

- 做：在 `ai-task-dispatcher.mjs` 主流程中、候选采集之前插入对账调用；对账结果纳入批次报告；对账失败不阻塞批次但需显式标注。
- 不做：不改动对账脚本 `registry-reconcile.mjs` 本身的判定逻辑（属 CHORE-73 范围）；不改变调度器的并发、看门狗、结束契约语义；不改动 M3 执行计划既有行为。

### 验收标准

1. 调度器启动后、冻结候选快照之前自动执行对账，`--dry-run` 与实跑均可见对账输出；
2. 对账产生回写时，以回写后的登记册作为候选采集依据；
3. 对账报「可疑差异」时，相关任务本批不纳入并在报告中列出原因；
4. 对账失败时批次继续，报告中标注「本次判据可能滞后」；
5. 总控提示词的「第 0 步：登记册对账」可移除仍不影响正确性；
6. 全量测试通过。

## 现状与缺口（供需求分析用）

- 对账入口：`collectMergeFacts` 仅在 `scripts/ai-task-execution-plan.mjs` 的 `main()` 内；
- `ai-task-dispatcher.mjs` 只导入该模块的函数（如 `assessAndSort`），**不进其主流程**，因此对账在 M5 链路中被整体跳过；
- 现役缓解手段：`.scratch/night-batches/night-batch-prompt-v2.md` 第 0 步由 agent 手动执行，属提示词层止血，易随提示词变更丢失。
