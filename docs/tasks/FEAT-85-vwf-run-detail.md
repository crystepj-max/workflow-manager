## 摘要（三要素速览）

### 任务目标

让用户从**一个列表**管理多个工作空间里的多个工作流任务，并在**一个稳定的详情区**看懂「现在在哪一步、这一步产出了什么、是否被退回、下一步怎么处理」。同一个 Logical Run 的多轮返工显示为**同一次运行的连续分段**，不创建看似全新的任务来掩盖历史；人工决策与受阻恢复在界面内完成，不再让用户复制命令。

### 涉及范围

- 做：
  - 多工作空间运行列表：按空间分组、空间筛选、状态筛选、结果 / 完成类型筛选、分页、返回位置保留
  - 单条 Logical Run 的详情工作区：生命周期、当前分段、快照修订、节点尝试、业务结果、完成类型、正式产物、活动记录
  - 唯一详情出口：目录只用于定位，正文只展示选中节点；「结果 / 检查 / 活动」在同一区域用页签切换
  - 返工可读性：每节点显示 attempt / round；历史按时间排序；退回意见跟随触发它的审查轮次；旧下游结果标记为「上一轮成果」
  - 扇出可读性：并行组、子任务独立结果、汇总输入来源、未完成子任务状态
  - `WAITING_HUMAN` 结构化决策卡：选项、理由输入、提交前影响说明、提交后锁定与续跑中状态；至少支持 `USER_ACCEPTED` / `ADD_BUDGET` / `STOP`
  - `BLOCKED` 恢复卡：阻塞原因、Provider / Model 修改前后值、产生新 Snapshot Revision 且保留旧修订
  - 工作空间面板：mode、repository、branch、当前 / base HEAD、集成状态、活动锁、清理状态
  - 保留暂停、立即中断、指导与恢复的既有运行控制语义；按钮名称必须对应实际 action
- 不做：
  - 不改执行引擎的重试、回环、返工上限或 Logical Run 生命周期语义
  - 不在运行页编辑工作流结构（模板编辑属 FEAT-84）
  - 不重新设计供应商 / 模型配置；恢复只调用既有续跑语义
  - 不增加「成功 / 失败」二元业务模型；业务 Outcome、Lifecycle、Completion Type 必须分层展示
  - 不用新 RPC 替代既有 `vwf.runs.list`、`vwf.logicalRuns.get`、`vwf.run.control` 与 `wf_run` 参数（除非先记录兼容性理由并单独交接）
  - **不新造与 LOC-016 冲突的生命周期定义**

### 验收标准

- [ ] V-1 同一列表可同时看到至少两个工作空间的多条任务，可按空间与状态筛选，返回后保留筛选位置
- [ ] V-2 同一 Logical Run 的多个 segment 只呈现为一个用户任务，详情可看到每一段与快照修订
- [ ] V-3 详情只有一个选中节点结果出口；结果 / 检查 / 活动用页签切换，不出现上下重复详情
- [ ] V-4 返工路径能读出「实现 → 检查退回 → 实现 → 检查」，每轮成果与意见对应正确，旧下游结果有上一轮标识
- [ ] V-5 多视角扇出显示多个子任务、独立结果与汇总输入；部分未完成时不伪装成汇总完成
- [ ] V-6 `WAITING_HUMAN` 卡支持 `USER_ACCEPTED` / `ADD_BUDGET` / `STOP`，提交后同一 Logical Run 继续或结束并保留控制事件（**依赖 DT-01 裁定；未裁定则按受阻交出**）
- [ ] V-7 `BLOCKED` 卡支持当前 Run 的 Provider / Model 修改，恢复后出现新 Snapshot Revision，旧修订仍可查
- [ ] V-8 工作空间面板显示 mode、repository、branch、当前 / base HEAD、集成、锁与清理状态；读取失败有可见错误
- [ ] V-9 结果、Lifecycle、Completion Type 分层显示；业务结果不是简单成功 / 失败徽标
- [ ] V-10 浅色 / 深色 / 390×844 / 键盘焦点均可读且可操作
- [ ] V-11 自动测试、浏览器证据、正式 DSH 真机 E2E 与人工验收状态分开记录
- [ ] V-12 与 LOC-016 的分歧裁决已完成并写入交接（复用 / 取代 / 并存三选一，含理由与证据）
