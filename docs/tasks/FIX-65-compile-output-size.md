## 摘要（三要素速览）

### 任务目标

最小图（`scripts/test/fixtures/hello-blueprint.json`）的编译产物不得超过宿主捕获上限 64KB，使 S6 用例恢复通过；同时不得削弱「12 个内置角色均可加载」的能力面。

### 涉及范围

- 做：定位编译产物体积增长的来源；在保持蓝图语义与能力面不变的前提下把最小图产物压回上限内（或按已有先例、以实测依据调整上限并同步宿主与断言）。
- 不做：不改动任何工作流模板的节点语义与边；不删除内置角色；不为通过断言而放宽验收口径而不留依据。

### 验收标准

1. `npm test` 全绿（含 `scripts/test/generate.test.mjs` 的 S6 用例）；
2. 体积断言与其依据一致（不再引用失效行号/已放弃的旧约束），并在交付证据中给出实测数字；
3. 保留防膨胀闸门：上限按实测值定值，且代码中写明「新增载荷优先瘦身」；
4. `loadBuiltinRoleDefs(loadBuiltinRoleIds())` 仍可加载 12 个内置角色；
5. 全 12 内置角色各一节点的图，其 JSON 响应仍在宿主 `runNode` 1MB 上限内。

> 诊断结论见规格 §6：A 方案（压缩骨架）实测不足以解决（缺口 11.3KB，压缩空间仅 4.4KB），且断言前提已与宿主事实矛盾，建议采用 B。
