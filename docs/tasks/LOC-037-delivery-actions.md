## 摘要（三要素）

**目标：**用户先得到完整交付事实，再按已授权的必要动作完成交付；外部动作失败和可选清理失败被准确区分。

**范围：**事实报告、动作计划、授权引用、local/CNB 适配、必要动作完成判定和安全资源回收。 本期不增加 GitHub 运行时发布适配（账号恢复后单独定义），不改人工验收关口，不自动决定发布目标，不强删分支或工作区。

**验收标准：**

- [ ] AC-01：非 Git 优化正常收口，无 Git/PR 调用；已授权 CNB 交付通过动作接口执行且回读确认。
- [ ] AC-02：缺必要授权时先完成可交付材料并准确等待该动作授权；既有有效授权不重复询问。
- [ ] AC-03：必须合并却合并失败时不得 DELIVERED；可选清理失败保留成果状态并列出待清理资源。
- [ ] AC-04：收口前后候选内容一致；含未保全改动的工作区不被强删；同组环境遵守全部成员完成后回收。
