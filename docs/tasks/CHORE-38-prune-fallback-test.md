## 摘要（三要素速览）

### 任务目标

给收口脚本里那记「清理失效登记」的兜底动作补上可复现的自动校验——让它退化了有人立刻知道；同时让收尾提示按真实结果说话，不再无条件宣称已清理。

### 涉及范围

- 做：
  - 新增两条断言类用例：① 正常收口后清理结果为「已清理」；② 构造「父工作区删掉后残留幽灵子登记」的场景，断言收口后该登记被真正注销
  - 收尾提示按结果分叉：成功说成功，失败说失败并给出人工补救命令
- 不做：
  - 不改清理动作本身的逻辑与执行时机
  - 不新增「清理失败」的故障注入用例（该异常保护行为本票不改，造故障的改动面不成比例）
  - 不改现有 10 个用例的断言（只新增不改写）
  - 不改收口流程的其他判定（合并门禁、归档、分支保留）
  - 不处理与本票无关的既有红灯（治理闸门中的 LOC 系列归档缺口与未收口工作区）

### 验收标准

- [ ] V-1 正常路径下清理结果字段被断言为「已清理」
- [ ] V-2 幽灵登记场景：收口后工作区清单不再包含该失效子登记
- [ ] V-3 收尾提示按结果分叉，失败分支含人工补救命令
- [ ] V-4 新用例会咬：临时跳过清理动作后新增用例变红，恢复后转绿
- [ ] V-5 单文件测试全绿；全仓 `npm test` 不引入新的失败（已知抖动项需单独复跑确认）
