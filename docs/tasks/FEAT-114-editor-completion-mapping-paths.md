## 摘要（三要素速览）

### 任务目标

让用户在编辑器里不打开 JSON 就能给自定义工作流声明完成映射，并保证多层结果字段路径（`$.a.b`）在「结果与去向」面板中如实回显、如实编辑——改取值不再静默覆盖用户手写的路径层级。

### 涉及范围

- 做：
  - 「结果与去向」段新增完成映射区：字段路径 + schema 候选值 + 写回 `output.completionPath`；
  - `outcomePath` / `completionPath` 的多层路径表达、回显与保真写回（含旧属性清理）；
  - `validate-core` 已有六条 `completionPath` 规则的前端同源提示；
  - 投影往返与回归测试（路径保真、不降层、规则界面态、载荷）。
- 不做：面板分层重排（定稿确认三层即定稿）；插件运行入口（DT-01 已裁 A）；Outcome Preset 纠偏与选择器（定稿 S-2）；看板与运行详情呈现（S-4 / `LOC-016` / `FEAT-208`）；运行时取值逻辑；`templates/`；把 `COMPLETED_OBSERVING` 加进候选。

### 验收标准

- [ ] 自定义工作流收口节点能在界面声明完成映射，`npm run generate` 与 `npm run validate` 通过且生成结果一致。
- [ ] 该工作流真实跑到收口后，运行详情显示完成类型，不再为空。
- [ ] 手写多层路径完整回显；在面板改取值或增删边后路径逐字不变，schema 无孤儿属性。
- [ ] 六条校验规则界面同口径提示，不引入内核没有的新规则。
- [ ] fanout 节点与内置模板节点不提供编辑入口。
- [ ] 回归测试覆盖保真、不降层、无孤儿、规则界面态；载荷不超 290816 B。
- [ ] 未改 `host.js` 运行时取值逻辑、未改 `templates/`。
