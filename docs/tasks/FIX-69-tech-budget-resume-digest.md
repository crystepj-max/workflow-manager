## 摘要（三要素速览）

### 任务目标

技术预算（LOC-031 / WR-011 V1）的受阻恢复必须遵守「激活 = 同节点 + 同输入版本」：业务输入修订后恢复 Run，必须获得全新激活键与全新激活预算，不得沿用冻结键继承已耗用量（修复前表现为 0 次新调用立即再受阻）。

### 涉及范围

- 做：预算快照冻结受阻时刻的输入摘要（`resume_digest`）；恢复沿用冻结键前校验输入摘要一致；补业务输入新版本恢复的回归用例。
- 不做：不改动技术预算的策略声明与限额口径（`control.retryPolicy`）；不改 LOC-030 的生命周期语义；不动 S6 体积闸门（独立任务 FIX-65）。

### 验收标准

1. `scripts/test/runtime-technical-budget.test.mjs` 全绿（21 用例 = 远端存量 20 + 新增回归「AC-03 业务输入新版本恢复：新激活签名获得全新预算，不继承已耗尽次数」）；
2. 既有「AC-03 受阻恢复不重置」（原样恢复 0 次新调用）保持通过——恢复沿用语义不得回退；
3. 探针复验（`.scratch/loc-031-f01f02-verification/probe.mjs`）：修复前新输入恢复 0 次新调用即再受阻；修复后获得全新激活键与全新预算；
4. F-01 场景（检查点现场形态提额增量精确生效）保持通过（远端既有用例 + 探针复证）。
