## 摘要（三要素）

**目标：**状态与恢复约定具有一处可直接测试的实现，调用者通过薄适配使用；用户已有工具、状态和恢复行为保持一致。

**范围：**状态/恢复纯逻辑、共享字段约定与薄适配的一个完整切片；生成器、host 及实际打包加载入口；必要的行为对照与迁移说明。 不重写引擎，不拆分整个 host/client，不改四模板拓扑、状态名或人工权限，不接管记录事务、输入绑定、精确失效和技术预算。

**验收标准：**

- [ ] AC-01：状态/恢复的权威规则只有一处实现，生成器和宿主不再各自维护相同转换表或条件分支。
- [ ] AC-02：正常、返工、人工等待、受阻恢复、取消及旧快照兼容的行为对照用例一致。
- [ ] AC-03：Node 环境可直接测试纯逻辑；实际 DSH 打包入口仍加载成功，VM/子进程边界无新增宿主依赖泄漏。
- [ ] AC-04：提交清单列出被消除的重复规则与调用方，未混入新的业务行为或未经本需求包约定的状态改名。
