## 摘要（三要素速览）

### 任务目标

把开发侧 DSH 运行目录（`~/.dsh-workflow-dev`）里与实体已不符的运行态残留清干净：退役 #185 独占 Home 机制的遗留目录、清理已终止的 UAT/探针工作区记录、收敛指向已消失目录的登记册条目，并输出一份可核对的清理报告。

> **定位说明**：清理对象合计约 220 KB，**本任务目标不是释放空间**，而是消除「登记册指向已消失实体」的不一致、并退役已废弃机制的遗留物。

### 涉及范围

- 做（**仅开发侧** `~/.dsh-workflow-dev`）：
  - 清理独占开发 Home 遗留目录 `tasks/loc-014-r1/`（#185 机制退役后无人认领，内含仅一个归属标记文件）；
  - 清理 `workspaces/records/` 下 12 条已终止的 UAT / 探针工作区记录；
  - 收敛 `workspaces/.vwf-registry/state.json`：现 11 条登记**全部**指向已不存在的 `ws-*` 目录（实体已消失），按实体为准移除已终止条目；
  - 输出清理报告（盘点清单 + 前后条目数对比 + 不可删除项及原因）。
- 不做：
  - **不动产品侧 `~/.dsh/workspaces/`**（含 1 条 RUNNING、1 条 PAUSED，可能仍有活动；且 LOC-020 已明确不动产品 DSH）；
  - **不动 `.agent-runs/` 证据明细**（已有 `task-runs-cleanup.mjs` + 7 天保留期机制与门控，属另一机制）；
  - 不动 `visual-workflow/`（模板、logical-runs、runs 等运行数据属另一机制，本任务不核实、不清理）；
  - 不做任何删除以外的架构或代码改动；
  - 不处理 CNB #19 的机制改造（那是 LOC-020）。

## 关键边界与异常

| 场景 | 处置规则 |
|---|---|
| 登记册条目指向的实体已消失（当前即是） | 以**实体为准**收敛条目，不反向重建目录 |
| `WAITING_HUMAN` 条目 | 先确认是否还有未完成的人工决策门；有则**保留**并写明 |
| 开发 DSH 实例正在运行 | 不得清理其实例正在使用的记录；先停实例或跳过该条并记入报告 |
| 锁文件 / 权限导致删除或改名失败（本机已知现象） | 如实写入报告，**不静默跳过、不谎报已清** |
| 待清对象被其他 Run 引用 | 停止该项并上报，不强行删除 |
