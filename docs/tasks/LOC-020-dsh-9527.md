## 需求分析结论（对原提案的实质修正）

分析阶段对原提案的核查结果，均已获确认（2026-09-13）。完整证据见 `.scratch/LOC-020-dsh-9527/requirements-analysis.md`。

1. **P0 前提已于代码层判定为「不支持」**：DSH 不存在「工作空间作用域」这一维度——动态插件注册表是**进程级全局**的，归属字段只有发起它的会话（`packages/extensions/cordis-host-runner/src/registry.ts:142`、`:54-55`）；DSH 的 `workspace` 实体只是「目录 → 会话」的展示分组。原假设「两个 workspace 各注册同名动态插件互不干扰」**不成立**。
2. **真正的共享资源是「进程」与「浏览器页面」**：宿主半边（工具 / RPC 服务）进程全局；浏览器半边在单个页面内全局。本插件宿主半边注册的是**固定名**（`wf_run`、`vwf_workspace`、`wf_control`、`vwf_debug` 及 `vwf.*` 路由）→ 原兜底方案「插件注册名带 Run 命名空间」只能覆盖 pluginId，**覆盖不到工具名与路由名**，并发激活必然撞名。
3. **多 Home 机制失效已被一手证据证实**：LOC-014 的专属 Home 目录内只有一个归属标记文件、无任何运行状态（分配了从未使用）；实际在跑的开发 DSH 用的是共享默认 Home；收口时无 `cleanup-report.md`（回收步骤被跳过，残留至今）。
4. **基线修正**：隔离手段改为「任务命名前缀 + 同一时刻只允许一个激活」；原验收条件「两个并行任务同时注册、互不干扰」不可达，改为「先后激活、自动切换、任何时刻只有一个激活」；历史残留清理拆为独立任务。
