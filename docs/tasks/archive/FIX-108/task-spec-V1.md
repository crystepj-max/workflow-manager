# 运行详情状态口径统一 + 上一轮成果标签显示条件修正

## 1. 缺陷描述（smoke-01 实测）

**缺陷 1 · 状态口径不一致**：同一事实在三处呈现互相矛盾——
- 结果信息：第一次审查「审查通过」
- 执行记录（attempt picker）：第一次「退回修改」
- 完整经过链路：第一次「已通过」

三个视图对「第一次执行到底过没过」给出了不同答案。根因方向：三处视图各自从不同字段/不同索引推导状态（审查自身结果 vs attempt 结局 vs 链路 tone 映射），缺少单一判定权威。

**缺陷 2 · 上一轮成果标签全量显示**：链路每个节点右侧都挂「上一轮成果」标签。设计意图（FEAT-85）：返工轮开始后，仅对「本轮尚未重新执行」的节点展示上一轮成果作参照；首轮节点、本轮已重做出的新成果不应显示。实测全节点显示，判定条件失效或从未生效。

## 2. 修复要求（诊断前置）

1. **诊断报告（施工第一步，落 run 目录）**：对 smoke-01 真实记录（经 vwf.records.list / records host 数据）复现三处不一致，逐视图写清「它读的是哪个字段、为什么得出该结论」、指出权威字段应当是谁（attempt 的真实结局 = 审查裁决 + 后续去向），并解释缺陷 2 的判定条件实际行为。
2. **统一状态权威**： attempt 结局判定的单一权威实现，三处视图（结果信息 / 执行记录 / 完整经过链路）全部改由它推导；语义集合至少：进行中、已通过、退回修改、阻塞、等待人工、已裁决。
3. **上一轮成果标签条件修正**：仅当「存在上一轮该节点的成果 且 本轮尚未执行到该节点」时显示；首轮不显示；本轮已有新成果的节点不显示。
4. 数据读取与 RPC 不变；不改后端。
