## 摘要（三要素速览）

### 任务目标

让登记册与主干合并事实保持一致：合并后账自动对上、并发写互不覆盖、调度判定不再被账本滞后误导。

### 涉及范围

- 做：三层机制——①对账脚本（git 事实 → 登记册自动回写）；②登记册版本锁（写回前校验，防读旧覆盖）；③执行计划依赖判定改看 git 事实（不再一律排除有依赖任务）。
- 不做：不引入远端实时推送（CNB 无现成事件能力，收益低）；不把登记册迁去远端（违背本地轨道离线可用）；不改变验收三态、返工上限等既有纪律。

### 验收标准

1. 对账脚本能从提交信息尾部任务号与收口标签推导合并事实，`apply` 自动回写落后条目；
2. 两会话并发写登记册时，后写者被拒并得到明确指引（先同步、再对账、后重读）；
3. 执行计划对「依赖已完成」的任务不再一律排除，对「依赖未完成」仍排除并说明；
4. 全量测试通过（638/638，含 5 个新增用例）。
