## 1. 需求背景

开发用的 DSH 环境目前沿用「每个开发任务开工时分配一套独占运行空间」的机制（#185）。本次用刚跑完的 LOC-014 做了实测核查，发现该机制在真实任务上**根本未被使用**：分配给它的专属目录里只有一个归属标记文件，没有任何运行状态；实际在跑的开发环境用的仍是共享默认空间；收口时环境回收步骤也被跳过，那个空目录至今残留。

同时，开发环境地址不固定（每次启动随机取端口），每次要查、要记。为「每任务独占空间」付出的整套防御（分配、归属双证、双证校验、14 天兜底扫描）没有换回实际价值。

## 2. 用户问题

一句话：**开发环境每次地址都不同，要为它查端口；而为「每任务独立运行空间」维护的那套机制，在真实任务里既没被用起来、也没被收干净，是纯成本。**

## 3. 目标

交付后：开发环境固定为一个地址，长期复用；任务之间不再靠复制整套运行空间隔离，而是靠「命名 + 同一时刻只允许一个任务激活插件」的纪律；与之配套的分配、归属校验、兜底扫描机制全部退役，收口语义从「按双证删运行空间」简化为「确认本任务插件已停用注销 + 清本任务工作区记录」。

## 4. 非目标

- 不做 DSH 上游改造（不给上游提「工作空间作用域」工作项）。
- 不做插件内部工具名与后台接口名的命名空间化。
- 不执行历史残留清理（拆为独立运行操作任务）。
- 不改变 git 层隔离（相邻容器工作区 + 产物锚定主检出）。
- 不改变产品 DSH（`~/.dsh`）的任何行为。

## 5. 修改前

- 每个任务开工时，为它分配一个专属运行空间目录并写入归属标记；目录已被别的任务占用或缺少标记时直接报错。
- 运行登记里记录该专属空间的路径。
- 开发环境启动时端口随机（`--port 0`），地址每次不同。
- 收口时先按「运行登记 + 空间内归属标记双证一致」校验，才允许删除该专属空间；另有 14 天兜底扫描清理残留。
- 实测结果（LOC-014）：专属空间分配了但未被使用；收口时未回收；残留至今在盘上。

## 6. 修改后

- 开发环境**唯一且长期复用**，固定监听 `127.0.0.1:9527`。
- 开工**不再分配专属运行空间**；运行登记中该字段语义改为「本任务的插件命名空间 + 固定端口」。
- 任务间隔离改由三层承担：① git 层（已落地，本次不动）② 插件注册名带任务前缀 ③ 「同一时刻只允许一个任务激活插件」纪律（激活前自动检查并停掉上一个）。
- 收口**不再删除运行空间**，改为：确认本任务的插件已停用并注销 → 清理本任务的工作区记录 → 输出回收报告。归属双证校验与 14 天兜底扫描退役。

## 7. 功能范围

1. 开发环境固定端口 9527；启动与状态检查脚本收敛为「单实例」语义。
2. 开工流程不再分配专属运行空间；运行登记相应字段语义改为「插件命名空间 + 固定端口」。
3. 插件注册名强制带任务前缀（形如 `<run_id>-vwf`），裸名被拒绝。
4. 激活插件前自动检查并停掉上一个任务遗留的插件，对人工只呈现一条清晰提示。
5. 收口环境回收改为「确认本任务插件已停用注销 + 清本任务工作区记录」，并输出报告；双证校验与兜底扫描退役。
6. 手册（Runbook §0 与 §7）与四个角色说明（开发、测试、审核、收口）同步对齐。
7. 设计文档新增一条决策：运行时实例布局 = 单实例固定端口 + 任务命名隔离（取代每任务独占空间）。
8. P0 结论**实机确认**并写入设计文档：代码层已判定 DSH 不存在「工作空间作用域」，实机确认「两个任务同时激活时撞名的实际表现（报错还是相互覆盖）」。

## 8. 不修改范围

- 不修改 git 层隔离与产物锚定规则。
- 不修改产品 DSH 的启动方式、端口与配置。
- 不修改插件内部的工具名与后台接口名。
- 不修改验收流程、返工额度、证据链规则。
- 不删除任何历史目录（本次只退役机制，不执行清理）。

## 9. 业务规则

- 插件注册名必须带任务前缀，禁止裸名。
- **同一时刻只允许一个任务的插件处于激活状态**；激活新任务前必须先停掉上一个，停不掉时如实报为遗留事项。
- 固定端口 9527 是唯一开发入口；端口被占用时报错并指明占用者，**不允许自动改用其他端口**（否则又回到地址漂移）。
- 开发环境不得指向产品运行空间。
- 收口未完成「本任务插件已停用并注销」的，不得视为收口完成。

## 10. 用户操作路径

1. 首次：执行开发环境启动命令 → 环境起在 `127.0.0.1:9527`，之后长期复用，不再每次重启。
2. 任务开工：脚本不再建专属运行空间，改为登记「本任务的插件名前缀 = 任务标识」。
3. 开发中：在 9527 上操作界面。激活本任务插件前，脚本自动检查并停掉上一个任务遗留的插件，人工只看到一条提示（谁被停掉了、现在跑的是谁）。
4. 收口：脚本确认本任务插件已停用并注销、清掉本任务工作区记录，输出回收报告；停不掉的残留如实写入遗留事项。
5. 查看状态：状态检查命令能一处看清——固定地址、当前激活的是哪个任务的插件、有无遗留。

## 11. 异常和边界场景

- **9527 被占用**：报错并给出占用进程信息；不自动改端口。人工处置后重试。
- **上一个任务的插件停不掉**（归属它的会话已消失）：明确提示「需人工在插件面板中清理」，计入收口遗留事项，**不得谎报已回收**。
- **开发环境本身挂了**：所有并行任务全停。开发态、非生产，已接受，写入手册。
- **早于本次改造的旧任务登记**：缺少新字段 → 按「无登记资源」处理，不报错、不阻断合并主路径。
- **启动时发现多个开发环境实例**：报错并列出，要求人工确认，不自动挑一个。
- **任务名撞名（两个任务派生出同一前缀）**：拒绝，要求换任务标识，不静默复用。

## 16. UAT 场景

### UAT-01 固定地址可用

- 验收目的：确认开发环境地址从此固定、可长期复用。
- 前置条件：
  1. 本机无其他进程占用 9527。
  2. 开发环境未启动。
- 操作步骤：
  1. 执行开发环境启动命令。
  2. 浏览器访问 `http://127.0.0.1:9527/`。
  3. 停掉后重新启动，再次访问同一地址。
- 预期结果：
  1. 启动输出明确给出 `127.0.0.1:9527`。
  2. 界面正常可用。
  3. 重启后地址不变，无需重新查询。
- 建议人工关注：启动输出是否一眼能看出地址；有无"又换端口了"的意外。

### UAT-02 两个任务切换激活，互不串台

- 验收目的：确认「同一时刻只允许一个任务激活」纪律真实生效。
- 前置条件：
  1. 开发环境已在 9527 运行。
  2. 准备两个任务（或两次模拟）各自带任务前缀的插件版本。
- 操作步骤：
  1. 任务 A 激活其插件，界面确认可用。
  2. 任务 B 激活其插件。
  3. 观察提示与 9527 上实际在跑的是谁。
- 预期结果：
  1. A 激活后正常可用。
  2. 激活 B 时脚本自动停掉 A，并给出一条清晰提示（停掉了谁、现在跑的是谁）。
  3. 任何时刻只有一个任务的插件在跑，不出现两个界面串台或后台接口被对方接管。
- 建议人工关注：提示是否清晰到不需要额外查证；是否存在"以为跑了 B，实际还是 A"的错觉。

### UAT-03 收口回收与残留如实上报

- 验收目的：确认回收语义简化后仍然可靠，且不存在谎报。
- 前置条件：
  1. 一个已完成验收、准备收口的任务。
- 操作步骤：
  1. 执行收口回收。
  2. 查看回收报告。
  3. 另造一个「归属会话已消失、插件停不掉」的残留场景，再执行一次回收。
- 预期结果：
  1. 报告显示：本任务插件已停用并注销、本任务工作区记录已清。
  2. 报告不再出现"双证校验""14 天兜底扫描"等字样。
  3. 残留场景下明确提示需人工在插件面板清理，并计入遗留事项，退出码反映未完成。
- 建议人工关注：报告是否说人话、能否据此判断"到底收干净了没有"。

## 17. 风险

- 🟡 **并发能力回归**：两个任务不能同时激活各自的插件版本。已由决策接受；手册需写明「同一标签页内不同任务的界面半边理论上可并存，不同任务请用不同标签页」。
- 🟡 **单点**：开发环境一挂，所有并行任务全停。开发态已接受。
- 🟡 **自动停上一个任务插件依赖「能被探测到」**：会话已消失时探测不到，只能人工兜底。已在异常场景与验收条件中显式要求如实上报。
- 🟡 **固定端口可能与用户既有习惯冲突**：9527 需确认未被其他常用服务占用；被占用时按设计报错，不自动改端口。

## 18. 已知限制

- 不做插件内部工具名与后台接口名的命名空间化，故这些名字在开发环境内仍是全局唯一——这是「同一时刻只允许一个激活」纪律存在的原因。
- 历史残留（今日空目录、12 条 UAT 记录）不在本任务范围，另立任务处理。
- DSH 侧「工作空间作用域」能力不存在，本任务不改变这一点；若将来上游提供，本方案可平滑叠加。
