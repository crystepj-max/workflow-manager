## 3. 方案

### 3.1 D-8 · 15 条：从存根回填机读凭据（不新造字段值）

对每个 `LOC` 任务，解析同目录存根的三行（状态 / 远端 / 分支），把**已在库的事实**写成机读字段：

```json
"archive_form": "lightweight-remote",
"merge": { "commit": "<登记册的完整哈希>", "merged_at": "<存根时间>" },
"remote_ref": "cnb#<存根远端号>"
```

**真实性约束（R-5）**：`merge.commit` 取**登记册**的完整值（检查要求逐字一致），并**断言**存根短哈希是其前缀；不一致则中止并报告，**不得**择一编造。

### 3.2 D-8 · 16 条：建归档目录 + 三件套

对每个任务：建 `docs/tasks/archive/<ID>/`，放入 ① 任务卡（`docs/tasks/<ID>-<slug>.md`）② **规格终版**（`docs/tasks/specs/<ID>-<slug>/` 中版本号最高者）③ 证据摘要（由 `scripts/workspace-evidence-summary.mjs <ID> --no-run-evidence --repo <路径>` 生成）。

### 3.3 D-8 · 2 条：补证据摘要

仅生成 `evidence-summary.json`，卡与规格已在归档内，不动。

### 3.4 D-9 · 12 条：执行到期清理

按约定 §1.8 执行「证据明细到期清理」。工具：`scripts/task-runs-cleanup.mjs`。

- **执行前**：以该工具**只读预演**取证（已取得：12 项、逐项目录、体积合计）。
- **安全网**：先把 12 个目录打包备份到 `/tmp/`，再执行删除；备份路径写入证据摘要引用。
- **删除前置条件**（工具既有硬约束，本票一并遵守）：`archive/<ID>/evidence-summary.json` 必须存在，否则拒绝删除该项。
- **执行方式说明**：该工具以 `root`（主检出）为锚点写登记册，而主检出登记册当前**被并行会话占用**（在制改动未提交）。为不污染他人在制内容，本票**按工具同一判定条件执行目录删除**，字段 `evidence_cleared_at` 由**修好后的工具**写入**本票工作区的登记册**。

#### 3.4.1 工具缺口修复（本票新增范围）

原实现把「到期但明细目录已不存在」的项只列为 `pending` 而**不写 `evidence_cleared_at`** → 登记册永远停在「未清理」→ D-9 长期报红且**无法用本脚本消除**。该缺口原以「潜在」记录，**2026-09-21 施工时被实际触发**：`loc-008-r1`~`loc-011-r1` 四个目录在备份后、删除前已被**其他进程**移除（登记册未同步），若不修则 D-9 对这 4 项无法转绿。

修法：该项在**摘要齐备**（约定 §1.8 前置条件）时改判为「按已清理登记」并写入 `evidence_cleared_at`；摘要缺失仍拒绝处理。语义说明：无明细即无残留，且证据摘要可回溯，登记「已清理」是陈述事实，非伪造。

### 3.5 D-10：改核验共享真值（负责人 2026-09-21 裁定口径 B）

> 口径在原提问（「远端或本地任一存在」）基础上，因**施工期取得新证据**而改推为**以远端为准**，经负责人二次裁定：
> 登记册 22 条全部标 `true`，但其中 **21 条远端根本没有分支**（仅 `CHORE-111` 有），而 20 条在本地残留；
> 15 个存根中 **14 个明确写 `branch_retained=false`**，即既有归档事实与登记册矛盾。以远端为准可同时消解该矛盾，
> 并让「保留」一词含义确定；若采「任一存在」，则 14 条 LOC 的登记册与存根将长期互相矛盾。

1. **检查器**（`scripts/validate-workspace.mjs`）：存在性判定由「本地 `refs/heads/<branch>`」改为**「远端 `refs/remotes/origin/<branch>`」**。失败文案标注「远端」，避免歧义。
2. **CI 环境**（`.github/workflows/validate.yml`）：补一步 `git fetch --no-tags --prune origin '+refs/heads/*:refs/remotes/origin/*'`，使共享真值可得（不静默降级：该步失败即显式报错）。
3. **数据校正**：**21 条**改标 `branch_retained=false`（`CHORE-36/37/38`、`FIX-72`、`LOC-008/009/010/011/012/013/014/015/017/019/020/021/023/045`、`CHORE-104`、`CHORE-106`、`FEAT-237`），每条均以**远端实测**为依据；`CHORE-111` 保持 `true`（远端确有分支）。
4. **不删本地残留分支**：那些分支是 CNB **squash 合并**下其提交的唯一副本，删除即真实丢失；它们在新口径下不影响判定。

**不采用**的两条路及其理由：改语义取消存在性核验 → 等于删掉检查，失去「防登记册标注与现实漂移」的原意；按「任一存在」判定 → 允许本地残留冒充「保留」，且无法消解登记册与存根的既有矛盾。

## 6. 风险与残留

- **D-9 删除不可逆**（工具语义为 `rm`）：已用打包备份兜底；删除内容为过程产物，证据摘要仍在归档内。
- **D-9 执行期异常（已记录）**：备份时 12 个目录均存在，紧接的删除步骤发现 `loc-008-r1`~`loc-011-r1` 四个已被**其他进程移除**且登记册未同步——系并行活动，非本票动作；备份包完整保留全部 12 个，且本票以「无残留目录 → 按已清理登记」如实收口。**建议后续排查该并行活动的来源**。
- **D-10 新口径依赖远端引用新鲜度**：本地执行前需 `git fetch`（已写入检查器注释）；CI 由显式 fetch 步骤保证，该步失败即显式报错而非降级。
- **`remote_ref` 为 CNB 指针**：CNB 侧 issue 号来自存根，未联网复核；按「存根 = 既有事实」采信，符合 FIX-72 的轻量归档语义。
- **登记册 `merge` 字段存在两种形态**（对象 / 形如 `'GitHub PR #206 (…)'` 的字符串）：摘要生成器对字符串形态取不到 `merge.commit`，故那批归档的摘要该字段为空。不影响 D-8 判定（本地收口路径不校验合并凭据），**记录为遗留**。
- 遗留：`.agent-runs/` 的 44 个孤儿目录；D-10 的 22 条无法核验项；D-10 涉及的 20 个本地残留分支（保留现场，未删）。
