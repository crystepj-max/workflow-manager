## 1. 需求背景

正式角色管理已经有内置 / 自定义分区、来源 badge、内置只读、自定义编辑 / 复制 / 删除与角色详情。但两件事仍然疼，且第三件事需要一个统一的收口：

1. 用户**分不清**内置角色和自定义角色；
2. 职责很长的自定义角色会**撑爆列表**；
3. 编辑器、运行页、角色页的主题变量分散在 `src/client.js` 与 DSH alias 中，缺少统一的语义命名，导致「深色背景配深色字」这类对比度问题反复出现。

本任务同时是三个切片的**收口切片**：在 FEAT-84 / FEAT-85 的表面结构稳定后，统一角色长文本、浅深色与无障碍。

## 2. 用户问题（业务语言）

1. **不知道能不能改**——看到内置角色想改，不确定是否允许；也看不出某个角色是哪来的。
2. **列表被撑爆**——某个角色职责写了几千字，列表行被拉得很长，其他角色被挤下去，找角色变慢。
3. **深色下看不清**——深色主题下出现深色背景配深色字；窄屏下按钮被工具条盖住，键盘焦点看不见。

## 3. 目标

1. 角色列表一眼区分内置与自定义；内置只读可复制，自定义可编辑 / 删除并显示引用阻塞。
2. 摘要与全文分离：列表摘要最多两行，完整职责在独立滚动详情中可读。
3. 编辑器、运行页、角色页收敛到**同一套 A 编排台语义 token**（浅 / 深成对定义）。
4. 对比度达标：正文 ≥ 4.5:1，非文本控件 ≥ 3:1；状态同时有文字与图形。
5. 390×844 与常见桌面宽度下均可操作；键盘可达全部操作、焦点可见、Escape 关闭并回收焦点。

## 4. 非目标

- 不修改角色存储、角色内容、角色引用关系、删除规则和宿主 RPC 语义。
- 不新增角色权限层；不把内置角色改成可直接编辑。
- 不改 FEAT-84 / FEAT-85 的业务路由、运行状态、模型 override 或模板数据。
- 不以降低正文字号、隐藏文字或降低对比度解决窄屏拥挤。
- 不重新引入初版 B/C 视觉方向；沿用 A 编排台的雾蓝语义系统。

## 5. 修改前

- 角色管理已有内置 / 自定义分区、来源 badge、内置只读、自定义编辑 / 复制 / 删除与角色详情。
- 角色行仍可能把完整职责、简介和操作挤在一行；长职责需要两行摘要 + 独立详情滚动。
- 原型已验证 4,537 字职责与连续长串时列表**不横向溢出**（`REVIEW-2.md` 记有浏览器检查记录），但该行为只在原型中验证过，**尚未落到正式组件与真实角色数据**。
- 主题变量分散在 `src/client.js` 与 DSH alias 中，缺少统一的语义 token 命名。
- 现有角色 RPC：`vwf.roles`、`vwf.roles.get/create/update/remove/usage`（本任务默认不改）。

## 6. 修改后

- 角色列表在标题与行内均可识别来源；内置角色只读、可查看与复制，自定义角色可编辑 / 复制 / 删除，删除前显示引用数量与受影响模板。
- 没有简介但职责很长的角色，列表只展示两行截断摘要；点「查看详情」后完整职责在独立滚动区域展示。
- 列表高度不随职责全文增长；连续长串（无空格长串）被断词或换行，不产生横向溢出。
- 编辑器、运行页、角色页共用一套浅 / 深语义 token；无低对比度文字。
- 390×844 下列表操作折行但不横向溢出；详情弹层独立滚动；关闭按钮与焦点始终可见。
- 键盘可到达筛选、查看、编辑、复制、删除、关闭与保存；Escape 关闭详情并回收焦点。

## 7. 功能范围

1. 角色来源（内置 / 自定义）在标题与行内双重可识别。
2. 内置只读 / 可复制；自定义可编辑 / 复制 / 删除；引用阻塞提示。
3. 角色摘要生成规则（显式 summary 优先；无 summary 时从职责生成两行摘要）。
4. 完整职责的独立滚动详情。
5. A 编排台语义 token 统一（浅 / 深成对：画布、表面、正文、次要正文、强调、状态、边框、焦点、遮罩）。
6. 对比度达标（正文 4.5:1 / 非文本 3:1）与状态的双通道表达（文字 + 图标 / 形状）。
7. 390×844 与常见桌面宽度的自适应；弹层安全边距与按钮折行。
8. 键盘可达性、可见焦点、Escape 关闭与焦点回收、真实 label。
9. 长职责与连续长串的溢出处理。

## 8. 不修改范围

- 角色存储、角色内容、角色引用关系、删除规则。
- 宿主角色 RPC（`vwf.roles` 系列）语义。
- 角色权限层。
- FEAT-84 / FEAT-85 的业务路由、运行状态、模型 override、模板数据。
- 视觉方向（不复活 B/C）。

## 9. 业务规则

- **来源以字段为准，不靠猜**：内置 / 自定义 badge 按 `builtin` 布尔语义映射；**不得通过角色名猜来源**。
- **摘要不写回原文**：真实角色没有 summary 时，客户端可从 content 生成显示摘要，但**不得写回或覆盖角色原文**。
- **内置只读不可绕过**：不提供删除；编辑入口不存在（复制为自定义后编辑）。
- **删除前显示影响**：显示引用数量与受影响模板；有引用时阻塞并说明原因。
- **对比度成对定义**：每个语义 token 必须同时给出浅色与深色值；**不得在单一主题里硬编码黑色 / 白色**。
- **状态不只用颜色**：状态信息同时使用文字与图标 / 形状。
- **窄屏不靠缩字**：不得以降低正文字号、隐藏文字或降低对比度解决拥挤。
- **角色语义不被视觉改造误改**：改样式不得改变内置 / 自定义的业务判定与引用行为。

## 10. 用户操作路径

1. 打开角色管理 → 看到「内置角色」与「自定义角色」两个分区及来源 badge。
2. 在内置区打开一个角色 → 无编辑按钮，只能查看或复制为自定义。
3. 在自定义区打开一个角色 → 确认名称、来源、两行简介与操作按钮互不挤压。
4. 打开一个「没有简介但职责很长」的角色 → 列表只显示两行截断摘要；点「查看详情」→ 完整职责在独立滚动区域展示。
5. 编辑 / 复制 / 删除一个自定义角色 → 删除前看到引用数量与受影响模板；有引用时被阻塞并说明原因。
6. 在编辑器与运行页对照同一 token 的呈现，确认浅 / 深两套语义一致。
7. 将视口切到 390×844 → 列表操作折行但不横向溢出；详情弹层独立滚动；关闭按钮可见。
8. 用 Tab / Shift+Tab 遍历筛选、查看、编辑、复制、删除、关闭、保存 → 焦点可见；按 Escape 关闭详情并回到触发元素。

## 11. 异常和边界场景

| 场景 | 期望行为 |
|---|---|
| 角色无 summary 但职责极长 | 列表显示两行截断摘要；全文在独立滚动区；**不写回**角色原文 |
| 职责含连续长串（无空格） | 断词或换行，不产生横向溢出 |
| 内置 / 自定义 badge 缺字段 | 按 `builtin` 布尔语义映射；**不通过角色名猜来源** |
| 某状态色在 DSH alias 中不存在 | 新增 token 时同时提供浅 / 深值与对比度证据；**不在单一主题硬编码黑 / 白** |
| 删除被引用角色 | 阻塞删除并显示引用数量与受影响模板 |
| 390×844 窄屏 | 按钮折行、弹层安全边距、详情内部滚动；主要操作不被工具条遮挡 |
| 深色主题某处对比度不足 | 修正 token 值而非换字号；记录测量方法与结果 |
| 详情打开后关闭 | Escape 关闭并**回收焦点**到触发元素 |
| 角色 RPC 读取失败 | 显示明确的失败状态，不把空列表当作「没有角色」 |

## 16. UAT 场景

### UAT-01 来源可辨识与权限边界

- 执行时机：裁决前可观测
- 验收目的：确认用户一眼能看出能不能改。
- 前置条件：
  1. 系统内至少有一个内置角色与一个自定义角色。
- 操作步骤：
  1. 打开角色管理，观察分区与来源 badge。
  2. 在内置角色上查找编辑与删除入口。
  3. 将内置角色复制为自定义，观察新角色归属。
  4. 在自定义角色上执行复制与删除。
- 预期结果：
  1. 内置与自定义在标题与行内均可辨识。
  2. 内置角色无编辑、无删除入口，可查看与复制。
  3. 复制产生的角色归入自定义区。
  4. 自定义角色可复制、可删除。
- 建议人工关注：来源是否由 `builtin` 字段判定，而非角色名。

### UAT-02 长职责与连续长串

- 执行时机：裁决前可观测
- 验收目的：确认长文本不破坏列表与布局。
- 前置条件：
  1. 准备一个无简介、职责约 4,500 字的自定义角色；另准备一个含无空格连续长串的角色。
- 操作步骤：
  1. 打开角色管理，观察列表行高与摘要行数。
  2. 点「查看详情」，检查完整职责是否在独立滚动区。
  3. 在窄屏与桌面宽度下分别观察是否出现横向滚动。
  4. 关闭详情，重新打开该角色，确认原文未被摘要覆盖。
- 预期结果：
  1. 列表摘要最多两行，行高不随全文增长。
  2. 完整职责在独立滚动区可读。
  3. 两种宽度下均无横向溢出。
  4. 角色原文未被写回或覆盖。
- 建议人工关注：摘要是显示层生成还是被持久化写回。

### UAT-03 主题 token 一致性与对比度

- 执行时机：裁决前可观测
- 验收目的：确认三页共用一套语义色且对比度达标。
- 前置条件：
  1. 对比度测量工具可用（记录工具名与版本）。
- 操作步骤：
  1. 分别以浅色与深色打开角色页、编辑器、运行页。
  2. 对正文字、次要正文、控件边界、图标与焦点指示逐项测量对比度。
  3. 检查状态提示是否同时有文字与图形。
- 预期结果：
  1. 三页使用同一套语义 token，同一语义在两主题下成对定义。
  2. 正文 ≥ 4.5:1；非文本控件与图标 ≥ 3:1；无深色背景配深色字。
  3. 状态同时有文字与形状 / 图标提示。
- 建议人工关注：测量方法、工具与采样点须随证据记录。

### UAT-04 窄屏与键盘
