## 1. 需求背景

LOC-023（工作区治理口径统一）已收敛 6 处「工作区与分支暂不删除」的错误口径，于 2026-09-15 人工验收为「有条件通过」。其优化意见②指出：交付链文本口径仍与已通过决策不一致，需继续收敛。

本次调查定位到残留一处，且性质不同——不是「该删不删」，而是**明示允许使用强删参数**：收口角色说明书 `dsh/roles/closeout.md:24` 写「残留本任务未提交/未跟踪文件时，先确认归属再用 `--force`」，与 LOC-023 规格 §9 R-4（禁止使用强删、四项前置才删、删不掉只登记遗留）直接互斥。这是同一次文档漂移的遗留尾巴。

## 2. 用户问题

照着收口说明书干活的执行体，在遇到删不掉的工作区时会选择强删手段；而该方法会连同内部未归档的过程产物一起删除，且绕过了「归档三件套已核对」这一前置。与此同时，账本上出现两套互相打架的说法——让执行者不知道该听谁的。

## 3. 目标

让收口说明书中「删不掉怎么办」这一条，与已通过决策完全一致：**拒绝删除、登记遗留、不阻塞合并、任何情况下不使用强删手段**。改完后，交付链上任何一处都不会再出现「允许/建议使用强删」的表述。

## 4. 非目标

- 不新增机器闸门（不在校验器里加「扫描允许强删表述」的检查项）——松哥裁定选项 A，本次只收敛文本本身；
- 不改 R-4 的判定语义与四项前置条件；
- 不改 `scripts/local-task-merge.mjs` 的删除行为（实现已正确）；
- 不追溯回改历史报告 `docs/reports/workspace-convergence-scan-2026-09-12.md`（历史记录，其中的操作实录属既往事实）；
- 不改动已分发到本机其他技能池的安装态副本（同步属另一事项）。

## 5. 修改前

收口角色说明书「阶段一」删除条款（`dsh/roles/closeout.md` 第 24 行）写着：

> 删除用 `git worktree remove <路径>`；残留本任务未提交/未跟踪文件时，先确认归属再用 `--force`；

相邻的第 25、26 行已写明「删除前确认归档三件套已入库」与「删除后必须追加 `git worktree prune`」，两条均正确，唯独第 24 行的兜底手段错误。

## 6. 修改后

同一条款改为：

> 删除用 `git worktree remove <路径>`，**不带 `--force`**；残留本任务未提交/未跟踪文件时**拒绝删除**——哪怕 git 提示「需加强删参数才能删」也不许升级手段，只把原因与 git 原话登记为遗留项，合并继续进行（口径出处：决策 0001 §6、约定 §1.7.1、LOC-023 规格 R-4）。

相邻的归档核对与 prune 兜底两句保持不变。

## 7. 功能范围

## 9. 业务规则

| 编号 | 规则 |
|---|---|
| R-1 | 删除命令一律 `git worktree remove <路径>`，**不带强删参数** |
| R-2 | 工作区存在未提交改动或未跟踪文件 → **拒绝删除**，登记为遗留项，合并主路径不阻塞 |
| R-3 | 遗留项必须保留 git 的原话（含「需要 `--force` 才能删」一类提示），同时标明「R-4 明确禁止使用」，让后续处理者一眼看出为何没删、以及本可选用但不允许的手段 |
| R-4 | 删除后必须追加 `git worktree prune`：删父工作区不会级联注销其内部嵌套的子登记（该缺口历史三次复现）——本条已在真源中且正确，保持不变 |
| R-5 | 口径一致性：改后的表述必须与 `runbook.md` §7 收口第 5 步、`local-track-offline-mode.md` §7.4、约定 §1.7.1（两阶段动作）与 §2.5 门控第 4 条原则句、`local-task-merge.mjs` 的实际行为语义一致，不得出现第二套说法 |

## 10. 用户操作路径

1. 执行体进入收口节点第 6 步「原子清理工作区」→ 阶段一；
2. 读取 §6 改写后的条款：按 `git worktree remove` 执行删除；
3. 若被 git 拒绝（提示有未跟踪/未提交文件）→ 不重试、不升级手段 → 把原因与 git 原话写入遗留事项；
4. 合并流程继续，不因删除失败而中断；
5. 删除成功后追加 prune 兜底注销嵌套残留登记。

## 11. 异常和边界场景

## 16. UAT 场景

### UAT-01 口径一致性核对

- 验收目的：确认收口说明书与已通过决策说的是同一件事，且不存在第二套说法
- 前置条件：
  1. 改动已提交到任务分支 `dev-chore-37-r1`
- 操作步骤：
  1. 打开 `dsh/roles/closeout.md`，阅读第 6 步阶段一删除条款
  2. 打开 `dsh/skills/construction-bootstrap/runbook.md` §7 收口第 5 步，比对两处关于「删不掉怎么办」的说法
  3. 打开 `docs/design/ai-task-define-delivery/local-track-offline-mode.md` §7.4，做第三次比对
- 预期结果：
  1. 三处均表达「拒绝删除 + 登记遗留 + 不阻塞 + 不使用强删」
  2. 不存在任何一处暗示或明示可以使用强删手段
- 建议人工关注：删一句「先确认归属」是否会丢失有用的操作提示——如认为该提示有价值，可在保持「禁止强删」前提下改写为「核实未跟踪文件归属后再决定是否处理」，但不得恢复任何强删许可

### UAT-02 检索核对与副本一致性

- 验收目的：确认全仓再无允许类表述，且生成副本已同步
- 前置条件：已执行 dist 重建

  1. 在仓库根目录检索 `--force` 关键字（排除依赖目录），逐条查看命中位置的上下文
  2. 比对 `dsh/roles/closeout.md` 与 `packages/dsh-visual-workflow/dist/roles/closeout.md`
- 预期结果：
  1. 允许类表述 0 条；剩余条目均为「禁止」「不使用」「界线说明」或历史归档报告
  2. 两份文件差异为空
