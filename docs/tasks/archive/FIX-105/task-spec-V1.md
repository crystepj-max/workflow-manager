# 完整经过链路按实际运转顺序排列并用图形+颜色区分结果状态

## 1. 缺陷描述

「查看完整经过」链路未按整个工作链路的**实际运转顺序**展示，也未用不同图形与颜色区分 通过 / 回退 / 阻塞 / 人工裁决 等结果状态——用户无法从链路读出「任务到底怎么走过来的」。

## 2. 修复要求

1. 链路按实际运转时序排列（含回退、业务返工、技术重试产生的轮次与分支），最近事件可识别。
2. 每个节点/段的状态以 **图标 + 颜色成对** 表达（不只靠颜色，符合既有无障碍口径）；语义色遵循 DESIGN.md 契约。
3. 状态集合至少覆盖：**通过、回退（业务返工与技术重试区分）、阻塞、人工裁决（等待中 / 已裁决）、进行中**；与详情页既有状态语义（STATUS_COLOR/STATUS_SHAPE 体系）一致。
4. 点选链路节点联动右侧当前结果的行为（FEAT-103 V-3）保持。
5. 数据来源为既有 run 状态（attempts / nodes / lifecycle / formal records），不改后端与 RPC。

## 3. 零回退约束

- FEAT-85 详情全部行为（三页签/决策卡/恢复卡/attempt 切换/DT-01 路径/返回保留位置）保持。
- FEAT-103 V-1~V-7（角色入口/简介/链路弹窗/整合）保持。
- 既有测试随调整同步修订；能力断言不删。

## 4. 验收条件

- [ ] V-1 链路顺序与真实执行时序一致（用一个含回退/返工的模板实测核对）。
- [ ] V-2 五类以上状态均有 图标+颜色 成对表达，浅深两主题下可辨识（对比度口径不回退）。
- [ ] V-3 点选联动行为保持；详情其余行为零回退。
- [ ] V-4 载荷预算不上调；token 集成口径断言保持。
