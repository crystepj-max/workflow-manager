# 设置页信息架构对齐原型（导航三分区 / 列表子页 / 运行详情大工作区 / 主题一致 / 内置记录操作）

## 1. 需求背景

FEAT-84/85/86 集成真机验收（对照 `packages/dsh-visual-workflow/prototypes/ui-workbench/` 原型第二轮，4178 在线版）发现：三个切片各自交付了能力，但设置页的**信息架构**仍停留在旧结构，与原型差距明显。本任务做呈现层对齐。

## 2. 用户问题（业务语言）

用户对照原型逐条核对，找不到原型里的结构：导航分区不一致、列表没有分层、运行记录点开后看不清、两个页面底色不一样、按钮名称和原型对不上。

## 3. 差距清单（原型 <> 现状，验收即按此逐条对照）

| # | 原型如何 | 现状如何 | 验收项 |
|---|---|---|---|
| 1 | 顶部导航 **流程库 / 运行 / 角色** 3 个 tab | 模板库 / 运行看板 2 个 tab；角色仍嵌在模板库的工作流模板编辑画布区域 | V-1 |
| 2 | 流程库列表下分 **全部 / 内置 / 我的** 3 个子 tab | 无子 tab | V-2 |
| 3 | 运行看板列表**按工作空间分组**，每组排序：需处理的任务 → 进行中 → 已完成 | 待处理人工门禁队列独立于运行看板列表 | V-3 |
| 4 | 运行看板记录点击后打开**更大尺寸的新页面**（与模板编辑工作区同级的工作区层） | 点击后仍在原页面内嵌展示，太窄看不清 | V-4 |
| 5 | 浅色主题下模板页与运行页背景一致 | 一灰一白 | V-5 |
| 6 | 内置工作流记录按钮：**查看流程、模型设置**，无删除按钮 | 查看并验收、模型覆盖、置灰的删除按钮 | V-6 |

## 4. 目标

- 导航、列表结构、承载表面、主题底色、操作命名与原型一致。
- FEAT-84/85/86 的能力语义零回退（见 §6）。

## 5. 非目标

- 不改 RPC、数据契约、校验器与工作流执行语义。
- 不新增原型未包含的页面能力。
- 不处理 DT-02（token 统一）——继续沿用集成期口径。

## 6. 能力零回退约束（与既有验收的关系）

- FEAT-84 V-1~V-13：编辑工作区的位置感/渐进披露/连接弹窗/撤销/内置只读+模型设置/对比度/窄屏等行为保持；本任务调整其入口与导航归属，不改其内部行为。
- FEAT-85：运行列表按工作空间分组、Logical Run 详情的全部行为（三页签、决策卡、恢复卡、attempt 切换、返回列表保留筛选与位置）保持；本任务把详情从内嵌改为大工作区层、把列表排序改为组内三段优先级。
- FEAT-86：角色库能力（来源识别、摘要收敛、详情滚动、逐层 Escape、焦点回收）保持；本任务把角色库从编辑器区域迁到独立「角色」tab，入口形态变化但能力不变。
- 涉及的既有呈现层测试（client.smoke.mjs / editor-workbench / role-theme 等）随呈现调整**同步修订**；能力级断言不得删除。

## 7. 验收条件

- [ ] V-1 顶部导航为 流程库 / 运行 / 角色 3 个 tab；角色库有独立入口，不再嵌于模板编辑画布区域。
- [ ] V-2 流程库列表提供 全部 / 内置 / 我的 3 个子 tab，默认「全部」，切换正确过滤且键盘可达。
- [ ] V-3 运行看板列表按工作空间分组；组内顺序：需处理（人工门禁）→ 进行中 → 已完成；原独立的人工门禁队列并入该列表（不丢失任何待处理项）。
- [ ] V-4 点击运行记录打开与模板编辑工作区同级的大工作区层展示 Logical Run 详情；关闭后回到列表并保留筛选与滚动位置。
- [ ] V-5 浅色主题下流程库页与运行页背景、表面色一致（同一 token 体系，无一处灰白混用）。
- [ ] V-6 内置工作流记录的操作为 查看流程、模型设置，不提供删除按钮（含置灰态）；自定义记录操作不回退。
- [ ] V-7 既有能力断言零回退：FEAT-84 V-1~V-13、FEAT-85 列表/详情用例、FEAT-86 角色用例（允许因信息架构调整修订 mount 路径与入口选择器）。

## 8. 风险

- 载荷预算余量仅约 7.2KB（272KiB 上限，当前 271327B）：新增结构优先复用既有样式与组件；超限先瘦身，禁止自行上调预算（预算调整走人工裁决）。
- 信息架构调整涉及多个既有测试的 mount 路径修订，改动面广：严格按「呈现调整同步修订测试，能力断言不删」执行。
