# 01 — 内置角色集合单一来源化，测试基线去硬编码

**What to build:** 让「系统内置了哪些角色」这件事只有一个地方说了算。当前测试里散落着「内置角色恰好 6 个」「前 6 个 id 是某某数组」这类写死的数字与清单，每新增或调整一个角色都要跟着改一遍。改完之后，测试断言从角色注册表本身派生，新增角色不再需要动测试。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent → **已完成（2026-08-30）**

## 完成情况

改造了 4 处硬编码断言，并新增 1 条结构护栏：

| 位置 | 原断言 | 改造后 |
|---|---|---|
| 无 fs 服务常驻 | `filter(builtin).length === 6` | 非空 + 全部 `builtin === true` |
| fs 读工作区增强摘要 | `deepEqual(ids.sort(), [6 个 id])` | 非 `.md` 文件不识别 + 含 `dev`/`closeout` |
| 无 `dsh/roles` 目录兜底 | `deepEqual(ids.sort(), [6 个 id])` | 非空 + 全部 `builtin` + 含 `closeout` |
| 内置置前 | `slice(0,6)` 精确等于 6 个 id | 最后一个内置的下标 < 第一个自定义的下标 |
| （新增） | — | 注册表结构不变量：id 唯一、id 为稳定英文、中文名非空 |

**设计取舍**：内置角色清单本身就是单一来源，测试不复制它。因此**没有**任何测试去断言「恰好 12 个」——清单即定义，加角色就是改定义。改为断言**结构不变量**（id 唯一 / 英文 / 中文名非空），这同时守住了 issue 验收第 1、10 条。

## 验收

- [x] 测试中不再出现硬编码的内置角色 id 列表或排序数组
