# 02 — dispatcher 从内置降为自定义角色，历史引用不失效

**What to build:** 让 `dispatcher`（调度）退出系统内置角色身份，改以使用者自定义角色的身份继续存在。使用者在角色库的「自定义」分组里能看到它，并且可以像其他自定义角色一样查看、编辑、克隆、删除；同时，**已经引用了它的历史工作流一个都不能坏**——打开旧流程、跑一次，节点仍能正常找到并使用这个角色。

**Why first:** 这是全部工作中风险最低、且能立刻验证「历史引用不丢失」这条验收标准的动作。已知它不需要搬动任何文件、也不需要改任何流程模板。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `dispatcher` 出现在角色库「自定义」分组，不再出现在「内置」分组
- [ ] 它获得了自定义角色应有的能力：可查看、可编辑、可基于此创建变体、可删除
- [ ] 内置角色的只读保护对它不再生效（此前尝试编辑/删除它应被拒绝，迁移后应被允许）
- [ ] 现有引用了它的工作流节点仍能正常解析角色并执行，跑一次真实验证
- [ ] 引用计数保护依然生效：在仍有流程引用它时尝试删除，应被拦下并提示引用数
- [ ] 角色定义文件保留在原处，未被移动或改名
