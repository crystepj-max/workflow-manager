# 03 — 五个存量角色升级为正式标准（dev / test / review / accept / closeout）

**What to build:** 把当前已在用的五个角色升级为正式版本。升级后：机器标识（英文 id）保持不变，中文正式名称与职责说明按统一标准对齐；**职责边界写进角色定义本身**——尤其是 `review`（审核）与 `evaluator`（评估）不能混为一谈：前者面向规范与需求符合性、质量问题审查，后者面向给定评价标准下的独立评估结论。升级后所有已引用这五个角色的流程行为连续，不出现回归。

**验收依据（#71 §10 四问）**：每个角色都需说明它与其余角色的能力边界，避免与基础角色重叠；可复用的多个场景需列明。
