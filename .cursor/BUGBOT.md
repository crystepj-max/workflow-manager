# Bugbot 评审规则（workflow-manager）

> 本文件只定义 **Cursor Bugbot 评审本次 PR diff 时的判定口径**。
> 治理侧——受控触发入口 `/codex-review`、轮次额度、同 HEAD 去重、人工 `extend`——
> 以仓库根 `AGENTS.md` 的「PR Review 收敛规则（Cursor Bugbot）」一节与
> `scripts/codex-review-controller.mjs` 为准，本文件不复述、也不新增第二套额度规则。
> 注：Bugbot 只读取 `.cursor/BUGBOT.md` 这类常驻规则文件，不会执行单次触发评论里的临时指令；
> 因此下面这些要求必须常驻于此才能真正生效。

## 评审范围

- 只针对**当前 PR 相对于其关联 Issue 验收条件**的改动评审。不得要求超出当前 Issue 范围的改造、重构或"顺手改进"。
- 判断"是否在本 PR 范围内"以关联 Issue / PR 描述写明的验收条件为准，而非"这条建议本身有没有道理"。

## 每条意见必须先分类，再表态

对每一条发现，显式标注其类别（与 `AGENTS.md` 同一套口径）：

- **A · 当前阻塞**：当前 Issue 验收条件未满足、本 PR 新引入的回归、或会导致本 PR 明显不正确 / 不安全的问题。只有 A 类构成"合并前必须修"。
- **B · 后续事项**：问题成立，但属历史遗留、额外增强、需扩大范围才能解决、或不影响当前 Issue 完成。标为 follow-up，不阻塞本 PR。
- **C · 不采纳**：偏好型建议、收益不足、与当前目标无关或判断不成立。说明理由后结束该条，不再重复提。

## 收敛纪律（重要）

- **不得把 B / C 类意见作为"本 PR 尚不能合并"的理由**；也不得因为"还能提出更多建议"就判定 PR 未完成。
- 当评审是在上一轮问题被修复后重新触发时：重点核对**上一轮 A 类是否已正确解决**、以及**本轮修改是否引入新的 A 类回归**；不要重开已被判为 B/C 的历史意见，也不要把新想法包装成阻塞。
- 本仓库已开启 **Incremental Review**（第 2/3 轮天然只覆盖上次评审之后的新改动），因此本节**不再重复要求"只看新改动"**；评审聚焦靠该仓库级配置，不靠本文件或触发评论里的临时指令，避免两套口径。
- 隐私/凭据泄露、注入等安全红线始终可按 A 类提出，但须指明具体位置与依据。

## 不要做的事

- 仓库侧 Trigger Mode 已设为 **Manual Only**（仅 `@cursor review` / `bugbot run` 触发），是否发起评审由 Controller 与轮次额度决定，不由本规则文件决定；不得回退到每次 push 自动评审。
- 不要修改代码、不要自动修复并推送（本仓库要求 Autofix 持续关闭）、不要直接合并、不要代为扩大当前 PR 的验收范围。
- PR 描述是本仓库的收口证据，由收口工具维护；Bugbot 不得生成或改写 PR 描述（建议仓库侧关闭 PR Summaries）。
